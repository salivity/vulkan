Configuring Color Formats in Vulkan Dynamic Rendering

This article explains how Vulkan's dynamic rendering feature simplifies pipeline creation by configuring attachment color formats directly, eliminating the need for traditional render pass and framebuffer objects. Introduced in Vulkan 1.3 via the VK_KHR_dynamic_rendering extension, this approach allows developers to declare color, depth, and stencil attachment formats at the pipeline creation stage using dedicated structures in the pipeline's extension chain. Below is a direct breakdown of how dynamic rendering configures attachment color formats dynamically during pipeline setup and matches them at draw time.

The Shift from Traditional Render Passes

In legacy Vulkan, creating a graphics pipeline strictly required a valid VkRenderPass handle. This render pass defined the format, sample count, load/store operations, and layout transitions for every attachment across multiple subpasses, tightly coupling the pipeline to a specific render pass compatibility class. Framebuffers (VkFramebuffer) were then bound at runtime to provide the actual image views matching that render pass.

Dynamic rendering removes the requirement for both VkRenderPass and VkFramebuffer. Instead, pipeline creation requires only the attachment formats that the pipeline expects to output to, deferring the attachment of actual image memory until command buffer recording.

Configuring Formats with VkPipelineRenderingCreateInfo

To configure attachment formats dynamically during pipeline setup, you set the renderPass member of VkGraphicsPipelineCreateInfo to VK_NULL_HANDLE and extend the structure using its pNext chain with VkPipelineRenderingCreateInfo.

The VkPipelineRenderingCreateInfo structure explicitly specifies the expected formats:

typedef struct VkPipelineRenderingCreateInfo {
    VkStructureType    sType;
    const void*        pNext;
    uint32_t           viewMask;
    uint32_t           colorAttachmentCount;
    const VkFormat*    pColorAttachmentFormats;
    VkFormat           depthAttachmentFormat;
    VkFormat           stencilAttachmentFormat;
} VkPipelineRenderingCreateInfo;

When defining the pipeline:

  1. Set the Type: Assign sType to VK_STRUCTURE_TYPE_PIPELINE_RENDERING_CREATE_INFO.
  2. Define Color Count: Set colorAttachmentCount to the number of color outputs targeted by your fragment shader.
  3. Supply Format Array: Point pColorAttachmentFormats to an array of VkFormat enums (e.g., VK_FORMAT_R8G8B8A8_SRGB, VK_FORMAT_B8G8R8A8_UNORM). Each index in the array maps directly to the corresponding fragment shader output location (layout(location = i)).
  4. Unused Attachments: If a specific output location is not used by an attachment, pass VK_FORMAT_UNDEFINED at that array index.
  5. Chain to Pipeline Info: Assign the address of your VkPipelineRenderingCreateInfo struct to the pNext pointer of VkGraphicsPipelineCreateInfo.

Runtime Execution with vkCmdBeginRendering

Because the pipeline only knows the format signatures defined in VkPipelineRenderingCreateInfo, the actual rendering targets are provided at runtime inside the command buffer using vkCmdBeginRendering.

This command consumes a VkRenderingInfo struct, which contains an array of VkRenderingAttachmentInfo structures defining the bound VkImageView, load/store operations, and clear values. The format of each VkImageView bound at vkCmdBeginRendering must match the corresponding format specified in pColorAttachmentFormats during pipeline creation. If the formats do not match, validation layers will report an error, and undefined rendering behavior will occur.
