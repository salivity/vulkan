Pipeline Derivatives and Code Sharing in Vulkan

Vulkan pipeline derivatives provide an explicit mechanism for creating new pipelines based on existing ones to minimize state duplication and compilation overhead. By designating a parent pipeline, the driver can reuse compiled shader code, intermediate representations, and internal hardware configurations for child pipelines with identical or closely related state. This article explains how pipeline derivatives function, how parent pipelines share compiled code, and how to implement this pattern in graphics and compute workloads.

What Are Pipeline Derivatives?

In Vulkan, compiling a pipeline (VkPipeline) is an expensive operation because it requires the driver to convert intermediate SPIR-V bytecode into optimized hardware-specific machine code, link pipeline stages, and prepare GPU-specific hardware state. When creating several pipelines that share significant portions of their execution graph—such as identical vertex processing but differing fragment stages or blend operations—creating each pipeline from scratch introduces redundant work.

Pipeline derivatives address this by establishing an explicit parent-child relationship. A child (derivative) pipeline specifies a parent pipeline, giving the driver a hint that it can branch off the parent’s already processed state rather than recompiling identical components from scratch.

How Parent Pipelines Share Compiled Code

When creating a child pipeline, the driver can bypass several stages of the compilation pipeline:

  • Shader Stage Reuse: If a parent and child share shader stages (such as an identical vertex shader, tessellation stage, or geometry shader), the driver can reuse the exact compiled machine instructions and register allocation maps rather than recompiling the SPIR-V code.
  • Shared State Validation: State blocks that remain constant between parent and child—such as input assembly layouts, rasterization settings, or depth-stencil configurations—can be shallow-copied or referenced internally rather than recomputed and validated.
  • Internal Dependency Linking: The driver can skip global link-time optimizations across the shared stages, executing only the delta optimizations required for the modified stages.

The degree of reuse depends on the underlying driver implementation. While the driver is not strictly required to share code, providing derivative hints allows compliant drivers to significantly shorten compile times and reduce the memory footprint of pipeline state objects (PSOs).

Configuring Pipeline Derivatives in Vulkan

Derivatives can be configured for both graphics pipelines (VkGraphicsPipelineCreateInfo) and compute pipelines (VkComputePipelineCreateInfo). The setup involves two main components: flags and base references.

1. Flagging the Parent and Child

To enable derivation, specific flags must be set in the flags field of the pipeline creation info structures:

  • Parent Pipeline: Must include the VK_PIPELINE_CREATE_ALLOW_DERIVATIVES_BIT flag. This informs the driver to retain intermediate compilation artifacts and data structures necessary to spawn children.
  • Child Pipeline: Must include the VK_PIPELINE_CREATE_DERIVATIVE_BIT flag, signaling that it intends to inherit state from a base pipeline.

2. Referencing the Parent

A derivative references its parent using one of two fields in the create-info structure:

  • basePipelineHandle: A handle to an already created VkPipeline that was constructed with the VK_PIPELINE_CREATE_ALLOW_DERIVATIVES_BIT flag.
  • basePipelineIndex: A zero-based index pointing to another pipeline structure within the same array passed to vkCreateGraphicsPipelines or vkCreateComputePipelines. This is used when batch-creating parent and child pipelines simultaneously. In this case, basePipelineHandle must be set to VK_NULL_HANDLE, and the parent entry in the array must appear earlier than the child or carry the allow-derivatives flag.
// Example: Creating a derivative pipeline using basePipelineHandle
VkGraphicsPipelineCreateInfo childPipelineInfo{};
childPipelineInfo.sType = VK_STRUCTURE_TYPE_GRAPHICS_PIPELINE_CREATE_INFO;
childPipelineInfo.flags = VK_PIPELINE_CREATE_DERIVATIVE_BIT;
childPipelineInfo.basePipelineHandle = parentPipelineHandle;
childPipelineInfo.basePipelineIndex = -1; // Ignored when handle is valid
// Configure remaining stages (e.g., modified fragment shader or blend state)

Common Use Cases

  • Material and Shader Variations: Using the same vertex transform logic across hundreds of materials while varying only the fragment shader or alpha-testing parameters.
  • Render Pass Variations: Using the same shader logic across different render target formats or blending configurations (e.g., additive vs. alpha-blended rendering).
  • Batch Compilation: Compiling an entire pipeline family within a single vkCreateGraphicsPipelines call using basePipelineIndex, enabling the driver to multithread compilation while sharing base artifacts in-memory.

Derivatives vs. Pipeline Caches

While pipeline derivatives provide explicit parent-child hints at pipeline creation time, they are complementary to VkPipelineCache. A pipeline cache persists compiled binary data across runs and avoids recompilation on subsequent application launches. Pipeline derivatives explicitly declare structural relationships at runtime, assisting drivers in optimizing memory usage, compilation latency, and state transitions between related pipelines during execution.
