How to Handle Window Resizing in Vulkan

Handling window resizing in Vulkan requires detecting the resize event, properly synchronizing running GPU operations, and rebuilding the swapchain alongside its dependent resources. When a window changes dimensions, the existing swapchain becomes invalid or suboptimal, requiring the engine to safely clean up old handles, query updated surface dimensions, and allocate new framebuffers. This guide walks through the exact step-by-step process needed to manage window resize events smoothly without stalling, freezing, or crashing your application.

1. Detect the Resize Event

Window resizing can be detected in two primary ways: through your windowing library (such as GLFW or SDL) via a framebuffer size callback, or directly through Vulkan's presentation queue return codes.

During presentation or swapchain acquisition, functions like vkAcquireNextImageKHR or vkQueuePresentKHR will return VK_ERROR_OUT_OF_DATE_KHR or VK_SUBOPTIMAL_KHR when the surface is no longer compatible with the swapchain. When using a windowing callback, set a boolean flag (e.g., framebufferResized = true) and trigger the recreation process on the next frame.

2. Handle Window Minimization

When a window is minimized, its width and height typically drop to zero. Attempting to create a swapchain with zero width or zero height will cause Vulkan to return an error. Check the surface extent before proceeding:

int width = 0, height = 0;
glfwGetFramebufferSize(window, &width, &height);
while (width == 0 || height == 0) {
    glfwGetFramebufferSize(window, &width, &height);
    glfwWaitEvents();
}

Pause rendering and wait until the window dimensions are positive before continuing with swapchain recreation.

3. Wait for the Device to Idle

Before destroying any swapchain components or framebuffers, ensure that the GPU is not currently reading from or writing to them. Call vkDeviceWaitIdle to flush the command queues and wait for all in-flight rendering operations to complete:

vkDeviceWaitIdle(device);

While finer-grained synchronization with fences is possible, vkDeviceWaitIdle is the safest and most common approach during a resize event.

4. Clean Up Dependent Resources

Destroy all objects that directly depend on the swapchain images and their dimensions. This includes:

  • Framebuffers (vkDestroyFramebuffer)
  • Image views associated with swapchain images (vkDestroyImageView)
  • Depth and stencil buffers, along with their image views, if their resolution matches the swapchain extent

Do not destroy the render pass unless its format changes, and do not destroy the old swapchain itself yet if you plan to use it for retirement during recreation.

5. Recreate the Swapchain

Query the physical device surface capabilities using vkGetPhysicalDeviceSurfaceCapabilitiesKHR to determine the new surface dimensions and supported transform flags.

Set up the VkSwapchainCreateInfoKHR structure with the updated extent. Assign the existing swapchain handle to the oldSwapchain field. Passing the old swapchain allows the driver to recycle resources and maintain a seamless transition. Once vkCreateSwapchainKHR succeeds, destroy the previous swapchain using vkDestroySwapchainKHR.

6. Recreate Image Views and Framebuffers

After creating the new swapchain:

  1. Retrieve the new swapchain image handles using vkGetSwapchainImagesKHR.
  2. Create corresponding VkImageView objects for each new image.
  3. Reallocate and recreate any resolution-dependent buffers (like depth/stencil attachments).
  4. Recreate the VkFramebuffer instances, linking them to your existing render pass and the new image views.

7. Update Dynamic State and Command Buffers

If your graphics pipeline uses dynamic states (VK_DYNAMIC_STATE_VIEWPORT and VK_DYNAMIC_STATE_SCISSOR), you do not need to recreate the pipeline. Simply update the viewport and scissor values in your command buffer during frame recording:

VkViewport viewport{};
viewport.width = (float)newWidth;
viewport.height = (float)newHeight;
viewport.minDepth = 0.0f;
viewport.maxDepth = 1.0f;
vkCmdSetViewport(commandBuffer, 0, 1, &viewport);

VkRect2D scissor{};
scissor.extent = newExtent;
vkCmdSetScissor(commandBuffer, 0, 1, &scissor);

If you do not use dynamic states, you must recreate the entire graphics pipeline with the new fixed dimensions. Finally, reset your resize flag to resume standard frame rendering.
