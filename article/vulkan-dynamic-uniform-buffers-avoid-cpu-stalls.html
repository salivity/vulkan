Vulkan Dynamic Uniform Buffers: Avoid CPU Stalls

Updating dynamic uniform buffers in Vulkan requires careful synchronization to prevent CPU write stalls, which occur when the host attempts to overwrite memory currently being read by the GPU. To maintain high throughput and low frame latency, developers must decouple CPU writes from GPU reads. This article covers practical techniques to eliminate CPU-GPU serialization, including multi-buffering with dynamic offsets, persistent memory mapping, push constants, and hardware-aligned ring allocations.

The Cause of CPU Write Stalls

When updating a uniform buffer directly via memory mapping, writing to a region the GPU is actively reading causes a data hazard. If you synchronize this access using blocking primitives like vkWaitForFences, the CPU sits idle, waiting for the graphics pipeline to drain. This pipeline bubble degrades frame rates and eliminates the benefits of asynchronous command submission.

Multi-Buffering Across Frames in Flight

The primary defense against CPU write stalls is allocating distinct memory regions for each concurrent frame in flight (typically double or triple buffering). By multiplying the dynamic uniform buffer size by MAX_FRAMES_IN_FLIGHT:

  • The CPU writes exclusively to the memory partition designated for the current frame index.
  • The GPU reads exclusively from partitions bound to previously submitted frames.
  • Fences submitted with vkQueueSubmit protect each frame's partition, ensuring the CPU only overwrites a block once the GPU has completed that specific frame's workload.

Ring Buffering with Dynamic Offsets

Rather than rebinding descriptor sets for each draw call or frame, allocate a single, large VkBuffer with VK_BUFFER_USAGE_UNIFORM_BUFFER_BIT and host-visible memory. Update data dynamically using a ring buffer (bump allocator) approach:

  1. Suballocate blocks linearly for each draw call during the frame.
  2. Advance an offset pointer as uniform data is copied.
  3. Pass the offset to vkCmdBindDescriptorSets using the pDynamicOffsets parameter.
  4. Reset the offset to the beginning of the frame's reserved partition at the start of the next cycle.

Ensure every dynamic offset strictly adheres to the hardware's minUniformBufferOffsetAlignment limit, queried from VkPhysicalDeviceLimits. Writing unaligned offsets causes validation errors and undefined behavior on most GPUs.

Persistent Mapping

Avoid repeatedly calling vkMapMemory and vkUnmapMemory every frame. Mapping memory introduces kernel and driver overhead that can stall the CPU. Instead, map the buffer memory immediately after allocation and store the returned pointer for the lifetime of the buffer. The CPU can then copy data directly to this persistent pointer using memcpy without runtime mapping penalties.

Choosing the Right Memory Properties

Select memory with VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT and, where possible, VK_MEMORY_PROPERTY_HOST_COHERENT_BIT.

  • Host-Coherent Memory: Eliminates the need to call vkFlushMappedMemoryRanges, ensuring writes are automatically made available to the device once committed to cache.
  • Non-Coherent Memory: Requires explicit calls to vkFlushMappedMemoryRanges to push CPU cache lines to GPU-visible memory. While requiring manual flushes, non-coherent memory can yield faster sequential CPU write speeds on certain architectures.

Using Push Constants for Micro-Updates

For small, rapidly changing uniforms (such as individual object transformation matrices under 128 bytes), dynamic uniform buffers can introduce unnecessary management overhead. Push constants reside directly within the Vulkan command stream, completely bypassing the memory allocation, mapping, and synchronization overhead of uniform buffers.
