Multisample Coverage Mask Generation in Vulkan

In Vulkan, multisample mask generation determines which sub-pixel sample points of a pixel are covered by a geometric primitive during rasterization. This article explores how Vulkan resolves coverage masks in complex anti-aliasing schemes, tracking the pipeline stages from fixed-function geometric testing and custom sub-pixel sample positions to programmable shader mask inputs, alpha-to-coverage conversion, and explicit sample mask modification in SPIR-V shaders.

1. Geometric Primitive Rasterization

During the rasterization stage, the GPU tests the primitive's boundaries against multiple discrete sample locations inside each pixel footprint. The number of locations corresponds to the rasterizationSamples defined in VkPipelineMultisampleStateCreateInfo.

For each sample point that falls inside the primitive boundaries:

  • A corresponding bit in a temporary coverage mask is set to 1.
  • Samples falling outside are set to 0.

In standard MSAA, this produces an initial bitmask representing geometric coverage (e.g., an 8-bit integer mask for VK_SAMPLE_COUNT_8_BIT).

2. Custom and Rotated Sample Locations

Complex anti-aliasing schemes often avoid standard uniform sub-pixel grids to minimize regular edge aliasing patterns. Vulkan exposes this via the VK_EXT_sample_locations extension.

  • Applications define custom floating-point coordinate offsets within the pixel for each sample index using VkSampleLocationsInfoEXT.
  • The rasterizer evaluates primitive containment against these rotated or jittered positions instead of standard hardware defaults.
  • This changes the geometric evaluation step directly, shifting which bits in the initial coverage mask turn on without requiring manual fragment-level math.

3. Pipeline State Masking (pSampleMask)

After geometric testing, Vulkan applies the static or dynamic pipeline sample mask (pSampleMask inside VkPipelineMultisampleStateCreateInfo or set dynamically via vkCmdSetSampleMaskEXT).

  • The pipeline performs a bitwise AND between the rasterization coverage mask and the bitmask array in pSampleMask.
  • Any sample disabled by the pipeline mask is immediately dropped from coverage, skipping fragment shading if all bits in the mask become zero.

4. Alpha-to-Coverage Processing

When alphaToCoverageEnable is enabled in VkPipelineMultisampleStateCreateInfo, the alpha component of the fragment shader's primary color output is converted into an additional coverage mask.

  • Vulkan converts the normalized floating-point alpha value into a bit pattern where the number of set bits is proportional to the alpha magnitude (e.g., an alpha of 0.5 enables approximately 50% of the sample bits).

  • The hardware uses a dither pattern across neighboring pixels to distribute enabled bits across the sample grid.

  • The resulting alpha-derived mask is combined with the existing coverage mask using a bitwise AND operation:

    \[\text{Coverage} = \text{Coverage} \ \& \ \text{AlphaMask}\]

5. Programmable Mask Control in SPIR-V

In advanced anti-aliasing configurations—such as custom resolve algorithms, order-independent transparency, or conservative rasterization adjustments—shaders directly read and write coverage masks.

  • Reading the Input Mask: Shaders consume the built-in variable gl_SampleMaskIn (decorated as SampleMask in SPIR-V). This input reflects the combined result of geometric testing, custom sample locations, and pSampleMask.
  • Writing the Output Mask: Shaders output an array of 32-bit integers to gl_SampleMask (also decorated as SampleMask). This explicitly overrides coverage.

If a fragment shader writes to SampleMask, Vulkan combines this value with the previous mask stages via a bitwise AND:

\[\text{FinalCoverage} = \text{GeometricCoverage} \ \& \ \text{pSampleMask} \ \& \ \text{ShaderOutputMask} \ \& \ \text{AlphaCoverage}\]

Writing 0 to a specific bit in gl_SampleMask guarantees that the corresponding sample location will not be updated in the framebuffer attachments.

6. Sample Shading and Mask Interaction

When sample shading is enabled (sampleShadingEnable = VK_TRUE and minSampleShading > 0.0), fragment shaders execute per-sample or at a sub-pixel frequency rather than once per pixel:

  • Evaluation: The fragment shader executes multiple times per pixel footprint.
  • Coverage Scoping: For each shader invocation, the SampleMaskIn input contains only the bits corresponding to the subset of samples assigned to that specific invocation.
  • Depth/Stencil Testing: The final calculated coverage mask acts as a gate. Depth and stencil tests are evaluated exclusively for samples where the final coverage bit remains 1.
