Vulkan Fragment Shading Rate via Screen-Space Surfaces

Fragment Shading Rate (FSR) is an optimization technique that decouples the fragment shader execution rate from pixel density, allowing graphics applications to dynamically lower shading work where visual fidelity will not be compromised. In the Vulkan API, controlling this rate through screen-space surfaces enables developers to define a low-resolution image that dictates the shading granularity for specific pixel regions across the screen. This article explains the fundamentals of fragment shading rate in Vulkan, how screen-space shading attachments function, and the technical steps required to implement and combine shading rates effectively.

Understanding Fragment Shading Rate

Traditionally, GPUs execute fragment shaders once per pixel (or multiple times per pixel when using supersampling). While this maintains high sharpness, it can result in wasted compute power in areas with flat colors, fast motion blur, depth of field, or peripheral vision in Virtual Reality (VR).

Fragment Shading Rate—often referred to broadly as Variable Rate Shading (VRS)—allows a single fragment shader execution to compute the color for multiple pixels at once, such as 2x1, 1x2, 2x2, or 4x4 pixel regions. The calculated color value is then broadcast across all the covered pixels in that block, cutting GPU compute overhead significantly with minimal perceptual loss in image quality.

Controlling Shading Rate in Vulkan

Vulkan exposes this hardware capability through the VK_KHR_fragment_shading_rate extension. The specification provides three distinct ways to set shading rates:

  1. Pipeline state: Setting a static or dynamic rate for entire draw calls using vkCmdSetFragmentShadingRateKHR.
  2. Primitive rate: Writing a per-primitive shading rate directly from the vertex, geometry, or mesh shaders using built-in variables.
  3. Screen-space attachment (Shading Rate Image): Binding a 2D image surface where each texel maps to a region of the render target and specifies the local shading rate.

Screen-space surfaces are the most powerful method for content-adaptive techniques, such as foveated rendering or edge-aware adaptive shading, because they dictate shading frequency spatially across the frame regardless of geometry complexity.

Working with Screen-Space Shading Surfaces

1. Hardware Limits and Texel Sizing

Before allocating a screen-space surface, query the hardware limits using VkPhysicalDeviceFragmentShadingRatePropertiesKHR. The GPU executes shading rates over fixed tile sizes, defined by minFragmentShadingRateAttachmentTexelSize and maxFragmentShadingRateAttachmentTexelSize (typically 8x8 or 16x16 pixels).

The dimensions of your screen-space rate image must correspond to the render target resolution divided by this texel size:

\[\text{Attachment Width} = \left\lceil \frac{\text{Render Target Width}}{\text{Texel Size Width}} \right\rceil\]

2. Creating the Attachment Image

The surface is backed by a VkImage created with the VK_IMAGE_USAGE_FRAGMENT_SHADING_RATE_ATTACHMENT_BIT_KHR usage flag.

The image typically uses an 8-bit unsigned integer format such as VK_FORMAT_R8_UINT. In this format, each texel stores an encoded value representing the desired rate:

  • High 2 bits: Horizontal rate (e.g., 1, 2, or 4).
  • Low 2 bits: Vertical rate (e.g., 1, 2, or 4).

3. Binding to the Render Pipeline

Depending on whether the application uses traditional render passes or dynamic rendering, the surface is attached as follows:

  • Dynamic Rendering (VK_KHR_dynamic_rendering): Include a VkRenderingFragmentShadingRateAttachmentInfoKHR structure in the pNext chain of VkRenderingInfo. This structure holds the imageView, the image layout (VK_IMAGE_LAYOUT_FRAGMENT_SHADING_RATE_ATTACHMENT_OPTIMAL_KHR), and the tile size.
  • Traditional Render Passes: Include a VkFragmentShadingRateAttachmentInfoKHR struct in the subpass description's pNext chain, referencing an attachment reference configured for the shading rate surface.

4. Combiner Operations

Because shading rates can come simultaneously from the pipeline, the primitive, and the screen-space surface, Vulkan uses combiner operations (VkFragmentShadingRateCombinerOpKHR) to resolve the final rate. When issuing draw commands via vkCmdSetFragmentShadingRateKHR, you configure two combiners:

  • Combiner 0: Combines the pipeline rate with the primitive rate.
  • Combiner 1: Combines the result of Combiner 0 with the screen-space surface rate.

Available operations include:

  • VK_FRAGMENT_SHADING_RATE_COMBINER_OP_KEEP_KHR: Ignores the second rate and keeps the first.
  • VK_FRAGMENT_SHADING_RATE_COMBINER_OP_REPLACE_KHR: Overwrites the first rate with the second.
  • VK_FRAGMENT_SHADING_RATE_COMBINER_OP_MIN_KHR: Selects the finer (higher quality, smaller pixel footprint) shading rate.
  • VK_FRAGMENT_SHADING_RATE_COMBINER_OP_MAX_KHR: Selects the coarser (lower quality, larger pixel footprint) shading rate.

Setting Combiner 1 to REPLACE or MAX allows the screen-space surface to reliably drive reduced shading density over specific zones of the screen, ensuring that background areas or outer peripheral regions are shaded at lower costs while focal points retain native resolution quality.
