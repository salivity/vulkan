What Is Depth Clamping in Vulkan?

This article provides an overview of depth clamping in the Vulkan graphics API, contrasting it with standard frustum clipping, detailing its underlying pipeline mechanics, and explaining how it prevents geometry beyond the near and far planes from being discarded.

Standard Depth Clipping vs. Depth Clamping

In standard Vulkan rasterization, geometry is transformed into clip space. Any primitive or portion of a primitive that falls outside the canonical view volume—specifically where \(Z < 0\) (near plane) or \(Z > 1\) (far plane) in Vulkan's depth convention—is discarded during primitive clipping. This prevents fragments outside the viewing frustum from reaching the fragment shader or depth buffer.

Depth clamping modifies this behavior. Instead of clipping the geometry against the near and far planes, Vulkan allows primitives to pass through rasterization intact. The resulting fragments generated beyond these planes have their depth values clamped to the viewport’s defined range, typically \([0.0, 1.0]\). The \(X\) and \(Y\) clipping planes remain fully active, meaning geometry extending past the screen edges is still clipped normally.

How Depth Clamping Works in the Vulkan Pipeline

When depth clamping is active, the graphics pipeline alters the fixed-function clipping and rasterization stages:

  1. Clip Stage Bypass: The hardware suppresses the polygon clipping operations normally triggered by the near and far \(Z\) planes. Polygons overlapping these boundaries are not subdivided or discarded.
  2. Fragment Generation: Rasterization processes the full primitive, interpolating vertex attributes including depth across the entire surface.
  3. Fragment Depth Clamping: Prior to the depth test and depth write stages, the fragment’s calculated depth value (\(z_f\)) is clamped to the viewport boundaries: \[\text{clamped\_depth} = \min(\max(z_f, \text{minDepth}), \text{maxDepth})\] Here, minDepth and maxDepth are specified in the VkViewport structure.

Because the depth test operates on this clamped value, the fragment is treated as if it sits directly on the near or far boundary.

Enabling Depth Clamping in Vulkan

To use depth clamping in a Vulkan application, two configuration steps are required:

1. Device Feature Enablement

Depth clamping is an optional hardware feature. When creating the logical device (vkCreateDevice), the depthClamp boolean in VkPhysicalDeviceFeatures must be set to VK_TRUE. You can verify support beforehand using vkGetPhysicalDeviceFeatures.

2. Pipeline Configuration

In the graphics pipeline creation, depth clamping is controlled within the VkPipelineRasterizationStateCreateInfo structure:

VkPipelineRasterizationStateCreateInfo rasterizer{};
rasterizer.sType = VK_STRUCTURE_TYPE_PIPELINE_RASTERIZATION_STATE_CREATE_INFO;
rasterizer.depthClampEnable = VK_TRUE;
// Other rasterization parameters...

Setting depthClampEnable to VK_TRUE activates clamping for both the near and far planes simultaneously.

Common Use Cases

Shadow Map Generation

The most common application of depth clamping is directional shadow mapping (e.g., Cascaded Shadow Maps). If an object between the light source and the camera extends behind the light's near plane, standard clipping removes the geometry, causing missing shadows (light bleeding). Enabling depth clamping forces those occluders to render directly at the near plane (\(Z = 0\)), preserving correct shadow projection.

Preventing Near-Plane Visual Artifacts

Depth clamping can be used to prevent camera-space clipping artifacts, such as rendering cockpit interiors, first-person character weapons, or volumetric light shafts where near-plane cuts would reveal unnatural cross-sections of 3D meshes.
