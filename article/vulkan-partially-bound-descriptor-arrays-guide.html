Vulkan Partially Bound Descriptor Arrays Guide

In Vulkan, managing large descriptor arrays efficiently often requires leaving unused indices empty without causing validation errors or device crashes. This article explains how to configure partially bound descriptor arrays using the descriptor indexing features introduced in Vulkan 1.2 (and the VK_EXT_descriptor_indexing extension). It highlights the specific descriptor binding flag required—VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT—alongside the physical device feature requirements and implementation details necessary to safely use unbound descriptors in your shaders.

The Required Descriptor Binding Flag

To allow a descriptor array to contain unbound (null or uninitialized) elements, you must use the following flag when creating the descriptor set layout:

  • VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT

By default, the Vulkan specification dictates that every descriptor in a set accessed by a pipeline must be valid and bound to a resource before draw or dispatch commands are recorded. Setting VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT relaxes this restriction, allowing elements in an array to be left unbound as long as the shader dynamically does not access them during execution.

Enabling the Required Device Feature

Before utilizing this flag, you must confirm support and enable the corresponding feature on the physical device. During device creation (vkCreateDevice), query and set the feature flag in the VkPhysicalDeviceDescriptorIndexingFeatures structure (promoted to core in Vulkan 1.2):

  • descriptorBindingPartiallyBound: Must be set to VK_TRUE.

If using Vulkan 1.2 or later, this feature can also be passed via the VkPhysicalDeviceVulkan12Features struct chained to VkDeviceCreateInfo::pNext.

Configuring the Descriptor Set Layout

To apply the flag to a descriptor array, include a VkDescriptorSetLayoutBindingFlagsCreateInfo structure in the pNext chain of VkDescriptorSetLayoutCreateInfo:

  1. Define an array of VkDescriptorBindingFlags, with one entry per binding in your layout.
  2. Assign VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT to the specific binding index corresponding to your descriptor array.
  3. Attach VkDescriptorSetLayoutBindingFlagsCreateInfo to VkDescriptorSetLayoutCreateInfo::pNext.

For example, if binding 0 is a large texture array:

VkDescriptorBindingFlags bindingFlags[] = {
    VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT
};

VkDescriptorSetLayoutBindingFlagsCreateInfo bindingFlagsInfo = {};
bindingFlagsInfo.sType = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_BINDING_FLAGS_CREATE_INFO;
bindingFlagsInfo.bindingCount = 1;
bindingFlagsInfo.pBindingFlags = bindingFlags;

VkDescriptorSetLayoutCreateInfo layoutInfo = {};
layoutInfo.sType = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_CREATE_INFO;
layoutInfo.pNext = &bindingFlagsInfo;
// Configure remaining layoutInfo fields...

Shader and Execution Constraints

While VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT permits unbound descriptors within an array, it does not allow a shader to execute memory operations on them:

  • Dynamic Non-Access: Any shader invocation that dynamically executes an instruction referencing an unbound descriptor results in undefined behavior (often causing GPU hangs or page faults).
  • Control Flow: You must ensure through shader control flow (such as conditionals, branch structures, or non-uniform dynamic indexing) that unbound descriptor slots are never sampled or read.
  • Complementary Flags: This flag is frequently paired with VK_DESCRIPTOR_BINDING_UPDATE_AFTER_BIND_BIT, which allows updating bound descriptor indices after the set has already been bound to a command buffer.
