Vulkan Dynamic Stencil Reference for Outline Rendering

In Vulkan, dynamic state allows specific pipeline configurations to be altered at command-recording time without rebuilding the pipeline object. In multi-pass outline rendering, the dynamic stencil reference state—enabled via VK_DYNAMIC_STATE_STENCIL_REFERENCE—allows developers to update the stencil test's comparison and write reference values on the fly using vkCmdSetStencilReference. This article explains how this mechanism operates across multiple passes to isolate silhouettes and draw distinct outlines efficiently.

The Role of Dynamic Stencil Reference State

By default, graphics pipeline states in Vulkan are immutable once baked into a VkPipeline object. Stencil parameters like comparison operations, write masks, and reference values typically reside within the VkPipelineDepthStencilStateCreateInfo struct.

When VK_DYNAMIC_STATE_STENCIL_REFERENCE is added to VkPipelineDynamicStateCreateInfo, the driver ignores the static reference values set during pipeline creation. Instead, the reference value becomes a command buffer state set directly via:

void vkCmdSetStencilReference(
    VkCommandBuffer                             commandBuffer,
    VkStencilFaceFlags                          faceMask,
    uint32_t                                    reference);

This dynamic control enables switching the active reference value between draw calls or passes without binding new pipeline objects, significantly reducing pipeline permutations and state transitions.

Multi-Pass Outline Workflow

Outline rendering typically relies on a two-pass technique using the stencil buffer to mask the interior geometry:

  1. Pass 1: Object Masking
    • The base geometry is rendered using standard depth testing and writing.
    • Stencil testing is enabled. The comparison operation is set to VK_COMPARE_OP_ALWAYS, and the pass operation is set to VK_STENCIL_OP_REPLACE.
    • A reference value (e.g., 0x01 or a unique object ID) is recorded using vkCmdSetStencilReference(commandBuffer, VK_STENCIL_FACE_FRONT_AND_BACK, 0x01).
    • As fragments pass the depth test, the stencil buffer is populated with this reference value.
  2. Pass 2: Outline Generation
    • An expanded version of the mesh is rendered (often extruded along vertex normals in the vertex shader), or an inverted-hull pass is executed.
    • The stencil test condition changes to VK_COMPARE_OP_NOT_EQUAL.
    • The reference value is supplied using vkCmdSetStencilReference(commandBuffer, VK_STENCIL_FACE_FRONT_AND_BACK, 0x01).
    • The stencil test evaluates the incoming fragment: if the stencil buffer already contains 0x01 from the first pass, the fragment is discarded. Fragments that extend beyond the silhouette succeed the test, rendering only the expanded border or outline.

Command Buffer Execution and Synchronization

During command recording, vkCmdSetStencilReference acts as a state update that applies to all subsequent draw calls until modified again.

  • Face Mask Control: The faceMask parameter can target VK_STENCIL_FACE_FRONT_BIT, VK_STENCIL_FACE_BACK_BIT, or VK_STENCIL_FACE_FRONT_AND_BACK. This allows two-sided stencil setups where front and back faces evaluate or write different dynamic references.
  • Per-Object Outlines: In scenes requiring individual outlines (such as color-coded object selection), each entity can be assigned a distinct dynamic reference ID via vkCmdSetStencilReference during the draw loop, without requiring distinct pipelines for each unique reference ID.
  • Mask Interaction: The dynamic reference value is bitwise AND-ed with the pipeline’s compareMask during the test and with the writeMask during the update. While the reference value is dynamic, ensure that the static compareMask and writeMask configured in the pipeline permit the bits used by the dynamic reference.
