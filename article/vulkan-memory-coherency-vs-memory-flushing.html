Vulkan Memory Coherency vs Memory Flushing

In the Vulkan graphics and compute API, transferring data from the CPU to GPU-accessible mapped buffers requires careful synchronization between host caches and device memory. This article explains the difference between utilizing hardware memory coherency (VK_MEMORY_PROPERTY_HOST_COHERENT_BIT) and manually managing cache lines via memory flushing (vkFlushMappedMemoryRanges). Understanding how these two approaches handle cache visibility, hardware overhead, and synchronization allows developers to write optimal buffer-update paths for both integrated and discrete architectures.

The CPU Cache Challenge in Mapped Memory

When memory is allocated with VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT and mapped to a CPU pointer via vkMapMemory, writing to that pointer modifies the host CPU's local cache hierarchy (L1/L2/L3) first, not necessarily the actual system RAM or dedicated VRAM. The GPU cannot reliably read these modifications until the updated cache lines are made visible to the device.

Vulkan provides two distinct mechanisms to bridge this gap between CPU caches and GPU visibility: host-coherent memory and manual memory flushing.

Host-Coherent Memory

Host-coherent memory is enabled by allocating device memory with the VK_MEMORY_PROPERTY_HOST_COHERENT_BIT flag in addition to the host-visible flag.

When writing to a host-coherent mapped buffer:

  • Automatic Visibility: Writes to the mapped memory are automatically made visible to the GPU without explicit API calls from the host.
  • Hardware/Driver Handling: Depending on the underlying hardware architecture, coherency is maintained either through hardware cache snooping (common in unified memory architectures) or automatic driver-level cache management.
  • Ease of Implementation: Developers do not need to track dirty regions, calculate memory alignment, or invoke secondary commands after modifying the buffer data.

While convenient, host coherency can introduce performance penalties. Hardware cache-snooping mechanisms can saturate interconnect buses with frequent synchronization traffic, particularly during heavy, continuous write operations.

Manual Memory Flushing

When memory is allocated without VK_MEMORY_PROPERTY_HOST_COHERENT_BIT, it is considered non-coherent. The host CPU updates its own local caches, but those writes remain invisible to the GPU until the developer explicitly flushes them using vkFlushMappedMemoryRanges.

When writing to a non-coherent mapped buffer:

  • Explicit Control: The developer defines exact VkMappedMemoryRange bounds indicating which sub-regions of the buffer were modified.
  • Batched Cache Eviction: CPU cache lines corresponding to the specified range are pushed out to memory all at once, minimizing bus traffic and eliminating the continuous overhead of hardware snooping.
  • Alignment Constraints: Flushed ranges must adhere to strict alignment rules defined by the device limit nonCoherentAtomSize. Both the offset and size parameters within VkMappedMemoryRange must typically be multiples of this value (unless the range extends to the end of the allocation).

Key Differences

  • Control and Responsibility: Host coherency shifts the burden of synchronization entirely to the driver and hardware. Flushing gives the developer direct responsibility over when and what cache ranges are written out to device-visible memory.
  • API Calls: Coherent memory requires only standard memory write operations (e.g., memcpy). Non-coherent memory requires an additional call to vkFlushMappedMemoryRanges before any GPU command reads the buffer.
  • Performance Profile: For sporadic, tiny, or unpredictable updates, host-coherent memory often simplifies code with negligible overhead. For large, batched data updates, non-coherent memory combined with explicit flushes avoids continuous cache-coherence traffic and frequently yields superior throughput.
  • Availability: Not all physical memory heaps support both modes. Dedicated VRAM on discrete GPUs usually does not support host visibility at all, while host-visible staging buffers or unified memory heaps may offer both coherent and non-coherent variants.
