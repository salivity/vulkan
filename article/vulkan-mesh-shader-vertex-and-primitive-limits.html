Vulkan Mesh Shader Vertex and Primitive Limits

In the Vulkan graphics API, mesh shaders replace traditional vertex and primitive processing stages to allow flexible, compute-like generation of geometry via clusters called meshlets. When designing mesh shaders using the cross-vendor VK_EXT_mesh_shader extension, developers must adhere to strict hardware limitations governing the maximum number of vertices and primitives a single meshlet workgroup can output. This article details the official specification minimums, property queries, and practical recommendations for vertex and primitive allocations per meshlet in Vulkan.

Core Limits in VK_EXT_mesh_shader

The output capabilities of a mesh shader workgroup are queried via the VkPhysicalDeviceMeshShaderPropertiesEXT structure passed to vkGetPhysicalDeviceProperties2. The primary properties defining the per-meshlet generation limits are:

  • maxMeshOutputVertices: The maximum number of vertices that a single mesh shader workgroup can emit. The Vulkan specification mandates that hardware supporting VK_EXT_mesh_shader must support at least 256 output vertices.
  • maxMeshOutputPrimitives: The maximum number of primitives (typically triangles or lines) that a single mesh shader workgroup can emit. The specification similarly mandates that implementations support at least 256 output primitives.

Additionally, implementations define maxMeshOutputComponents, which restricts the total scalar components across all vertex outputs (guaranteed minimum of 16,384), and maxMeshOutputLayers, which limits render target layer rendering.

In-Shader Declaration Constraints

Within GLSL (using GL_EXT_mesh_shader) or SPIR-V, a mesh shader must explicitly declare the maximum output size in its layout qualifiers. For example:

layout(local_size_x = 32) in;
layout(triangles, max_vertices = 64, max_primitives = 126) out;

The declared max_vertices and max_primitives values must not exceed the physical device's maxMeshOutputVertices and maxMeshOutputPrimitives respectively. Exceeding these values results in validation errors or undefined behavior.

Architectural Best Practices

While hardware guarantees support for up to 256 vertices and 256 primitives, maximizing these values can lead to suboptimal GPU occupancy. Each meshlet requires on-chip memory to store its output attributes before primitive assembly and rasterization.

  • Triangles per Meshlet: A common target for triangle geometry is 64 to 128 vertices and 126 to 256 triangles. A configuration of 64 vertices and 126 primitives is widely regarded as a sweet spot across major desktop GPU architectures (including NVIDIA, AMD, and Intel), balancing memory footprint and hardware thread scheduling.
  • Workgroup Invocations: The number of invocations per workgroup (maxMeshWorkGroupInvocations, required minimum of 32) should generally be chosen to align with the GPU’s native subgroup (wave/warp) size to prevent idling threads when writing out vertex and index buffers.
