Why Vulkan Mipmapping Requires Blit Flags

Generating mipmaps dynamically at runtime in Vulkan requires downsampling an image through a sequence of blit operations, typically executed with vkCmdBlitImage. Because this standard mipmap generation technique reads from a higher-resolution mip level and writes to the next lower-resolution level, the chosen image format must explicitly support both VK_FORMAT_FEATURE_BLIT_SRC_BIT and VK_FORMAT_FEATURE_BLIT_DST_BIT. Without these two capabilities supported by the physical device, attempting to use the blit command to downsample the texture will result in undefined behavior or validation layer errors.

The Role of vkCmdBlitImage in Mipmap Generation

Unlike APIs like OpenGL that offer built-in functions such as glGenerateMipmap, Vulkan gives low-level control and requires developers to implement their own mipmapping pipeline. The standard approach involves iteratively downsampling the base texture level-by-level until all mip levels are populated:

  1. Level \(i\) is transitioned to VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL.
  2. Level \(i+1\) is transitioned to VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL.
  3. vkCmdBlitImage copies and downsamples level \(i\) to level \(i+1\) using linear filtering.
  4. Level \(i\) is transitioned to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL for shader sampling.
  5. The process repeats with level \(i+1\) becoming the new source for level \(i+2\).

Because each mip level (except the first and last) acts as both a target for writing and a source for subsequent reading, the image format must satisfy the hardware requirements for both roles.

Why VK_FORMAT_FEATURE_BLIT_SRC_BIT Is Required

During downsampling, the source mip level must be read and filtered by the graphics hardware's fixed-function texture filtering units.

When you specify VK_FORMAT_FEATURE_BLIT_SRC_BIT, you are verifying that the hardware can read this specific format as an input for a blit command. In addition, blitting generally requires VK_FILTER_LINEAR to perform a smooth downsampling step, which demands that the format can be sampled using linear interpolation during transfer operations. If this flag is missing, the GPU cannot safely sample or filter pixels from that format.

Why VK_FORMAT_FEATURE_BLIT_DST_BIT Is Required

The blit destination represents the smaller target mip level that receives the filtered pixel data.

The VK_FORMAT_FEATURE_BLIT_DST_BIT flag verifies that the GPU has the hardware capability to write interpolated pixel data directly into the specified image format. Not every format natively supports hardware-accelerated writes or conversions during a blit operation. Without destination blit support, the GPU cannot store the filtered output into the target mip slice.

Checking Format Capabilities

Before attempting to create an image intended for blit-based mipmapping, applications must query the physical device using vkGetPhysicalDeviceFormatProperties.

The returned VkFormatProperties struct contains optimalTilingFeatures. The application must verify that:

(formatProperties.optimalTilingFeatures & VK_FORMAT_FEATURE_BLIT_SRC_BIT) &&
(formatProperties.optimalTilingFeatures & VK_FORMAT_FEATURE_BLIT_DST_BIT)

If both flags are not present for the selected format under optimal tiling, vkCmdBlitImage cannot be used.

Alternatives When Blit Flags Are Not Supported

If a format lacks either VK_FORMAT_FEATURE_BLIT_SRC_BIT or VK_FORMAT_FEATURE_BLIT_DST_BIT, mipmaps must be generated through alternative pipelines:

  • Compute Shaders: Use a compute shader to manually sample level \(i\) and write to level \(i+1\) via storage images (VK_FORMAT_FEATURE_STORAGE_IMAGE_BIT).
  • Graphics Render Passes: Render a fullscreen quad where each mip level is bound as a color attachment (VK_FORMAT_FEATURE_COLOR_ATTACHMENT_BIT) and the preceding level is sampled as a standard texture.
  • Precomputed Mipmaps: Generate all mip levels offline during asset preparation and upload them directly into the image subresources, avoiding any runtime generation on the GPU.
