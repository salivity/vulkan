Guide to Vulkan VK_KHR_performance_query Extension

The VK_KHR_performance_query extension provides developers and profiling tools with a standardized way to query internal GPU hardware performance counters in the Vulkan API. By exposing metrics such as execution unit utilization, cache hit and miss rates, and memory bus bandwidth, it allows for granular, low-level performance analysis across different hardware vendors without relying on proprietary, vendor-specific diagnostic APIs.

Purpose and Core Functionality

Before the introduction of VK_KHR_performance_query, retrieving hardware-specific performance metrics required external vendor profiling tools or proprietary extensions specific to NVIDIA, AMD, Intel, or mobile GPU manufacturers. The primary purpose of VK_KHR_performance_query is to standardize this mechanism across the entire Vulkan ecosystem.

The extension enables an application to query hardware counters directly inside the Vulkan command stream, placing counter collection within the exact execution context of specific draw, compute, or copy commands.

How the Extension Operates

The extension integrates into the standard Vulkan query pool infrastructure using the VK_QUERY_TYPE_PERFORMANCE_QUERY_KHR query type. The general profiling workflow involves several distinct steps:

  1. Counter Enumeration: The application queries the device using vkEnumeratePhysicalDeviceQueueFamilyPerformanceQueryCountersKHR to discover which hardware counters are available on a specific queue family. Each counter describes its storage format (float, integer, percentage), unit of measurement, and scope.
  2. Determining Required Passes: Hardware architectures have a limited number of physical performance registers, meaning not all counters can be sampled simultaneously. The API provides vkGetPhysicalDeviceQueueFamilyPerformanceQueryPassesKHR to determine how many times a workload must be replayed (passes) to capture the requested combination of counters.
  3. Query Pool Creation: A query pool is allocated with VkQueryPoolPerformanceCreateInfoKHR, specifying the exact subset of counters the application intends to record.
  4. Recording and Extraction: Commands are bookended using vkCmdBeginQuery and vkCmdEndQuery. If multiple passes are required, the exact sequence of commands must be submitted and recorded across the required number of passes before reading the results back with vkGetQueryPoolResults.

Common Use Cases

  • Profiling Tools Integration: Tools like RenderDoc, GPU vendor profilers, and in-engine diagnostic overlays use the extension to gather accurate execution data per draw call, pipeline stage, or pass.
  • Bottleneck Identification: Developers can analyze whether a shader workload is compute-bound, bandwidth-bound, or stalled on texture cache lookups.
  • Automated CI Benchmarking: Game engines and graphics runtimes can run automated test suites that capture counter values to detect performance regressions in specific rendering passes.

Considerations and Limitations

VK_KHR_performance_query is designed exclusively for profiling and development environments rather than runtime end-user builds. Because physical counter sampling may require replaying commands across multiple passes, it cannot generally be used for real-time dynamic engine adjustments. Additionally, because GPU counters can potentially leak sensitive information across processes via timing side-channels, modern operating systems and display drivers often require elevated administrator privileges or specific developer modes to enable counter collection.
