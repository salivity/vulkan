Vulkan Occlusion Queries and Hierarchical Z-Culling

This article examines how occlusion queries in the Vulkan API interface with GPU-driven Hierarchical Z (Hi-Z) culling. It outlines the interaction between hardware depth hierarchies, bounding box query tests, and modern GPU rendering paths to eliminate redundant draw calls and overdraw without relying on CPU readbacks.

Hierarchical Z-buffering (Hi-Z) is a fixed-function hardware optimization that stores a multi-resolution pyramid of the depth buffer. Each level in the pyramid represents the maximum (or minimum, depending on the depth convention) depth value for a tile of pixels. Before rasterizing geometry at the pixel level, the GPU compares the incoming primitive’s depth bounds against these coarse tiles. If the primitive is entirely behind the existing depth threshold of a tile, it is instantly discarded, bypassing fragment shader execution.

Occlusion queries in Vulkan (VK_QUERY_TYPE_OCCLUSION) directly exploit this hardware architecture. An application wraps the rendering of simplified proxy geometry—such as an Axis-Aligned Bounding Box (AABB) of a complex mesh—between vkCmdBeginQuery and vkCmdEndQuery. When rasterizing these bounding boxes, the GPU does not write color or depth values; it only evaluates whether any samples pass the current depth-stencil test. Because these proxy meshes produce flat surfaces over screen tiles, the GPU's rasterizer tests them directly against the coarse Hi-Z representation rather than evaluating individual depth buffer pixels, allowing the query to complete with minimal processing overhead.

To implement GPU-based culling using this mechanism in Vulkan, developers typically follow a multi-stage approach:

  1. Depth Pre-Pass: A depth-only pass or the previous frame’s reprojected depth buffer establishes the initial depth state and populates the hardware Hi-Z caches.
  2. Proxy Testing: Conservative bounding volumes of candidate meshes are rendered into an occlusion query pool with depth-testing enabled and depth-writes disabled. The hardware Hi-Z unit discards fully occluded boxes across entire tiles simultaneously.
  3. GPU-Side Evaluation: Instead of stalling the pipeline by copying query results back to the CPU via vkGetQueryPoolResults, Vulkan allows results to remain on the GPU. Using the VK_EXT_conditional_rendering extension, the query pool's output is written directly to a GPU buffer. The Vulkan commands for the actual complex meshes are executed conditionally based on whether the query registered a sample count greater than zero.
  4. Indirect Execution: Alternatively, a compute shader can process the query results buffer, constructing draw parameters inside a VkDrawIndexedIndirectCommand buffer to conditionally launch or skip mesh draws entirely on the GPU timeline.

By combining Vulkan occlusion queries with the GPU's internal Hi-Z pipeline, the graphics hardware performs coarse, high-throughput depth elimination on lightweight geometry, completely insulating the fragment shading and vertex processing stages from occluded, high-poly assets.
