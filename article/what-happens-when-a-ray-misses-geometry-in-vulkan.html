What Happens When a Ray Misses Geometry in Vulkan

In Vulkan ray tracing, when a traversing ray fails to intersect any valid geometry within an acceleration structure, the pipeline immediately halts traversal and triggers fallback logic rather than terminating unexpectedly. In a standard ray tracing pipeline, this event invokes a dedicated miss shader identified via the Shader Binding Table (SBT) to handle tasks like background rendering or shadow evaluation. If ray queries are used instead, traversal simply terminates, returning a status code indicating that no geometry was encountered.

The Traversal and Miss Detection Process

When a ray is cast using the traceRayEXT() function within a ray generation, closest hit, or callable shader, the hardware traverses the Top-Level Acceleration Structure (TLAS) and any nested Bottom-Level Acceleration Structures (BLAS). During traversal, the ray is evaluated against geometric bounding volumes and primitives.

A miss occurs under any of the following conditions:

  • The ray trajectory never intersects any primitive bounding boxes or custom Axis-Aligned Bounding Boxes (AABBs).
  • Potential intersections fall outside the defined parametric range between rayTmin and rayTmax.
  • Primitives along the path are rejected by instance inclusion masks.
  • Potential intersections are culled by ray flags, such as gl_RayFlagsCullBackFacingTrianglesEXT.
  • An any-hit shader explicitly rejects all candidate hits along the path using ignoreIntersectionEXT().

Once the traversal hardware confirms that no intersection meets the criteria within the valid ray intervals, traversal terminates, and control transitions directly to miss handling.

Execution of the Miss Shader

In ray tracing pipelines (VK_KHR_ray_tracing_pipeline), a miss triggers the execution of a Miss Shader (.rmiss). Which miss shader executes is governed by parameters passed to traceRayEXT():

traceRayEXT(
    topLevelAS,       // Acceleration structure
    rayFlags,         // Ray behavior flags
    cullMask,         // 8-bit mask to filter instances
    sbtRecordOffset,  // Hit group offset
    sbtRecordStride,  // Hit group stride
    missIndex,        // Index of the miss shader in the SBT
    origin,           // Ray origin
    tMin,             // Minimum ray travel distance
    direction,        // Ray direction
    tMax,             // Maximum ray travel distance
    payloadLocation   // Ray payload index
);

The missIndex parameter defines the offset into the miss shader section of the Shader Binding Table. Vulkan indexes the table as:

\[\text{Miss Shader Address} = \text{Miss Base Address} + (\text{missIndex} \times \text{Miss Stride})\]

If the index points to an entry configured with an invalid or null shader handle, the execution results in undefined behavior, which often triggers a VK_ERROR_DEVICE_LOST.

Modifying the Ray Payload

The miss shader shares access to the incoming ray payload defined by rayPayloadInEXT. Because a miss shader cannot generate further intersections along the same path, its primary role is to update this payload to reflect the absence of geometry before returning control to the caller:

  • Primary and Camera Rays: The miss shader samples an environment map, applies an atmospheric model, or writes a constant clear color to the payload to draw the sky or background.
  • Shadow Rays: For simple binary visibility testing, the miss shader marks a flag in the payload indicating light visibility (for example, setting isVisible = true or attenuation to 1.0). If the ray hits geometry, the closest hit or any-hit shader would instead mark it as occluded.
  • Ambient Occlusion Rays: The miss shader records maximum ambient illumination, indicating that ambient light reached unobstructed space.

Ray Miss Handling in Ray Queries

When using inline ray tracing via ray queries (VK_KHR_ray_query) in standard compute or graphics pipelines, no miss shader exists. Instead, traversal is executed incrementally using a loop:

rayQueryEXT rayQuery;
rayQueryInitializeEXT(rayQuery, topLevelAS, rayFlags, cullMask, origin, tMin, direction, tMax);

while(rayQueryProceedEXT(rayQuery)) {
    // Process candidate intersections if using custom geometry or any-hit logic
}

if (rayQueryGetIntersectionTypeEXT(rayQuery, true) == gl_RayQueryCommittedIntersectionNoneEXT) {
    // The ray missed all geometry; handle background or visibility directly here
}

When the ray misses all primitives, rayQueryProceedEXT() eventually returns false, and rayQueryGetIntersectionTypeEXT() resolves to gl_RayQueryCommittedIntersectionNoneEXT. The invoking shader must then execute its own fallback logic in place.
