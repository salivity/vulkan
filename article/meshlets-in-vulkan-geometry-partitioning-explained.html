Meshlets in Vulkan: Geometry Partitioning Explained

This article provides an overview of meshlets, explaining how traditional 3D models are divided into small, cache-friendly geometric clusters to optimize rendering. It covers the core concept of a meshlet, the mathematical and structural methods used to partition polygonal meshes, and how the Vulkan graphics API processes these structures using modern mesh shading pipelines to significantly boost GPU throughput.

What is a Meshlet?

A meshlet is a small, localized sub-mesh derived from a larger polygonal 3D model. In traditional graphics pipelines, geometry is fed to the GPU as long streams of indexed vertex and index buffers. This approach suffers from bottlenecks in vertex reuse, limited cache locality, and inefficient culling of off-screen or occluded triangles.

A meshlet solves these issues by packaging geometry into self-contained clusters with a fixed upper bound of vertices and primitives. A common configuration targets a maximum of 64 vertices and 126 triangles per meshlet. Because these limits are strictly defined, all local indexing within a meshlet can use 8-bit integers rather than standard 16-bit or 32-bit indices, drastically reducing memory bandwidth.

How Geometry is Partitioned into Meshlets

Partitioning a large polygonal mesh into meshlets typically occurs during offline asset conditioning or via a GPU compute pre-pass. The partitioning process follows several key steps:

  1. Adjacency and Graph Construction: The mesh's triangles and vertices are analyzed to build an adjacency graph that maps which triangles share edges and vertices.
  2. Cluster Growing: Algorithms (such as Metis, greedy search, or spatial clustering based on surface normals) iterate through the graph. The algorithm groups connected triangles into a cluster until it hits either the vertex count limit (e.g., 64) or the primitive count limit (e.g., 126).
  3. Locality Optimization: The cluster generation actively optimizes for vertex sharing. High vertex reuse within the cluster minimizes the total number of unique vertices stored per meshlet.
  4. Local Indexing: Global 32-bit vertex indices are mapped to compact local arrays. Each triangle inside the meshlet points to local 8-bit indices corresponding to the meshlet's internal vertex list.
  5. Bounding Volume Generation: Each meshlet generates its own spatial metadata, including an oriented bounding box (OBB) or bounding sphere, as well as a normal cone. This metadata is stored alongside the meshlet data to enable fast rejection tests.

Processing Meshlets in Vulkan

Vulkan interfaces with meshlets through the VK_EXT_mesh_shader extension, bypassing the classic input assembler, vertex shader, and geometry shader stages in favor of a compute-centric pipeline composed of Task and Mesh shaders.

1. The Task Shader (Cluster Culling)

The task shader acts as a coarse-grained filter for meshlets:

  • A task shader workgroup receives an array of meshlet descriptors.
  • It evaluates the bounding volumes and normal cones of each meshlet against the camera's view frustum, occlusion buffers, and view angle.
  • Entire meshlets are discarded before entering the geometry pipeline if they lie outside the frustum, face away from the camera (cluster backface culling), or are occluded.
  • Surviving meshlets dispatch subsequent mesh shader workgroups dynamically using the EmitMeshTasksEXT command.

2. The Mesh Shader (Primitive Generation)

Once dispatched, each mesh shader workgroup processes a single meshlet:

  • Mesh shaders operate cooperatively like compute shaders, with threads working in parallel across the meshlet's internal data.
  • Threads load the unique vertices into on-chip shared memory, transform them to screen space, and write the compact, 8-bit local primitive indices directly to the rasterizer via built-in output arrays.
  • Because the thread allocation closely matches the hardware's warp or wavefront size, hardware resources are used near maximum efficiency with zero reliance on the legacy hardware index buffer cache.

By replacing continuous vertex streams with independently processed, pre-culled meshlets, Vulkan enables fine-grained level-of-detail management, massive draw call reduction, and optimal utilization of modern GPU compute capabilities.
