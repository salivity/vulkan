Vulkan GPU Pointers in Compute Shader Linked Lists

In modern GPU computing, managing dynamic data structures such as linked lists has traditionally required indexing schemes within Shader Storage Buffer Objects (SSBOs). With the introduction of Vulkan's buffer device address feature, developers can utilize raw 64-bit GPU pointers directly within compute shaders. This article explores how GPU pointers eliminate addressing overhead, reduce register pressure, bypass descriptor constraints, and significantly accelerate linked list traversal during compute workloads.

The Limitation of Index-Based Traversal

Historically, linked lists on the GPU rely on simulated pointers: integer indices referencing slots within an SSBO. In this model, traversing a linked list requires the compute shader to compute the physical memory location of a node at runtime using a base address and an offset formula:

\[\text{Target Address} = \text{Buffer Base Address} + (\text{Node Index} \times \text{Node Stride})\]

This approach incurs multiple execution bottlenecks:

  • Redundant ALU Operations: Each traversal step requires integer multiplication and addition to resolve the byte offset before issuing the memory load instruction.
  • Buffer Boundary Constraints: All linked list nodes must generally reside within a single contiguous buffer allocation, or complex logic must be written to handle partitioning across multiple descriptors.
  • Descriptor Overhead: Accessing nodes via descriptors requires binding management and consumes GPU descriptor registers, which can throttle shader occupancy.

Direct Address Dereferencing with Buffer Device Address

The VK_KHR_buffer_device_address extension (promoted to core in Vulkan 1.2) allows shaders to query and consume 64-bit GPU virtual addresses directly. Used in tandem with the GLSL extension GL_EXT_buffer_reference, structures can declare member pointers that point directly to other structures.

In a linked list implementation, each node contains a 64-bit pointer pointing directly to the memory address of the next node:

layout(buffer_reference, std430) buffer Node;
layout(buffer_reference, std430) buffer Node {
    uint data;
    Node next;
};

When dereferencing node.next, the GPU avoids calculating offsets relative to a descriptor base. Instead, it issues a direct memory load using the retrieved 64-bit address, mimicking standard pointer chasing in CPU C/C++ applications.

Elimination of Address Arithmetic and Latency Reduction

Traversing a linked list is a latency-bound operation; each iteration depends strictly on the arrival of the pointer load from the previous iteration. By eliminating the index-to-address scaling operations, GPU pointers cut down the instruction dependency chain in the inner traversal loop.

Because the GPU's execution units do not have to perform index multiplication and boundary checking before memory fetches, the time between a node being read and the next fetch being issued is minimized. This tight dependency loop is critical for mitigating memory pipeline stalls.

Reduced Register Pressure and Improved Occupancy

When using conventional descriptor-backed buffers, the GPU must track descriptor state, buffer sizes, and base addresses throughout the lifetime of the traversal loop. This retention increases scalar and vector register pressure.

GPU pointers are stored and manipulated as plain 64-bit integers. As a result:

  • The compiler can pack addresses into standard general-purpose registers without reserving special descriptor-handling registers.
  • Lower register pressure directly enables higher warp/wavefront occupancy on the compute units, allowing the GPU to hide memory latency more effectively across concurrent threads.

Cross-Buffer Traversals and Heterogeneous Memory

Index-based approaches fail when data structures span multiple memory allocations, requiring indirection tables or complex paging systems. GPU pointers use the entire 64-bit virtual address space mapped by the Vulkan driver.

Nodes belonging to the same logical linked list can reside in entirely separate VkBuffer objects or even different memory types (such as host-visible memory and high-bandwidth device-local memory). The traversal shader executes identically regardless of where the memory allocation resides, simplifying dynamic memory managers and custom GPU allocators.

Memory Alignment and Cache Behavior

GPU memory hierarchies favor coalesced, uniform access patterns. Linked lists inherently produce non-coalesced, divergent memory accesses across execution threads. While GPU pointers do not automatically fix divergence, they provide control over alignment via the buffer_reference_align layout qualifier.

Specifying explicit memory alignment matching the GPU's cache line interfaces (e.g., 16, 32, or 64 bytes) ensures that dereferenced pointers do not cross cache lines unnecessarily. Combined with direct address loading, this control yields more predictable cache hit rates and minimizes wasted memory bus bandwidth during deep pointer-chasing operations.
