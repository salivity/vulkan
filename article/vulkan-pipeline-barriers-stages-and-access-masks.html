Vulkan Pipeline Barriers: Stages and Access Masks

In the Vulkan API, pipeline barriers synchronize execution and memory access between commands submitted to a queue. Configuring a barrier requires setting pipeline stage masks (srcStageMask and dstStageMask) to establish an execution dependency and access masks (srcAccessMask and dstAccessMask) to establish a memory dependency. Properly configuring these parameters guarantees that data written by prior commands is completed and made visible before subsequent operations attempt to read from or write to the same resources, avoiding race conditions without introducing unnecessary GPU stalls.

Execution Dependencies: Pipeline Stages

Execution dependencies govern when operations happen relative to one another in the GPU pipeline. They are defined using VkPipelineStageFlags (or VkPipelineStageFlags2 in Vulkan 1.3 / VK_KHR_synchronization2).

  • Source Stage Mask (srcStageMask): Identifies the pipeline stages of prior commands that must finish executing before the barrier takes effect. Any work submitted before the barrier in these stages will complete prior to proceeding past the barrier.
  • Destination Stage Mask (dstStageMask): Identifies the pipeline stages of subsequent commands that must wait. Any work submitted after the barrier requiring these stages will pause execution until the barrier's conditions are fulfilled.

Using coarse flags such as VK_PIPELINE_STAGE_ALL_COMMANDS_BIT or VK_PIPELINE_STAGE_TOP_OF_PIPE_BIT / VK_PIPELINE_STAGE_BOTTOM_OF_PIPE_BIT should be avoided when possible. Specifying exact stages—such as VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT or VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT—allows the GPU to overlap independent operations across different stages.

Memory Dependencies: Access Masks

An execution dependency alone does not guarantee that written data is visible to other stages, because GPUs use distinct, non-coherent caches across different functional units. Access masks define how resources are accessed and handle cache flushing and invalidation using VkAccessFlags (or VkAccessFlags2).

  • Source Access Mask (srcAccessMask): Specifies the memory write operations that must be completed and made available (flushed from internal caches to common memory or L2 cache). If the previous operations only performed reads, srcAccessMask can be set to 0.
  • Destination Access Mask (dstAccessMask): Specifies the memory operations that must be made visible (caches invalidated so that subsequent reads or writes fetch the freshest data).

Stage and Access Mask Compatibility

Vulkan strictly enforces that access masks correspond logically to the stages provided in the pipeline stage masks:

  1. Every access flag in srcAccessMask must be supported by at least one stage in srcStageMask.
  2. Every access flag in dstAccessMask must be supported by at least one stage in dstStageMask.

For instance, pairing VK_ACCESS_COLOR_ATTACHMENT_WRITE_BIT with VK_PIPELINE_STAGE_VERTEX_SHADER_BIT is invalid because color attachment writes do not occur during vertex shading.

Common Configuration Patterns

1. Color Attachment Write to Fragment Shader Sample

When a render pass writes to an image and the next pass samples that image as a texture:

  • srcStageMask: VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT
  • srcAccessMask: VK_ACCESS_COLOR_ATTACHMENT_WRITE_BIT
  • dstStageMask: VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT
  • dstAccessMask: VK_ACCESS_SHADER_READ_BIT
  • Layout Transition: VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL

2. Compute Shader Write to Vertex Shader Read

When a compute shader writes to a storage buffer that will subsequently be read as a vertex buffer or uniform buffer:

  • srcStageMask: VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT
  • srcAccessMask: VK_ACCESS_SHADER_WRITE_BIT
  • dstStageMask: VK_PIPELINE_STAGE_VERTEX_INPUT_BIT
  • dstAccessMask: VK_ACCESS_VERTEX_ATTRIBUTE_READ_BIT

3. Host Write to GPU Device Read

When updating host-visible memory without explicit host coherent flushes, or synchronizing after a vkQueueSubmit:

  • srcStageMask: VK_PIPELINE_STAGE_HOST_BIT
  • srcAccessMask: VK_ACCESS_HOST_WRITE_BIT
  • dstStageMask: Target pipeline stage (e.g., VK_PIPELINE_STAGE_TRANSFER_BIT)
  • dstAccessMask: Corresponding access type (e.g., VK_ACCESS_TRANSFER_READ_BIT)

Vulkan 1.3 and Synchronization2

In modern Vulkan, vkCmdPipelineBarrier2 replaces the original pipeline barrier command. It consolidates stage and access masks directly into VkMemoryBarrier2, VkBufferMemoryBarrier2, and VkImageMemoryBarrier2 structures via 64-bit flags (VkPipelineStageFlags2 and VkAccessFlags2). This eliminates the mismatch risk between global stage masks and per-resource access masks, simplifying configuration while maintaining identical underlying synchronization logic.
