How Vulkan Ray Generation Shaders Initiate Traversal

In Vulkan ray tracing pipelines (VK_KHR_ray_tracing_pipeline), ray generation shaders serve as the computational entry point responsible for launching rays into a 3D scene. These shaders set up ray parameters—such as origin, direction, and traversal bounds—and trigger the hardware-accelerated traversal of Top-Level Acceleration Structures (TLAS) using dedicated shading language intrinsics. Once invoked, traversal tests the rays against bounding volume hierarchies (BVH) to evaluate intersections with the underlying geometry.

Binding the Top-Level Acceleration Structure

Before traversal can begin, the application must provide the shader access to the scene representation. In Vulkan, scenes are organized hierarchically: Bottom-Level Acceleration Structures (BLAS) hold actual vertex and index geometry, while a Top-Level Acceleration Structure (TLAS) contains instances pointing to those BLAS objects with transformation matrices.

The application exposes the TLAS to the ray generation shader using a descriptor set bound with the descriptor type VK_DESCRIPTOR_TYPE_ACCELERATION_STRUCTURE_KHR. Within GLSL, this structure is declared as a uniform variable:

layout(binding = 0, set = 0) uniform accelerationStructureEXT topLevelAS;

Initializing Ray Geometry and Payloads

When the command vkCmdTraceRaysKHR is issued on the host, the GPU launches a grid of ray generation shader invocations corresponding to specified dimensions (typically matching the render target's width, height, and depth).

Each thread calculates its work coordinates using built-in variables like gl_LaunchIDEXT and gl_LaunchSizeEXT. The shader transforms these coordinates from screen space into world space to derive the ray's starting position (origin) and normalized path (direction). Additionally, the shader defines a payload variable marked with the rayPayloadEXT storage qualifier to carry data, such as colors or hit distances, across shader stages.

Executing Traversal via traceRayEXT

Traversal is formally initiated by calling the built-in intrinsic function traceRayEXT() in GLSL (or TraceRay() in HLSL). This call halts standard execution of the ray generation thread and passes control to the GPU's traversal hardware or compute emulation units.

The traceRayEXT() function requires the following parameters:

  • Acceleration Structure: The bound topLevelAS handle to traverse.
  • Ray Flags: Bitwise flags modifying traversal behavior (e.g., gl_RayFlagsOpaqueEXT to skip any-hit shaders, or gl_RayFlagsTerminateOnFirstHitEXT for shadow evaluations).
  • Cull Mask: An 8-bit integer matched against the instance masks defined in the TLAS to include or exclude specific geometry groups.
  • SBT Offsets and Strides: Values determining how geometry instances select specific hit groups within the Shader Binding Table (SBT).
  • Miss Index: The index offset used to select the appropriate miss shader if no intersections are found.
  • Ray Bounds: Three-dimensional vectors for the ray origin and ray direction, along with scalar floating-point values for minimum distance (tMin) and maximum distance (tMax).
  • Payload Location: The identifier specifying which rayPayloadEXT variable receives data from downstream shaders.

Hardware Traversal and Downstream Execution

Once traceRayEXT() is executed, the GPU's ray-tracing cores traverse the TLAS hierarchy down to individual BLAS nodes, testing ray-box and ray-triangle intersections.

Depending on the results of the traversal:

  • If an intersection is confirmed, the traversal logic indexes into the Shader Binding Table to invoke the designated Any-Hit, Intersection, or Closest-Hit shader.
  • If the ray exceeds tMax without finding a valid intersection, the designated Miss shader is executed.

After all downstream hit or miss processing completes, control returns to the ray generation shader immediately following the traceRayEXT() invocation. The shader can then read the updated ray payload values to perform further shading calculations, write results to a storage image, or launch subsequent secondary rays (such as reflections or ambient occlusion).
