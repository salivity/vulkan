Vulkan Pipeline Statistics for Geometry Bottlenecks

Vulkan pipeline statistics querying provides low-overhead, hardware-level metrics that track how primitives and vertices move through each programmable and fixed-function stage of the graphics pipeline. By capturing exact counts of vertex invocations, primitive assembly, clipping behavior, and fragment generation, developers can evaluate the efficiency of their geometry pipeline. Comparing these metrics reveals severe geometry inefficiencies, such as excessive off-screen processing, micro-triangles, and inefficient shader amplification, allowing targeted optimizations.

Understanding Pipeline Statistics Queries

Vulkan exposes GPU counters directly via query pools configured with the VK_QUERY_TYPE_PIPELINE_STATISTICS type. When creating a query pool, the application specifies flags (VkQueryPipelineStatisticFlags) to determine which metrics the hardware records.

To measure specific draw commands, the application sandwiches draw calls between vkCmdBeginQuery and vkCmdEndQuery within a command buffer. Once the GPU completes the work, results are retrieved on the CPU using vkGetQueryPoolResults or copied to a buffer on the GPU using vkCmdCopyQueryPoolResults.

Key Metrics for Geometry Analysis

Geometry bottlenecks occur when the GPU spends disproportionate time processing, transforming, and culling vertices rather than rasterizing visible pixels. Several specific query flags are essential for diagnosing these issues:

  • VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_VERTICES_BIT: Tracks the total raw vertices consumed by the input assembler.
  • VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_PRIMITIVES_BIT: Measures how many primitives (triangles, lines, points) were assembled.
  • VK_QUERY_PIPELINE_STATISTIC_VERTEX_SHADER_INVOCATIONS_BIT: Tracks vertex shader executions, which helps verify the efficiency of the post-transform cache.
  • VK_QUERY_PIPELINE_STATISTIC_CLIPPING_INVOCATIONS_BIT and ..._CLIPPING_PRIMITIVES_BIT: Measures the geometry sent to the clipping stage and how many viable primitives survived clipping.
  • VK_QUERY_PIPELINE_STATISTIC_GEOMETRY_SHADER_INVOCATIONS_BIT and ..._PRIMITIVES_BIT: Tracks invocation and amplification factors if geometry shaders are used.
  • VK_QUERY_PIPELINE_STATISTIC_FRAGMENT_SHADER_INVOCATIONS_BIT: Used in correlation with primitive metrics to determine primitive density.

Diagnosing Specific Bottlenecks

1. Inefficient Culling (High Clipping Discard)

A classic geometry bottleneck is feeding the GPU triangles that never contribute to the final image.

By comparing VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_PRIMITIVES_BIT to VK_QUERY_PIPELINE_STATISTIC_CLIPPING_PRIMITIVES_BIT, you obtain the survival rate of your primitives. If the input assembly counts are drastically higher than the primitives output by the clipper, the pipeline is wasting compute cycles transforming vertices outside the camera frustum or occluded by other geometry.

Remedy: Introduce coarse CPU-side bounding-box culling or a GPU compute-based culling pass (such as frustum and Hi-Z occlusion culling) before the draw calls.

2. Sub-Pixel / Micro-Triangle Overhead

Modern GPUs struggle when triangles are smaller than a single pixel or quad-fragment (2x2 pixels), as helper lanes in compute warps/wavefronts are underutilized.

To identify this, compare VK_QUERY_PIPELINE_STATISTIC_CLIPPING_PRIMITIVES_BIT with VK_QUERY_PIPELINE_STATISTIC_FRAGMENT_SHADER_INVOCATIONS_BIT. If the ratio shows an extremely low number of fragment shader invocations per survived primitive, the scene suffers from micro-triangles.

Remedy: Implement a Level of Detail (LOD) system to swap in lower-polygon meshes at distance, or apply normal maps instead of modeling minute geometric details.

3. Poor Post-Transform Cache Utilization

When using indexed drawing, the post-transform cache prevents re-executing vertex shaders for duplicate vertices shared across triangles.

Comparing VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_VERTICES_BIT with VK_QUERY_PIPELINE_STATISTIC_VERTEX_SHADER_INVOCATIONS_BIT reveals caching behavior. If the invocation count closely matches the assembly count on shared-vertex meshes, the index buffer order is suboptimal.

Remedy: Reorder index and vertex buffers using cache-optimizing algorithms (such as Tom Forsyth's algorithm or modern tools like meshoptimizer) to maximize vertex reuse.

4. Geometry Shader Amplification Penalties

Geometry shaders that generate a high number of new primitives can quickly saturate memory bandwidth and pipeline throughput.

Comparing VK_QUERY_PIPELINE_STATISTIC_GEOMETRY_SHADER_INVOCATIONS_BIT to VK_QUERY_PIPELINE_STATISTIC_GEOMETRY_SHADER_PRIMITIVES_BIT measures the amplification factor. An excessive output count can stall downstream rasterization stages.

Remedy: Offload complex amplification to tessellation shaders, compute shaders generating indirect draws, or mesh shaders (VK_EXT_mesh_shader), which offer greater control over on-chip memory.
