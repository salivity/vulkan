TLAS Transformations in Vulkan Ray Tracing

In Vulkan's ray tracing pipeline, top-level acceleration structures (TLAS) position and orient geometry by holding instances of bottom-level acceleration structures (BLAS). Each instance stores a single 3x4 affine transformation matrix that defines how the associated BLAS geometry transitions from its local object space into world space. This article details the specific geometric transformations represented by this structure, its mathematical layout, and its operational limitations.

The Transform Matrix Structure

Vulkan defines instance-level geometric transforms using the VkTransformMatrixKHR structure within each VkAccelerationStructureInstanceKHR. Mathematically, this is a 3x4 matrix stored in row-major order:

| m[0][0]  m[0][1]  m[0][2]  m[0][3] |
| m[1][0]  m[1][1]  m[1][2]  m[1][3] |
| m[2][0]  m[2][1]  m[2][2]  m[2][3] |

This structure acts as a standard 4x4 affine transformation matrix where the bottom row is implicitly defined as [0, 0, 0, 1].

Supported Geometric Transformations

Because the matrix is affine, it supports any combination of linear transformations and translation:

  • Translation: Handled by the fourth column (m[0][3], m[1][3], and m[2][3]). These values specify the offset along the X, Y, and Z axes in world space.
  • Rotation: Handled by the left 3x3 submatrix. Standard Euler angles, quaternions, or axis-angle rotations are converted into this 3x3 orthogonal orientation matrix.
  • Scaling: Handled along the diagonal and axes within the left 3x3 submatrix. It supports both uniform and non-uniform scaling across the X, Y, and Z axes.
  • Shearing (Skewing): Handled by the off-diagonal components of the left 3x3 submatrix, allowing geometric deformation along specified planes.

Unsupported Transformations

Because the fourth row is strictly implicit ([0, 0, 0, 1]), Vulkan TLAS instances do not support projective transformations (such as perspective warping). Any non-affine deformation or non-linear displacement must either be baked directly into the vertex data of the BLAS or processed during runtime via programmable shader stages before acceleration structure updates.
