Per-Draw Variable Rate Shading in Vulkan

Variable Rate Shading (VRS) per-draw is a graphics optimization technique that enables developers to control fragment shading frequency at the granularity of individual draw calls, reducing GPU workload without significantly impacting visual fidelity. This article explains the fundamentals of per-draw VRS and demonstrates how to dynamically configure it in Vulkan using the VK_KHR_fragment_shading_rate extension.

Understanding Per-Draw Variable Rate Shading

Traditional rendering executes the fragment shader once for every rasterized pixel (a 1x1 rate). Variable Rate Shading decouples pixel coverage from fragment shader invocation rate. By grouping pixels together—such as 2x1, 1x2, 2x2, or 4x4 blocks—the GPU executes the fragment shader once and broadcasts the resulting color across all pixels within that block.

Per-draw VRS applies a single shading rate across an entire draw call. This is particularly effective for rendering passes or geometry where fine shading detail is unnecessary. Common use cases include:

  • Distant or background objects where high spatial frequency details are not perceptible.
  • Objects subject to heavy motion blur or depth of field effects.
  • Secondary render passes, such as ambient occlusion, shadow maps, or velocity buffers.

Unlike image-based VRS, which determines shading rates from a screen-space texture, per-draw VRS requires no additional memory attachments or lookups, making it lightweight and simple to integrate.

Prerequisites in Vulkan

To utilize per-draw VRS, the application must enable the VK_KHR_fragment_shading_rate device extension.

During device initialization, query and enable the feature in VkPhysicalDeviceFragmentShadingRateFeaturesKHR:

VkPhysicalDeviceFragmentShadingRateFeaturesKHR shadingRateFeatures = {};
shadingRateFeatures.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_FRAGMENT_SHADING_RATE_FEATURES_KHR;

VkPhysicalDeviceFeatures2 deviceFeatures = {};
deviceFeatures.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_FEATURES_2;
deviceFeatures.pNext = &shadingRateFeatures;

vkGetPhysicalDeviceFeatures2(physicalDevice, &deviceFeatures);

// Ensure the pipeline rate is supported
if (shadingRateFeatures.pipelineFragmentShadingRate) {
    // Enable the feature during vkCreateDevice
}

Enabling Dynamic Pipeline State

To change the shading rate dynamically on a command buffer without creating separate graphics pipelines for each rate, enable VK_DYNAMIC_STATE_FRAGMENT_SHADING_RATE_KHR in your pipeline dynamic state creation info:

VkDynamicState dynamicStates[] = {
    VK_DYNAMIC_STATE_VIEWPORT,
    VK_DYNAMIC_STATE_SCISSOR,
    VK_DYNAMIC_STATE_FRAGMENT_SHADING_RATE_KHR
};

VkPipelineDynamicStateCreateInfo dynamicStateCI = {};
dynamicStateCI.sType = VK_STRUCTURE_TYPE_PIPELINE_DYNAMIC_STATE_CREATE_INFO;
dynamicStateCI.dynamicStateCount = 3;
dynamicStateCI.pDynamicStates = dynamicStates;

Setting the Shading Rate Dynamically

Once the dynamic state is part of the pipeline, call vkCmdSetFragmentShadingRateKHR during command recording before issuing draw commands.

The function signature requires specifying the fragment dimensions and combiner operations:

VkExtent2D fragmentSize = { 2, 2 }; // Executes one fragment shader invocation per 2x2 pixel block

VkFragmentShadingRateCombinerOpKHR combinerOps[2] = {
    VK_FRAGMENT_SHADING_RATE_COMBINER_OP_KEEP_KHR,    // Pipeline vs Primitive rate
    VK_FRAGMENT_SHADING_RATE_COMBINER_OP_KEEP_KHR     // Result vs Attachment rate
};

vkCmdSetFragmentShadingRateKHR(commandBuffer, &fragmentSize, combinerOps);

// Bind pipeline, vertex buffers, and issue the draw call
vkCmdBindPipeline(commandBuffer, VK_PIPELINE_BIND_POINT_GRAPHICS, pipeline);
vkCmdDraw(commandBuffer, vertexCount, 1, 0, 0);

Combiner Operations

The combinerOps array defines how the per-draw shading rate interacts with other potential shading rate sources (primitive-level shading rates from the vertex/mesh shader and screen-space shading rate attachments):

  • combinerOps[0] dictates how the pipeline-specified rate combines with primitive-level rates.
  • combinerOps[1] dictates how that intermediate result combines with the shading rate attachment.

Using VK_FRAGMENT_SHADING_RATE_COMBINER_OP_KEEP_KHR ensures that the per-draw fragment size is preserved directly, bypassing modifications from other sources. Other options, such as VK_FRAGMENT_SHADING_RATE_COMBINER_OP_MIN_KHR or VK_FRAGMENT_SHADING_RATE_COMBINER_OP_MAX_KHR, allow rates to blend based on priority or visual quality requirements.
