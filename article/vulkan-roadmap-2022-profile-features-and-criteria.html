Vulkan Roadmap 2022 Profile Features and Criteria

The Vulkan Roadmap 2022 profile establishes a unified feature baseline for mid-to-high-end graphics hardware, encompassing PCs, consoles, and modern mobile devices. Introduced by the Khronos Group alongside Vulkan 1.3, this milestone sets strict requirements for modern hardware capabilities to reduce fragmentation for developers. This article details the specific core features, extensions, and hardware criteria mandated by the Vulkan Roadmap 2022 profile.

The Purpose of the Roadmap Profile

The Vulkan Roadmap profile provides a forward-looking standard that requires support for modern hardware capabilities beyond the core Vulkan 1.3 specification. Hardware vendors supporting this profile guarantee a consistent programming environment across operating systems and chipsets, allowing developers to target modern rendering techniques without managing extensive feature fallbacks.

Key Feature Criteria

To comply with the Vulkan Roadmap 2022 specification, drivers and devices must support a defined set of capabilities across memory architecture, pipeline management, and shader operations.

1. Descriptor Indexing and Bindless Rendering

The profile requires full support for descriptor indexing features (VkPhysicalDeviceDescriptorIndexingFeatures), which form the foundation for modern bindless resource management:

  • Update-After-Bind: Descriptors can be updated after command buffers are recorded or while being bound, eliminating frequent pipeline stalls.
  • Partially Bound Descriptors: Shaders can access arrays of resources where not all array elements refer to valid resources, provided unused slots are not accessed.
  • Runtime Descriptor Arrays: Shaders can declare descriptor arrays without specifying an array size at compile time.
  • Non-Uniform Indexing: Allows dynamic array indexing inside shader invocations where different invocations in a draw call access different elements.

2. Dynamic Rendering

Vulkan Roadmap 2022 mandates dynamic rendering (VK_KHR_dynamic_rendering). This feature simplifies rendering loop architectures by:

  • Removing the requirement to instantiate VkRenderPass and VkFramebuffer objects.
  • Permitting color, depth, and stencil attachments to be specified dynamically at draw time using vkCmdBeginRendering.
  • Significantly reducing the boilerplate code needed to configure render targets.

3. Buffer Device Address

The profile mandates 64-bit native GPU memory pointers via the buffer device address feature (bufferDeviceAddress). This enables:

  • Passing memory pointers directly to shaders without using traditional binding models.
  • Building complex, pointer-based data structures such as trees, linked lists, and bounding volume hierarchies (BVHs) directly on the GPU.
  • Unlocking low-overhead GPU-driven rendering techniques.

4. Extended Dynamic State

To mitigate pipeline compilation overhead and reduce the combinatorial explosion of pipeline state objects (PSOs), the profile requires:

  • Extended Dynamic State (VK_EXT_extended_dynamic_state): Dynamic control over culling mode, front-face orientation, primitive topology, depth test, depth write, and stencil test configurations.
  • Extended Dynamic State 2 (VK_EXT_extended_dynamic_state2): Dynamic control over depth bias, primitive restart, and rasterizer discard enable states.

5. Comprehensive Subgroup Operations

Hardware must support extensive subgroup (wavefront/warp) functionality across compute, fragment, and other shader stages:

  • Required Operation Types: Full support for basic, vote, arithmetic, ballot, shuffle, shuffle relative, and quad subgroup operations.
  • Subgroup Size Control: Developers gain control over the preferred wave size and the ability to require specific compute subgroup sizes.
  • Subgroup Extended Types: Support for 8-bit and 16-bit integer and floating-point types within subgroup operations.

6. Shader Precision and Layout Enhancements

  • Scalar Block Layout (scalarBlockLayout): Relaxes alignment rules, allowing standard C-style scalar memory packing in storage and uniform buffers instead of strict std140 or std430 alignments.
  • Smaller Numeric Types: Hardware must support 16-bit floating-point and integer types in storage buffers, uniform buffers, and push constants, optimizing memory bandwidth and register pressure.
  • Separate Stencil Masks: Independent read and write masks for stencil attachments are mandatory to support advanced masking workflows.
