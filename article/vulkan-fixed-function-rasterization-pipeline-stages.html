Vulkan Fixed-Function Rasterization Pipeline Stages

In the Vulkan API, the graphics pipeline combines programmable shader stages with non-programmable, hardware-driven processes known as fixed-function stages. While programmable shaders execute custom user code for vertices and fragments, fixed-function stages handle the structured tasks of fetching geometry, organizing primitives, converting vectors into discrete pixels, testing depth, and blending final colors. This article breaks down each fixed-function stage that drives the rasterization pipeline in Vulkan.

Input Assembly

The Input Assembly (IA) stage is the entry point of the graphics pipeline. It collects raw vertex data from vertex and index buffers specified by the application. Using the topology settings configured in VkPipelineInputAssemblyStateCreateInfo, the Input Assembly organizes these individual vertices into cohesive geometric primitives, such as point lists, line strips, or triangle lists. Primitive restart functionality is also evaluated here, allowing indexed strips to be broken and restarted efficiently.

Tessellation Primitive Generation

When tessellation shaders are enabled, a fixed-function primitive generator operates between the Tessellation Control Shader (TCS) and Tessellation Evaluation Shader (TES). It takes the tessellation levels calculated by the TCS and subdivides a geometric patch into a fine mesh of points, triangles, or quads, generating domain coordinates that are then passed to the TES.

Viewport Transformation and Clipping

Before primitives reach the rasterizer, they pass through clipping, perspective division, and viewport transformation configured via VkPipelineViewportStateCreateInfo.

  • Perspective Division: Converts homogeneous clip coordinates into normalized device coordinates (NDC) by dividing by the \(w\) component.
  • Clipping: Primitives are clipped against the view frustum boundaries and any user-defined clipping planes. Geometry outside these bounds is discarded, and geometry spanning the edges is clipped to form new primitives.
  • Viewport and Scissor: NDC coordinates are mapped to pixel coordinates defined by the viewport rectangle and depth range. The scissor test then eliminates any primitives or parts of primitives outside a specified rectangular region.

The Rasterization Core

The central rasterization stage transforms continuous geometric primitives into discrete, two-dimensional fragments for screen rendering. Managed through VkPipelineRasterizationStateCreateInfo, it carries out several specific hardware operations:

  • Face Culling: Discards primitives based on whether they face toward or away from the camera (front-facing or back-facing), determined by vertex winding order (clockwise or counter-clockwise).
  • Polygon Mode: Determines whether triangles are rendered as solid surfaces, wireframe outlines, or individual vertex points.
  • Depth Bias: Offsets depth values to resolve rendering artifacts, such as shadow-map acne or z-fighting.
  • Fragment Generation: Evaluates which pixel grid locations are covered by the primitive, interpolating vertex attributes across the primitive surface to create per-fragment input data.

Multisampling

When Multisampling Anti-Aliasing (MSAA) is enabled through VkPipelineMultisampleStateCreateInfo, coverage is computed per-sample rather than strictly per-pixel. This stage determines sample coverage masks, handles alpha-to-coverage conversions, and manages sample shading rates to smooth geometry edges before fragment shading and final composition.

Depth and Stencil Testing

Fragment depth and stencil tests compare fragment values against data in the attached depth and stencil buffers, governed by VkPipelineDepthStencilStateCreateInfo.

  • Early Fragment Tests: If permitted by shader attributes and state flags, depth and stencil tests run before the fragment shader executes, discarding occluded fragments early to save execution overhead.
  • Late Fragment Tests: If fragment shaders modify the depth value or discard pixels dynamically, testing occurs after fragment shading. If the fragment passes, the depth and stencil buffers are updated according to the pipeline's configured operations.

Color Blending

The final fixed-function stage is Color Blending, configured by VkPipelineColorBlendStateCreateInfo. It takes the output color from the fragment shader and determines how it should be written to the render target attachments.

  • Blending Operations: Computes linear combinations of the incoming source color and the destination color already stored in the framebuffer, supporting standard alpha blending, additive blending, or custom factors.
  • Logic Operations: Bypasses standard arithmetic blending to apply bitwise operations (such as XOR or AND) between source and destination values.
  • Color Write Masking: Restricts which individual color channels (Red, Green, Blue, Alpha) are permitted to write to the underlying attachment.
