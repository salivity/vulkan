Arm Mobile Studio: Vulkan Power and Bandwidth Guide

Arm Mobile Studio provides game and application developers with a suite of profiling tools to identify hardware bottlenecks, optimize energy efficiency, and manage system resources on Arm-powered mobile devices. This article explains how Arm Mobile Studio evaluates power consumption and memory bandwidth for workloads running on the Vulkan graphics and compute API, detailing the core tools, hardware performance counters, and techniques used to diagnose performance issues.

Profiling Architecture with Streamline

The primary tool for evaluating power and bandwidth in Arm Mobile Studio is Streamline Performance Analyzer. Streamline captures system-wide performance data simultaneously across the application processor (CPU), Arm Mali GPU, and system memory buses.

To profile a Vulkan application, Streamline relies on a target daemon running on the mobile device (gatord). This daemon samples hardware performance counters at regular intervals while your Vulkan application executes, mapping GPU and system activity directly alongside the CPU thread timeline.

Evaluating Memory Bandwidth

Memory bandwidth is often the most critical performance and thermal constraint on mobile devices. Heavy external memory access (DRAM) generates significant heat and drains battery faster than on-chip computation. Arm Mobile Studio evaluates Vulkan memory bandwidth using specific Mali GPU hardware counters:

  • External Read and Write Bytes: Streamline records the exact volume of data transferred between the Mali GPU and external DRAM, reported in bytes per second (or gigabytes per second). High read/write rates indicate that the Vulkan pipeline is not caching data efficiently.
  • Internal Cache Utilization: Counters track L2 cache hit and miss rates, internal bus requests, and texture cache fetches. High miss rates in Vulkan descriptor sets or textures lead directly to high external bandwidth usage.
  • Vulkan Render Pass Verification: In Vulkan, developers must explicitly define load and store operations (VK_ATTACHMENT_LOAD_OP_* and VK_ATTACHMENT_STORE_OP_*). Arm Mobile Studio verifies whether transient attachments (such as depth and stencil buffers) are correctly kept in fast on-chip tile memory or erroneously written out to DRAM, exposing unnecessary bandwidth consumption.

Evaluating Power Consumption and Thermals

Direct power measurement on commercial mobile devices can be challenging because many lack per-component physical current sensors. Arm Mobile Studio approaches power evaluation through a combination of physical hardware sensors and performance counter correlation:

  • Hardware Energy Meters: If the profiling target contains standard Linux power supply interfaces or hardware energy meters (such as on developer reference boards or rooted devices), Streamline reads these nodes to report instantaneous power draw in milliwatts (mW) or current draw in milliamps (mA).
  • Thermal Throttling Tracking: Streamline tracks device dynamic voltage and frequency scaling (DVFS) and temperature sensors. When a Vulkan workload demands too much power, the operating system throttles GPU and CPU clock frequencies. Arm Mobile Studio visualizes frequency drops against frame rate degradation to pinpoint when thermal limits are breached.
  • Activity-Based Energy Estimation: By analyzing execution engine counters—such as arithmetic logic unit (ALU) utilization, rasterization cycles, and fragment shader thread execution—developers can identify compute-heavy Vulkan pipelines that consume high energy, even in the absence of dedicated physical power probes.

API-Level Diagnostics with Graphics Analyzer and Performance Advisor

Arm Mobile Studio links system-level metrics back to specific Vulkan API calls using Graphics Analyzer and Performance Advisor:

  • Graphics Analyzer: Intercepts the Vulkan API stream to identify draw calls, pipeline barriers, and memory allocation flags. It highlights improper image usage, uncompressed textures (lack of ASTC), and suboptimal buffer mappings that cause bandwidth spikes.
  • Performance Advisor: Automatically processes Streamline captures and generates high-level optimization reports. It correlates frame budget targets with bandwidth budgets, alerting developers when a specific Vulkan frame exceeds the recommended external memory bandwidth budget (typically around 1 to 2 GB/s depending on the device class).
