How to Enumerate Physical Devices in Vulkan

Before a Vulkan application can execute rendering commands or compute workloads, it must identify and select the physical graphics hardware available on the host system. This article explains the standard process for enumerating physical devices in Vulkan, covering the required initialization of an instance, the two-step querying mechanism via vkEnumeratePhysicalDevices, and the evaluation of device properties and capabilities to select the optimal GPU for your application.

1. Initialize the Vulkan Instance

Enumeration cannot take place without a valid VkInstance. The instance represents the connection between your application and the Vulkan runtime. You must create the instance using vkCreateInstance, enabling any necessary global extensions or validation layers. Once created, the resulting VkInstance handle is passed to the device enumeration functions.

2. Query the Number of Available Devices

Vulkan uses a two-call pattern to query dynamic arrays. In the first call, you determine how many physical devices support Vulkan on the machine by passing a null pointer for the array parameter:

uint32_t deviceCount = 0;
VkResult result = vkEnumeratePhysicalDevices(instance, &deviceCount, NULL);

if (result != VK_SUCCESS || deviceCount == 0) {
    // Handle error: No Vulkan-compatible GPUs found
}

If deviceCount returns 0, the system lacks hardware or drivers with Vulkan support, and the application cannot proceed with hardware acceleration.

3. Retrieve the Physical Device Handles

Once the device count is known, allocate an array or vector large enough to hold the handles (VkPhysicalDevice). You then execute the second call to populate the buffer:

VkPhysicalDevice* devices = malloc(sizeof(VkPhysicalDevice) * deviceCount);
vkEnumeratePhysicalDevices(instance, &deviceCount, devices);

Each element in the devices array is a VkPhysicalDevice handle representing a distinct hardware entity, such as a discrete GPU, an integrated graphics processor, or a software rasterizer.

4. Evaluate Device Suitability

Having a list of physical devices is rarely enough; most applications must query each handle to find one that meets specific requirements. Three primary functions provide this information:

  • vkGetPhysicalDeviceProperties: Returns a VkPhysicalDeviceProperties struct containing general device metadata, such as the device name, vendor ID, API version, driver version, and device type (e.g., VK_PHYSICAL_DEVICE_TYPE_DISCRETE_GPU vs. VK_PHYSICAL_DEVICE_TYPE_INTEGRATED_GPU).
  • vkGetPhysicalDeviceFeatures: Returns a VkPhysicalDeviceFeatures struct indicating support for optional hardware features, such as tessellation shaders, multi-viewport rendering, or wide lines.
  • vkGetPhysicalDeviceQueueFamilyProperties: Retrieves the queue families supported by the device. An application must confirm that a device provides queue families with specific flags, such as VK_QUEUE_GRAPHICS_BIT for rendering or VK_QUEUE_COMPUTE_BIT for compute tasks.

5. Select the Device

Iterate through the retrieved VkPhysicalDevice handles, score or filter them against your criteria (for example, favoring discrete GPUs that support required features and surface presentation), and store the chosen handle. The selected VkPhysicalDevice is subsequently used to create a logical device (VkDevice), which serves as the primary interface for actual resource allocation and execution.
