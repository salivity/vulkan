Vulkan Video Session Parameters Object Structure

This article provides an architectural overview of the VkVideoSessionParametersKHR object within the Vulkan Video API framework. It covers the object's core purpose in hardware-accelerated video decode and encode workflows, examines the creation and update structures that define it, and explains how codec-specific sequence and picture parameters are integrated into its architecture.

The Role of VkVideoSessionParametersKHR

In the Vulkan Video extensions (VK_KHR_video_queue, along with decode and encode sub-extensions), a video session parameters object (VkVideoSessionParametersKHR) stores codec-level metadata that changes infrequently during a video stream. It abstracts parameters such as Sequence Parameter Sets (SPS), Picture Parameter Sets (PPS), and Video Parameter Sets (VPS) for standards like H.264, H.265, and AV1. Decoupling this metadata from per-frame execution pipelines reduces overhead by avoiding continuous validation and reloading of parsing state during processing commands.

The Creation Structure: VkVideoSessionParametersCreateInfoKHR

A video session parameters object is instantiated by passing a pointer to a VkVideoSessionParametersCreateInfoKHR structure to the vkCreateVideoSessionParametersKHR function. The primary fields defining this structure include:

  • sType: Must be set to VK_STRUCTURE_TYPE_VIDEO_SESSION_PARAMETERS_CREATE_INFO_KHR.
  • pNext: A pointer to an extension-specific structure carrying initial parameter data (such as SPS and PPS headers) tailored to the active codec profile.
  • flags: A bitmask reserved for future use; currently required to be 0.
  • videoSessionParametersTemplate: An optional handle to an existing VkVideoSessionParametersKHR object. If supplied, the newly created object inherits the baseline parameters stored within the template.
  • videoSession: The parent VkVideoSessionKHR handle. The parameter object is strictly bound to this session and must adhere to its profile, resolutions, and codec configurations.

Codec-Specific Payload Chains

Because sequence configurations vary fundamentally by format, the generic creation structure relies on codec-specific structures linked via the pNext chain to define the underlying payload. Examples include:

  • H.264 Decoding/Encoding: Structures such as VkVideoDecodeH264SessionParametersCreateInfoKHR provide arrays of StdVideoH264SequenceParameterSet and StdVideoH264PictureParameterSet data derived from standard Vulkan Video header definitions (vk_video).
  • H.265 (HEVC): Structures such as VkVideoDecodeH265SessionParametersCreateInfoKHR extend the chain to pass VPS, SPS, and PPS data arrays.
  • AV1: Dedicated structures carry sequence-header-level control information tailored to AV1 bitstream profiles.

These payloads contain data such as aspect ratios, bit depth, chroma format configurations, scaling lists, and reference picture list parameters.

Updating Session Parameters

When a video stream encounters parameter changes (such as an in-band parameter set change mid-stream), the parameter object does not need to be destroyed and recreated. Instead, updates are applied in-place using vkUpdateVideoSessionParametersKHR, which accepts a VkVideoSessionParametersUpdateInfoKHR structure:

  • sType: Set to VK_STRUCTURE_TYPE_VIDEO_SESSION_PARAMETERS_UPDATE_INFO_KHR.
  • pNext: Codec-specific add/update structures (e.g., VkVideoDecodeH264SessionParametersAddInfoKHR) containing the new parameter set data.
  • updateSequenceCount: A monotonically increasing integer managed by the application to track updates and ensure synchronization.

Execution Context

The resulting VkVideoSessionParametersKHR handle is bound to command buffers alongside the parent VkVideoSessionKHR via vkCmdBeginVideoCodingKHR. During execution, video decoding or encoding operations reference the active parameter sets directly through picture-level metadata structures that reference specific SPS and PPS identifiers stored inside the parameter object.
