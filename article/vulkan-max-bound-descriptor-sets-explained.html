Vulkan Max Bound Descriptor Sets Explained

This article examines the maximum number of descriptor sets that can be bound simultaneously in the Vulkan graphics and compute API. It covers the core specification's minimum hardware requirements, the real-world limits found across desktop and mobile GPUs, and standard architectural practices for structuring descriptor set layouts within these constraints.

The Core Specification Limit

In Vulkan, the maximum number of descriptor sets that can be bound concurrently to a pipeline is governed by the maxBoundDescriptorSets property within the VkPhysicalDeviceLimits structure.

According to the official Vulkan specification, the guaranteed minimum for maxBoundDescriptorSets across all conformant implementations is 4. Any fully compliant Vulkan driver, regardless of platform, must allow an application to bind at least four sets simultaneously (indices 0 through 3) via vkCmdBindDescriptorSets.

Typical Hardware Capabilities

While 4 is the universal baseline, modern graphics hardware often supports more:

  • Desktop GPUs (NVIDIA, AMD, Intel): Modern desktop hardware typically supports between 8 and 32 simultaneously bound descriptor sets. For example, modern NVIDIA architectures typically expose a limit of 32, while many AMD architectures support 8 or 32 depending on the driver and hardware generation.
  • Mobile GPUs (ARM Mali, Qualcomm Adreno, Apple via MoltenVK): Mobile implementations are generally more constrained. While many newer mobile chips support 8 sets, older or low-power hardware strictly enforces the specification minimum of 4.

Developers targeting a broad range of platforms must query vkGetPhysicalDeviceProperties at runtime to inspect limits.maxBoundDescriptorSets before attempting to allocate or bind more than four sets.

Why the Baseline Is Set to Four

The minimum limit of 4 directly reflects common rendering architectures. Organizing descriptor sets by update frequency allows developers to minimize binding overhead. The standard convention partitions data into four distinct tiers:

  1. Set 0 (Per-Frame): Global data that changes once per frame, such as view and projection matrices, ambient lighting, or directional light data.
  2. Set 1 (Per-Pass): Data specific to a render pass or post-processing phase, such as depth maps, shadow cascades, or G-buffer samplers.
  3. Set 2 (Per-Material): Material-specific resources, such as albedo, normal, and roughness textures shared across multiple objects.
  4. Set 3 (Per-Object / Per-Draw): Data unique to a specific instance or draw call, such as local transformation matrices, bone data, or dynamic offsets.

By designing pipelines around this four-set hierarchy, applications achieve high performance through minimal state churn while maintaining full compatibility across all Vulkan-compliant hardware.
