VK_EXT_depth_clip_control: OpenGL Depth in Vulkan

This article explains how the VK_EXT_depth_clip_control extension enables developers to use OpenGL-style depth clipping conventions natively within Vulkan. By addressing the fundamental architectural difference between Vulkan's standard \([0, 1]\) depth range and OpenGL's \([-1, 1]\) range, this extension simplifies graphics porting, optimizes translation layers like Zink and Wine, and eliminates the runtime performance and precision penalties associated with manual coordinate conversions in shaders.

The Coordinate Space Discrepancy

A fundamental difference between OpenGL and Vulkan lies in how Normalized Device Coordinates (NDC) represent depth.

  • OpenGL uses a clip-space volume where depth ranges from \(-w_c \le z_c \le w_c\), resulting in an NDC depth range of \([-1, 1]\).
  • Vulkan natively uses a clip-space volume where depth ranges from \(0 \le z_c \le w_c\), resulting in an NDC depth range of \([0, 1]\).

When porting an OpenGL codebase to Vulkan or running OpenGL applications over translation layers, this divergence presents a significant obstacle. Geometry that relies on the \([-1, 1]\) convention will clip incorrectly against Vulkan's near plane (\(z = 0\)), causing primitives situated between \(-w_c\) and \(0\) to be discarded during the primitive clipping stage before reaching the viewport transformation.

Historical Workarounds and Limitations

Before dedicated extension support, developers handling OpenGL workloads on Vulkan had to mitigate this discrepancy through workarounds:

  1. Shader Modification: Compilers or translation layers modified vertex shaders to remap \(z\) coordinates dynamically, using transformations such as \(z_{vulkan} = \frac{z_{opengl} + w}{2}\). This incurred additional arithmetic instructions in vertex processing.
  2. Matrix Manipulation: Projection matrices were adjusted to project directly into \([0, 1]\). While viable for modern engines with full source access, this approach frequently caused precision loss near the near plane and was difficult to apply automatically to legacy fixed-function or precompiled OpenGL shaders.
  3. Disabling Clipping: Developers occasionally disabled depth clipping entirely using depth clamping. However, clamping causes primitives behind the camera or beyond the far plane to be rasterized and projected incorrectly onto the screen boundaries, requiring manual discard handling in fragment shaders.

How VK_EXT_depth_clip_control Works

The VK_EXT_depth_clip_control extension resolves this issue at the hardware pipeline level. It introduces configuration settings directly to the viewport state of the graphics pipeline, instructing the rasterizer's primitive clipping stage to evaluate depth bounds using OpenGL rules.

The extension introduces a new structure: VkPipelineViewportDepthClipControlCreateInfoEXT. This structure can be appended to the pNext chain of VkPipelineViewportStateCreateInfo during pipeline creation:

  • negativeOneToOne: A boolean member within VkPipelineViewportDepthClipControlCreateInfoEXT. Setting this flag to VK_TRUE changes the clipping volume condition to \(-w_c \le z_c \le w_c\).

When enabled, hardware clip testing allows vertices with negative \(z_c\) values down to \(-w_c\) to survive clipping. The subsequent viewport transformation then scales the \([-1, 1]\) range into the configured minDepth and maxDepth of the viewport (which typically map to the \([0, 1]\) range of the Vulkan depth buffer).

Practical Benefits

By adjusting the clipping volume to match OpenGL conventions directly on the hardware:

  • Zero Shader Overhead: Shaders can output standard OpenGL clip space coordinates without needing patching, matrix alterations, or injected arithmetic.
  • Preserved Numerical Precision: Eliminating manual range remapping in vertex shaders avoids floating-point roundoff errors and maintains depth buffer precision.
  • Streamlined Layer Emulation: Emulation frameworks and API translators achieve near-native performance and strict behavioral compliance with legacy OpenGL applications.
