Vulkan Memory Budget Management Algorithms

Managing device memory in Vulkan requires applications to explicitly handle allocation, tracking, and reclamation without automatic driver-level safety nets. Because exceeding physical memory constraints leads to fatal VK_ERROR_OUT_OF_DEVICE_MEMORY crashes, modern engines rely on structured memory budgeting algorithms to ensure stability. This article outlines the optimal algorithms and structural approaches used to monitor resource usage, sub-allocate large memory blocks, dynamically evict lower-priority assets, and handle memory fragmentation under tight budget constraints.

The Foundation: Dynamic Budget Querying

Before applying management algorithms, an application must determine available system headroom. Operating systems dynamically reassign GPU memory across multiple processes, meaning static allocations are prone to failure.

Vulkan provides the VK_EXT_memory_budget extension, which exposes real-time information through VkPhysicalDeviceMemoryBudgetPropertiesEXT. By polling heapBudget and heapUsage values periodically, an engine gains the real-time ground truth of its allocation boundaries. Optimal memory managers use this query to continuously update a global safety envelope, adapting algorithms dynamically based on current memory pressure.

Two-Level Segregated Fit (TLSF) for Sub-Allocation

Vulkan caps the total number of live allocations through the physical device limit maxMemoryAllocationCount (often restricted to a few thousand). Direct OS-level allocations via vkAllocateMemory per individual resource will quickly cause out-of-memory errors regardless of remaining bytes.

The optimal solution is to allocate large blocks (typically 64 MiB to 256 MiB) and manage internal allocations via the Two-Level Segregated Fit (TLSF) algorithm:

  • Bounded Latency: TLSF executes in \(O(1)\) time complexity for both allocation and deallocation, making it ideal for rendering loops.
  • Low Fragmentation: It segregates free memory blocks into classes using a two-tier array system (powers-of-two coarse lists with linear sub-divisions), minimizing internal fragmentation.
  • Buddy Allocation Alternative: While buddy allocators provide simpler coalescence, TLSF consistently demonstrates lower internal fragmentation when managing varied resource sizes such as non-power-of-two textures, transient buffers, and acceleration structures.

Dual-Watermark (Threshold) Throttling

A dual-watermark algorithm prevents sudden memory spikes from triggering hard crashes by staging engine reactions across two defined usage thresholds:

  1. Soft Limit (typically 75–85% of heap budget): Crossing this mark triggers asynchronous shedding of non-essential resources. The engine stops speculative prefetching, downgrades texture Streaming Mipmap levels, and signals background loading queues to halt new allocations.
  2. Hard Limit (typically 90–95% of heap budget): Crossing this threshold enforces synchronous throttling. The engine flushes garbage collection queues, cancels in-flight staging transfers, unloads cached procedural data, and forces lowest-fidelity fallbacks for dynamic geometry and particle systems.
  3. Emergency Fallback: Any allocation that cannot fit in VK_MEMORY_PROPERTY_DEVICE_LOCAL_BIT shifts to VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT (system RAM) if supported by the memory type architecture, trading bus bandwidth for system stability.

Priority-Based Least Recently Used (LRU) Eviction

When memory reaches capacity, active resources must be evicted or downsized. An optimal eviction architecture relies on a multi-queue Priority-Based LRU (Least Recently Used) algorithm:

  • Categorization: Resources are assigned static priority buckets (e.g., Critical/Render Targets, High/Active Geometry, Medium/Secondary Textures, Low/Audio or Cache).
  • Execution: Each bucket contains a double-linked list ordered by last-accessed frame index. When memory pressure requires eviction, the algorithm iterates from the lowest-priority queue upward, scanning from the tail (oldest item).
  • Vulkan Paging Extensions: Modern implementations can leverage VK_EXT_pageable_device_local_memory. This extension standardizes interaction with operating system memory managers (such as Windows D3D12/WDDM or Linux drivers), allowing the application to explicitly define priority via vkSetDeviceMemoryPriorityEXT so the OS driver pages out appropriate allocations cleanly without crashing.

Incremental Compaction and Defragmentation

Over time, interleaved allocation and destruction of resources causes external fragmentation, leaving memory chunks that are large enough in aggregate but too scattered to satisfy an allocation.

An optimal defragmentation strategy uses an incremental, non-blocking compaction algorithm:

  • Scoring: Sub-allocation blocks are scored by fragmentation level (ratio of free memory to the largest contiguous free chunk).
  • Targeted Migration: The most fragmented blocks are marked for compaction. The engine creates a new target block and schedules asynchronous copy commands (vkCmdCopyBuffer, vkCmdCopyImage) over multiple frames.
  • Handle Redirection: Internal references are updated to point to the new offsets, and old memory blocks are released back to the driver. By spreading copy commands across multiple frames, the application prevents pipeline bubbles while consistently regaining contiguous memory headroom.
