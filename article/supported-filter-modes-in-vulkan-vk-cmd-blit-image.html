Supported Filter Modes in Vulkan vkCmdBlitImage

When transferring and scaling pixel data between images in Vulkan using the vkCmdBlitImage command, developers must specify a VkFilter mode to control how texels are sampled and interpolated during scaling. This article details the filter modes supported by vkCmdBlitImage, the differences in how they sample data, and the hardware capability checks required to use them properly.

Supported Filter Modes

The vkCmdBlitImage function accepts a VkFilter parameter that dictates the reconstruction filter applied when the source and destination regions differ in size. Vulkan supports the following filter modes:

  • VK_FILTER_NEAREST: Selects the single texel closest to the integer coordinates of the source region. This mode does not perform interpolation, resulting in sharp, pixelated edges when scaling up, but it is computationally inexpensive and widely compatible across all formats that support blitting.
  • VK_FILTER_LINEAR: Computes a weighted average of the texels surrounding the sample point using linear interpolation (bilinear for 2D images, trilinear for 3D images). This produces smoother transitions when scaling, making it ideal for standard color image resampling.
  • VK_FILTER_CUBIC_EXT (or VK_FILTER_CUBIC_IMG): Implements higher-order bicubic filtering over an expanded neighborhood of texels. This mode offers superior edge preservation and sharpness compared to linear filtering. It is introduced via extensions such as VK_EXT_filter_cubic and is not part of the baseline core specification.

Format and Feature Requirements

Not all filter modes can be used with every image format or hardware configuration. Before issuing a blit command, the application must query device capabilities using vkGetPhysicalDeviceFormatProperties:

  1. Blit Support: The source format must include VK_FORMAT_FEATURE_BLIT_SRC_BIT, and the destination format must include VK_FORMAT_FEATURE_BLIT_DST_BIT in their format feature flags.
  2. Linear Filtering: To use VK_FILTER_LINEAR, the source image format must also support linear filtering, verified by the presence of VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT.
  3. Cubic Filtering: Using VK_FILTER_CUBIC_EXT requires device extension support and the format feature flag VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_CUBIC_BIT_EXT on the source image format.

Format Restrictions

Vulkan enforces strict limitations on filter modes based on the underlying format type:

  • Integer Formats: If the source format contains unsigned or signed integer components (such as VK_FORMAT_R8G8B8A8_UINT or VK_FORMAT_R32G32_SINT), the filter mode must be set to VK_FILTER_NEAREST. Linear or cubic filtering on integer formats is invalid.
  • Depth/Stencil Formats: Blits involving depth and stencil aspects are generally restricted to VK_FILTER_NEAREST, depending on implementation-specific support, because interpolating non-color data often results in invalid depth or stencil references.
