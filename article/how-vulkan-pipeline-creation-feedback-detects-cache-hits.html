How Vulkan Pipeline Creation Feedback Detects Cache Hits

The VK_EXT_pipeline_creation_feedback extension (promoted to core in Vulkan 1.3) allows developers to determine whether a pipeline or its individual shader stages were compiled from source or retrieved from a cache. By attaching dedicated feedback structures to the pipeline creation chain, the driver writes back execution metrics and bit flags immediately upon pipeline creation. This article explains how the extension interfaces with pipeline compilation, the specific data structures and flags involved, and how to interpret the results to detect cache hits versus full shader compilation.

The Feedback Mechanism

When creating graphics or compute pipelines via vkCreateGraphicsPipelines or vkCreateComputePipelines, the driver performs heavy compilation tasks unless pre-compiled binaries are already available. The VK_EXT_pipeline_creation_feedback extension exposes these internal compilation events to the application.

To request feedback, you chain a VkPipelineCreationFeedbackCreateInfoEXT structure into the pNext chain of VkGraphicsPipelineCreateInfo, VkComputePipelineCreateInfo, or VkRayTracingPipelineCreateInfoKHR.

This structure accepts pointers to receive two tiers of feedback:

  1. Pipeline Feedback: A pointer to a single VkPipelineCreationFeedbackEXT structure that provides aggregate feedback for the overall pipeline.
  2. Stage Feedback: A pointer to an array of VkPipelineCreationFeedbackEXT structures corresponding to each individual shader stage passed in the pStages array.

Structure of VkPipelineCreationFeedbackEXT

After the pipeline creation function returns, the driver populates each provided VkPipelineCreationFeedbackEXT struct, which contains two main fields:

  • flags: A bitmask of VkPipelineCreationFeedbackFlagBitsEXT indicating the origin of the compiled data.
  • duration: A 64-bit integer representing the duration (in nanoseconds) that the driver spent creating the pipeline or stage.

Identifying Cache Hits vs. Compilation

The determination of whether a shader was compiled from source or loaded from a cache is made by inspecting the bits in the flags field:

  • VK_PIPELINE_CREATION_FEEDBACK_VALID_BIT_EXT: Indicates that the feedback data was populated by the driver. If this bit is not set, the driver was unable to provide feedback, and the remaining bits and duration should be ignored.

  • VK_PIPELINE_CREATION_FEEDBACK_APPLICATION_PIPELINE_CACHE_HIT_BIT_EXT: When this flag is present, the pipeline or specific shader stage was retrieved directly from the VkPipelineCache object provided by the application during the creation call. No source compilation occurred for the matching stage.

  • VK_PIPELINE_CREATION_FEEDBACK_BASE_PIPELINE_ACCELERATION_BIT_EXT: Indicates that compilation was accelerated by reusing state from a basePipelineHandle or basePipelineIndex.

Interpreting Driver-Level Caches and Source Compilations

If VK_PIPELINE_CREATION_FEEDBACK_VALID_BIT_EXT is set, but VK_PIPELINE_CREATION_FEEDBACK_APPLICATION_PIPELINE_CACHE_HIT_BIT_EXT is not set, one of two scenarios occurred:

  1. Full Compilation from Source: The driver had to translate the SPIR-V bytecode into native GPU machine code from scratch. This state is typically accompanied by a significantly higher duration value.
  2. Internal Driver Cache Hit: Many GPU drivers maintain internal, on-disk shader caches outside of the Vulkan VkPipelineCache construct. While this is not an application pipeline cache hit (and will not set the application cache hit bit), it can be identified by an unusually low duration compared to a cold compile, despite the cache hit flag being absent.

Per-Stage vs. Whole-Pipeline Granularity

Evaluating both the pipeline-level and stage-level feedback allows for granular tracking:

  • The pipeline-level feedback flags denote whether the overall pipeline assembly hit the cache.
  • The stage-level feedback flags identify precisely which stages (e.g., vertex, fragment) were reused and which ones required a new compilation pass. This is common when modifying a single shader in a multi-stage pipeline where other stages remain unchanged.
