Vulkan Depth Clip Control and Unclamped Depth Ranges

This article explores how Vulkan handles depth ranges without clamping by using the depth clip control mechanism. By default, Vulkan ties depth clipping directly to the frustum and viewport parameters, which can constrain depth manipulation or introduce unintended clamping artifacts. Through extensions such as VK_EXT_depth_clip_control and VK_EXT_depth_clip_enable, developers can alter the clipping space, decouple depth clipping from depth clamping, and preserve unclamped floating-point depth values across the pipeline.

The Standard Vulkan Depth Pipeline

In standard Vulkan execution, the depth coordinate \(z_c\) in clip space must fall within the range \(0 \le z_c \le w_c\). Primitives outside this volume are clipped prior to rasterization unless depth clamping is enabled via VkPipelineRasterizationStateCreateInfo::depthClampEnable.

However, enabling depthClampEnable causes fragments that would otherwise fall outside the near and far planes to be clamped to the viewport's minDepth and maxDepth bounds (typically \([0.0, 1.0]\)). While useful for shadow volume construction or certain stencil operations, this default behavior makes it impossible to preserve fragments with true, unclamped depth values outside the conventional near/far boundaries.

Modifying the Clip Volume with VK_EXT_depth_clip_control

The VK_EXT_depth_clip_control extension alters the fundamental clip-space boundaries before viewport transformation occurs. It introduces VkPipelineViewportDepthClipControlCreateInfoEXT, which can be chained to VkPipelineViewportStateCreateInfo to configure the negativeOneToOne parameter.

When negativeOneToOne is enabled, the depth clip range changes from the default Vulkan volume (\([0, w_c]\)) to the symmetric range:

\[-w_c \le z_c \le w_c\]

This directly manages depth ranges without clamping by expanding the valid mathematical space of the projection matrix. It accommodates pipelines ported from Direct3D or OpenGL without forcing intermediate shader conversions or artificially clamping geometry that relies on a wider mathematical range.

Decoupling Clipping from Clamping

To truly process depth values without clamping, the pipeline must decouple clipping (discarding geometry beyond planes) from clamping (constraining depth values to \([minDepth, maxDepth]\)).

  1. Clip Disable via VK_EXT_depth_clip_enable: While depthClampEnable suppresses clipping, it forces clamping. Enabling VK_EXT_depth_clip_enable allows an application to set depthClipEnable = VK_FALSE independently. Fragments outside the near/far planes are not clipped, yet their actual fragment depth remains unclamped if using an unconstrained depth format.
  2. Floating-Point Depth Buffers: When combined with 32-bit floating-point depth formats (such as VK_FORMAT_D32_SFLOAT), Vulkan can write depth values less than \(0.0\) or greater than \(1.0\) if viewport depth clamping is bypassed. Depth clip control ensures that primitives extending beyond standard boundaries maintain their continuous mathematical values rather than flattening against the near or far limits.

Preventing Depth Distortions in Modern Techniques

Controlling depth clipping without clamping is critical for advanced rendering techniques:

  • Infinite Reverse-Z Projections: Reverse-Z techniques map the near plane to \(1.0\) and an infinite far plane toward \(0.0\). Utilizing depth clip control ensures that precision near infinity is not compromised by premature near-plane clipping or unwanted clamping limits.
  • Cascaded Shadow Maps: Shadow passes frequently process geometry situated behind the light's near plane to prevent holes in cast shadows. Bypassing clipping without forcing fragments into a fixed clamp boundary preserves correct depth testing for self-shadowing geometry.
  • Seamless API Translation: Graphics translation layers (such as DXVK and vkd3d) require identical depth behavior to Direct3D, which natively supports unclamped depth calculations. Depth clip control allows Vulkan to replicate these ranges natively, eliminating precision degradation or costly emulation in shaders.
