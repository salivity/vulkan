Official Vulkan Conformance Requirements for Vendors

Before an independent hardware vendor (IHV) can legally and technically claim official support for the Vulkan graphics and compute API, it must satisfy a rigorous certification process defined by the Khronos Group. To earn the right to use the Vulkan trademark and gain patent protections, the vendor cannot simply implement the API specifications; it must become a Khronos Adopter, achieve a 100% pass rate on the official Conformance Test Suite (CTS), and successfully pass a formal peer-review process conducted by other Khronos members.

1. Execute an Adopter Agreement

To initiate official compliance, a hardware vendor must sign the Vulkan Adopter Agreement or be a contributing Khronos Group member at a tier that includes Vulkan adoption rights. This legal agreement grants the vendor conditional rights to access the conformance review process, license the official Vulkan trademark, and receive the intellectual property protections established under the Khronos IP framework upon successful certification.

2. Implement the API Specification

The vendor must engineer a fully functional driver that implements the Vulkan core specification for its targeted hardware and operating system platforms. The implementation must cover all non-optional Vulkan commands, pipeline stages, memory models, and resource types specified for the targeted API version (such as Vulkan 1.2 or 1.3), along with any advertised hardware extensions.

3. Pass the Vulkan Conformance Test Suite (CTS)

The vendor must execute the complete, open-source Vulkan Conformance Test Suite against its driver and hardware configuration. The CTS evaluates API edge cases, shader execution accuracy, limits, pipeline integrity, and memory safety:

  • Zero Failures: The implementation must achieve a 100% pass rate for the declared specification. Any failure, crash, or non-deterministic behavior prevents certification.
  • Waiver Requests: If an implementation fails a test due to a flaw or ambiguity within the CTS itself rather than the driver, the vendor must document the issue and submit a formal waiver request to the Khronos Vulkan Working Group for approval.

4. Submit Results for Peer Review

Once testing is complete, the IHV compiles a formal submission package containing the full CTS execution logs, exact driver versions, hardware identifiers, operating system build information, and any approved test waivers. This package is uploaded to the private Khronos conformance submission portal.

5. Clear the Review Period

Submitted results undergo a mandatory 30-day review period during which other Khronos Group members can inspect the submission, challenge the methodology, and attempt to reproduce the test results. If an objection or invalid test result is raised, the vendor must resolve the discrepancy by submitting patch evidence, updating the driver, or refiling.

6. Official Trademark Grant and Listing

If no unresolved challenges remain at the conclusion of the 30-day window, the implementation is declared officially conformant. The vendor is officially granted the license to display the Vulkan name and logo on packaging, documentation, and marketing materials, and the hardware and driver pairing is added to the public Khronos Conformant Products registry.
