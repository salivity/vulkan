Guide to Vulkan VK_NV_ray_tracing_motion_blur

The VK_NV_ray_tracing_motion_blur extension introduces hardware-accelerated motion blur to the Vulkan ray tracing pipeline by adding time-dependent traversal capabilities. This article explains the fundamentals of the extension and details how it alters acceleration structure definitions to encode transformation and geometry changes across temporal intervals.

What is the VK_NV_ray_tracing_motion_blur Extension?

Standard hardware ray tracing in Vulkan via VK_KHR_ray_tracing_pipeline evaluates geometry at a single, static point in time. While post-processing motion blur techniques rely on screen-space velocity buffers, they frequently introduce artifacts such as disocclusion errors, ghosting, and incorrect blurring of reflections and shadows.

The VK_NV_ray_tracing_motion_blur extension enables real-time motion blur directly within the ray tracing pipeline. It allows rays to carry a time parameter between \(0.0\) and \(1.0\) (representing the camera shutter interval). The ray tracing hardware then traverses acceleration structures that interpolate positions and transforms over that same interval, ensuring physically accurate reflections, refractions, and silhouettes for fast-moving geometry.

Expanding Acceleration Structures for Motion Blur

To support time-dependent queries, acceleration structures must store temporal data alongside spatial data. The extension expands the standard VK_KHR_acceleration_structure framework primarily through descriptor chains (pNext) and specialized instance representations.

Acceleration Structure Creation Flags

When creating acceleration structures that contain temporal movement, the application must set the VK_ACCELERATION_STRUCTURE_CREATE_MOTION_BIT_NV flag within VkAccelerationStructureCreateInfoKHR::flags.

Additionally, the creation structure’s pNext chain must include the new VkAccelerationStructureMotionInfoNV struct:

typedef struct VkAccelerationStructureMotionInfoNV {
    VkStructureType                                sType;
    const void*                                    pNext;
    uint32_t                                       maxInstances;
    VkAccelerationStructureMotionInfoFlagsNV       flags;
} VkAccelerationStructureMotionInfoNV;

This struct informs the driver that the acceleration structure must allocate additional internal header space to store motion paths and instance motion descriptors instead of standard static instances.

Expanding Top-Level Acceleration Structures (TLAS)

In standard Vulkan ray tracing, a Top-Level Acceleration Structure points to a linear array of VkAccelerationStructureInstanceKHR structs. To accommodate temporal changes, VK_NV_ray_tracing_motion_blur replaces the standard instance definition with VkAccelerationStructureMotionInstanceNV.

Because different objects move differently, this motion instance format is a union capable of defining three distinct behaviors via VkAccelerationStructureMotionInstanceTypeNV:

  1. Static Instances (VK_ACCELERATION_STRUCTURE_MOTION_INSTANCE_TYPE_STATIC_NV): Wraps a standard VkAccelerationStructureInstanceKHR for objects that remain stationary within the frame, ensuring backwards compatibility and memory efficiency within the same TLAS.

  2. Matrix Motion Instances (VK_ACCELERATION_STRUCTURE_MOTION_INSTANCE_TYPE_MATRIX_MOTION_NV): Uses VkAccelerationStructureMatrixMotionInstanceNV to define linear interpolation between two or more 3x4 affine transformation matrices over time. This approach is well-suited for linear translation or simple transformation paths.

  3. SRT Motion Instances (VK_ACCELERATION_STRUCTURE_MOTION_INSTANCE_TYPE_SRT_MOTION_NV): Uses VkAccelerationStructureSRTMotionInstanceNV to separate transformations into Scale, Rotation (as quaternions), and Translation. Direct matrix interpolation often produces shearing and distortion during rotations; decomposing transforms into SRT parameters ensures that rotating objects maintain their volume and shape across the shutter duration.

Expanding Bottom-Level Acceleration Structures (BLAS)

For non-rigid deformations—such as character meshes with skinning animations—motion cannot be expressed purely through TLAS transform matrices. The extension enables geometry-level vertex motion blur within BLAS.

To achieve this, VkAccelerationStructureGeometryTrianglesDataKHR accepts VkAccelerationStructureGeometryMotionTrianglesDataNV in its pNext chain. This introduces an additional vertex data pointer containing the positions of the vertices at the end of the time interval. During traversal, the intersection engine interpolates vertex positions between the baseline buffer and the secondary motion buffer based on the ray's timestamp.

Traversal and Shader Integration

Once the acceleration structure headers and nodes are extended to support motion data, shaders can trace time-aware rays. In SPIR-V, rays are dispatched with an extra floating-point time operand passed into the traversal instruction (such as traceRayExt in GLSL).

During traversal, the ray-tracing core evaluates the instance and geometry headers, calculates the exact interpolated positions corresponding to the ray’s timestamp, and evaluates intersections accordingly. This provides accurate motion-blurred silhouettes, shadows, and secondary bounces directly in hardware.
