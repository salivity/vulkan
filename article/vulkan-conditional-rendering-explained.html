Vulkan Conditional Rendering Explained

Conditional rendering in Vulkan allows applications to dynamically execute or discard draw and dispatch commands directly on the GPU without CPU intervention. By reading a predicate value from a GPU buffer, the hardware decides at execution time whether a set of rendering commands should be processed or completely skipped. This technique eliminates CPU-GPU synchronization stalls, optimizes rendering pipelines, and serves as a fundamental building block for fully GPU-driven rendering architectures.

What is Conditional Rendering?

Standard command submission in Vulkan requires the CPU to record commands into a command buffer, specifying exactly what to draw. In scenarios like occlusion culling, determining whether an object is visible often occurs on the GPU (e.g., via compute shaders or hardware occlusion queries). Without conditional rendering, reading these visibility results requires syncing the GPU data back to the CPU—introducing severe pipeline latency—or rendering anyway and relying on early-Z tests or pixel discard, which still wastes vertex processing and rasterization cycles.

Conditional rendering, provided by the VK_EXT_conditional_rendering extension, bridges this gap. It allows command buffers to include conditional blocks whose execution depends on values stored in a VkBuffer on the GPU.

How the GPU Discards Drawing Commands

Conditional rendering operates through a command-level guard on the GPU's command processor. The core workflow involves the following steps:

  1. Setting the Predicate Buffer: A compute shader, occlusion query copy, or transfer command writes a 32-bit integer value into a designated VkBuffer.
  2. Beginning the Condition: The CPU records vkCmdBeginConditionalRenderingEXT, passing a VkConditionalRenderingBeginInfoEXT structure. This structure references the predicate buffer, an offset, and flags such as VK_CONDITIONAL_RENDERING_INVERTED_BIT_EXT.
  3. Recording Commands: Inside the block, standard commands such as vkCmdDraw, vkCmdDrawIndexed, or vkCmdDispatch are recorded.
  4. Ending the Condition: The CPU records vkCmdEndConditionalRenderingEXT to close the scope.

When the GPU reaches this block during execution, the command processor reads the 32-bit value directly from the specified buffer location:

  • If the value is non-zero (or zero, if the inverted flag is set), the condition passes, and the drawing commands proceed down the graphics pipeline as normal.
  • If the condition fails, the GPU command processor discards the encapsulated commands at the front end.

Because the discard occurs at the command processor level, the GPU skips vertex pulling, vertex shading, geometry processing, rasterization, and pixel shading entirely. Memory bandwidth and compute resources that would have been allocated to the discarded meshes are completely spared.

Key Use Cases and Benefits

  • Occlusion Culling: Bounding boxes can be tested for visibility, and their corresponding high-detail meshes can be drawn conditionally based on the visibility result, keeping the entire culling loop on the GPU.
  • Elimination of Synchronization Stalls: The CPU never needs to wait for the GPU to finish visibility passes to decide what to render in subsequent passes, preventing expensive pipeline bubbles.
  • Static Command Buffers: Command buffers containing complex drawing logic can be recorded once during initialization and conditionally enabled or disabled per frame simply by updating predicate buffer values.
