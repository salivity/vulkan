Querying Compacted AS Size with Vulkan Query Pools

Compacting acceleration structures in Vulkan allows developers to significantly reduce video memory consumption by shrinking bottom-level acceleration structures (BLAS) to their true post-build footprint. Because the final compacted size cannot be calculated statically, applications must query the required memory size from the GPU after the initial build step. This article details the sequential steps to set up, record, and retrieve compacted acceleration structure sizes using Vulkan query pools.

1. Enable Required Extensions and Features

Ensure the instance and device enable the VK_KHR_acceleration_structure extension and its dependencies (VK_KHR_deferred_host_operations). When creating the logical device, enable the accelerationStructure feature in VkPhysicalDeviceAccelerationStructureFeaturesKHR.

2. Create an Acceleration Structure Query Pool

Create a dedicated query pool configured to hold size query results:

  • Populate a VkQueryPoolCreateInfo structure.
  • Set queryType to VK_QUERY_TYPE_ACCELERATION_STRUCTURE_COMPACTED_SIZE_KHR.
  • Set queryCount to the number of acceleration structures you intend to query simultaneously.
  • Call vkCreateQueryPool to allocate the resource.

3. Build the Initial Structure with Compaction Flags

Before querying, the source acceleration structure must be built with compaction support:

  • Set the flags field of VkAccelerationStructureBuildGeometryInfoKHR to include VK_BUILD_ACCELERATION_STRUCTURE_ALLOW_COMPACTION_BIT_KHR.
  • Allocate the initial uncompacted scratch and destination buffers using the sizes from vkGetAccelerationStructureBuildSizesKHR.
  • Record the build command into a command buffer using vkCmdBuildAccelerationStructuresKHR.

4. Insert an Execution and Memory Barrier

The query command cannot read the built structure until the build operations are complete. Insert a pipeline barrier into the command buffer:

  • Source stage: VK_PIPELINE_STAGE_ACCELERATION_STRUCTURE_BUILD_BIT_KHR
  • Destination stage: VK_PIPELINE_STAGE_ACCELERATION_STRUCTURE_BUILD_BIT_KHR
  • Source access mask: VK_ACCESS_ACCELERATION_STRUCTURE_WRITE_BIT_KHR
  • Destination access mask: VK_ACCESS_ACCELERATION_STRUCTURE_READ_BIT_KHR

Call vkCmdPipelineBarrier (or vkCmdPipelineBarrier2) to enforce this synchronization.

5. Reset the Query Pool

Before emitting queries, reset the query pool indices that will be used:

  • Call vkCmdResetQueryPool within the command buffer prior to writing queries, or call vkResetQueryPool on the host if the hostQueryReset feature is supported and enabled.

6. Write Acceleration Structure Properties

Record the query command onto the command buffer:

  • Call vkCmdWriteAccelerationStructuresPropertiesKHR.
  • Pass the target acceleration structure handles in the pAccelerationStructures array.
  • Set queryType to VK_QUERY_TYPE_ACCELERATION_STRUCTURE_COMPACTED_SIZE_KHR.
  • Specify the query pool handle and the firstQuery index.

7. Retrieve the Size Values

Submit the command buffer to the compute or graphics queue. Once the query has completed, extract the result:

  • Host Retrieval: If allocating destination memory via the CPU, wait for the submission fence to signal, then call vkGetQueryPoolResults. Pass a VkDeviceSize array to receive the byte sizes, and set flags such as VK_QUERY_RESULT_64_BIT | VK_QUERY_RESULT_WAIT_BIT.
  • Device Retrieval: If using device-side allocation routines, copy the query values directly to a buffer on the timeline using vkCmdCopyQueryPoolResults.

8. Compact the Structure

Using the queried size, create a new compact buffer and acceleration structure handle, then record vkCmdCopyAccelerationStructureKHR with mode set to VK_COPY_ACCELERATION_STRUCTURE_MODE_COMPACT_KHR to finalize the process.
