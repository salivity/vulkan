Combined vs Separate Samplers in Vulkan Explained

In Vulkan, texture sampling can be handled either by bundling a texture and its sampling state into a combined image sampler or by defining them as distinct, separate objects. Combined image samplers tie a specific image view directly to a sampler within a single descriptor, mimicking legacy graphics pipelines. Conversely, separating sampled images from samplers decouples the underlying pixel data from the filtering state, providing greater flexibility and reducing descriptor consumption. This article breaks down the mechanics, advantages, differences, and performance considerations of both approaches.

What Is a Combined Image Sampler?

A combined image sampler is represented in Vulkan by the descriptor type VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER. It binds a VkImageView (the resource data) and a VkSampler (the sampling parameters, such as address modes, filtering, and mipmapping) together in a single descriptor slot.

In GLSL, this corresponds to the traditional texture lookup syntax:

layout(binding = 0) uniform sampler2D combinedTexture;

void main() {
    vec4 color = texture(combinedTexture, uv);
}

Key Characteristics:

  • One-to-One Pairing: The shader treats the image and the sampler as an indivisible unit.
  • Legacy Portability: Mimics the texture binding model used in OpenGL and DirectX 9/11, making it easier to port legacy codebases.
  • Simplicity: Requires fewer descriptor set bindings in shaders when managing standard asset pipelines where each texture requires only one fixed filtering configuration.

What Are Separate Samplers and Images?

Vulkan allows developers to decouple resources using two distinct descriptor types:

  1. VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE: References the texture data (VkImageView) without any sampling state.
  2. VK_DESCRIPTOR_TYPE_SAMPLER: Defines the filtering rules and addressing modes (VkSampler) without referencing any image data.

In GLSL, these are declared individually and combined dynamically during the texture lookup:

layout(binding = 0) uniform texture2D separateImage;
layout(binding = 1) uniform sampler separateSampler;

void main() {
    vec4 color = texture(sampler2D(separateImage, separateSampler), uv);
}

Key Characteristics:

  • Decoupled Architecture: Follows modern hardware models similar to DirectX 12 and Metal.
  • Combinatorial Reuse: Any sampled image can be paired dynamically with any sampler in the shader.
  • Reduced Descriptor Redundancy: Multiple textures can share a single global sampler.

Key Differences Comparison

Feature Combined Image Sampler Separate Image and Sampler
Descriptor Type VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE & VK_DESCRIPTOR_TYPE_SAMPLER
GLSL Types sampler2D, samplerCube, etc. texture2D, textureCube paired with sampler

Descriptor Count 1 descriptor per image/sampler pair 1 descriptor per image + 1 descriptor per sampler

Architectural Advantages and Trade-offs

1. Descriptor Management and Scaling

When using combined image samplers, sampling 50 textures with 3 different filtering states (e.g., linear, nearest-neighbor, and anisotropic) requires 150 combined image sampler descriptors.

With separate samplers and images, the same setup requires only 50 sampled image descriptors and 3 sampler descriptors (53 descriptors total). This significantly reduces descriptor pool allocation overhead and memory usage.

2. Bindless and Modern Rendering Pipelines

Modern rendering architectures—particularly bindless pipelines—rely heavily on separate images and samplers. Typically, an engine will bind a small, global array of static samplers (such as linear clamp, linear repeat, point clamp) at application startup and index into a large array of texture descriptors dynamically using push constants or material IDs.

3. Hardware Alignment

Modern desktop GPUs (AMD, NVIDIA, Intel) maintain physically distinct hardware tables for texture data and sampler states. Using separate samplers maps directly to the underlying GPU registers and instructions.

However, some mobile and tile-based architectures (such as older Mali or PowerVR designs) internally link texture units with sampling states. On these devices, the driver may synthesize a combined state behind the scenes when separate descriptors are used, though modern drivers handle this with negligible overhead.

Which One Should You Use?

  • Use Combined Image Samplers when porting older OpenGL applications, maintaining simple 1:1 image-to-sampler relationships, or targeting constrained mobile platforms where minimal descriptor binding updates are needed.
  • Use Separate Samplers and Images when building modern, scalable rendering engines, implementing bindless architectures, or requiring dynamic combinations of filtering modes across varied texture assets.
