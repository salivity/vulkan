Requesting an Unsupported Vulkan API Version

When an application requests a Vulkan core API version higher than what an installed driver or loader supports, initialization fails, preventing the application from running on incompatible hardware. Specifically, the Vulkan runtime halts the startup sequence by returning a VK_ERROR_INCOMPATIBLE_DRIVER error code during instance creation. This mechanism safeguards the system against unexpected crashes, invalid memory calls, and undefined behaviors that would occur if an application attempted to invoke core functions and features that the driver cannot execute.

Behavior at Instance Creation

When setting up Vulkan, an application specifies its intended core version using the apiVersion member of the VkApplicationInfo structure passed into vkCreateInstance.

If the application requests a major or minor version (such as Vulkan 1.3) that exceeds the maximum version supported by the system's Vulkan loader or the underlying driver:

  • vkCreateInstance immediately fails.
  • The function returns the VK_ERROR_INCOMPATIBLE_DRIVER error code.
  • No VkInstance handle is created, completely stopping Vulkan operations before any graphics pipelines, resources, or devices can be initialized.

Behavior at Device Creation

Even if the Vulkan instance initializes successfully—for example, if the loader supports the requested version—a specific physical GPU driver on the system might not support that same version.

Physical device capabilities are determined by the driver. If an application requires a core version that a specific VkPhysicalDevice does not support:

  • Version Clamping: Vulkan dictates that the effective version of a logical device is the minimum of the instance version and the physical device’s supported version. An application cannot force a device to run a version higher than its hardware driver allows.
  • Feature and Extension Failures: If an application assumes newer core features are present without verifying support, passing structures or flags introduced in unsupported versions into vkCreateDevice will result in VK_ERROR_INITIALIZATION_FAILED or VK_ERROR_FEATURE_NOT_PRESENT.
  • Undefined Behavior and Missing Entry Points: If an application bypasses validation and attempts to call core function pointers introduced in newer API versions, the loader will return NULL for those entry points. Attempting to execute a NULL function pointer causes an immediate segmentation fault or crash.

How Applications Handle Version Checks

Robust Vulkan applications do not blindly request the newest API version. Instead, they determine compatibility before creating the instance and device:

  1. Instance Version Query: Applications call vkEnumerateInstanceVersion to check the maximum version supported by the runtime loader before calling vkCreateInstance.
  2. Physical Device Inspection: After creating the instance, the application inspects the apiVersion field of VkPhysicalDeviceProperties by calling vkGetPhysicalDeviceProperties.
  3. Graceful Fallback: If the driver’s supported version is lower than the application's ideal target, the application can either step down its feature set to an older core version (such as falling back from 1.3 to 1.2) or display a user-friendly error instructing the user to update their graphics drivers.
