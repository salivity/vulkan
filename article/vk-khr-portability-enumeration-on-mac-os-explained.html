VK_KHR_portability_enumeration on macOS Explained

This article explains the purpose of the VK_KHR_portability_enumeration instance extension and why it is mandatory for running Vulkan applications on macOS. It details the relationship between Apple's Metal framework, the MoltenVK translation layer, and the Vulkan Portability Initiative. You will learn why macOS hardware is treated as a non-conformant Vulkan implementation by default and how enabling this extension allows the Vulkan loader to discover and use available graphics devices on Apple platforms.

The Role of MoltenVK and the Portability Subset

Apple does not provide native support for the Vulkan graphics and compute API on macOS, iOS, or iPadOS, relying instead on its proprietary Metal API. To run Vulkan applications on Apple hardware, developers use MoltenVK, an open-source compatibility layer that translates Vulkan API calls directly into Metal commands at runtime.

Because Metal and Vulkan have fundamentally different hardware abstraction models and pipeline architectures, MoltenVK cannot support 100% of the core Vulkan specification without severe performance penalties. Consequently, MoltenVK implements the VK_KHR_portability_subset extension. This extension informs the application that the underlying device does not fully conform to the standard Vulkan specification and exposes specific hardware-level limitations, such as constraints on certain blending operations, triangle fans, or push constant sizes.

What Is the VK_KHR_portability_enumeration Extension?

The Vulkan loader operates under a strict conformance guarantee: by default, function calls such as vkEnumeratePhysicalDevices only return physical devices that pass the complete Vulkan Conformance Test Suite (CTS). This safety mechanism prevents standard Vulkan applications from running on partially compatible implementations that might lead to crashes or undefined rendering behavior.

The VK_KHR_portability_enumeration extension is an instance-level extension introduced by the Khronos Group. It acts as an opt-in switch. When an application enables this extension, it explicitly informs the Vulkan loader that it is aware of portability devices and is capable of handling implementations that expose the VK_KHR_portability_subset extension.

Why It Must Be Enabled on macOS

Because MoltenVK exposes a portability subset rather than a fully conformant Vulkan implementation, the Vulkan loader will hide the underlying physical devices by default.

If an application attempts to initialize Vulkan on macOS without enabling portability enumeration:

  1. vkEnumeratePhysicalDevices will return zero available devices, or
  2. The initial call to vkCreateInstance may return the error code VK_ERROR_INCOMPATIBLE_DRIVER.

To discover any GPUs on macOS, the application must explicitly acknowledge that it can run on non-conformant implementations. Enabling VK_KHR_portability_enumeration is the only standard way to force the Vulkan loader to surface the MoltenVK-driven Metal device.

How to Implement the Extension

To enable portability enumeration in a Vulkan application, two specific configurations are required during instance creation:

  1. Add the Extension Name: Include VK_KHR_PORTABILITY_ENUMERATION_EXTENSION_NAME (defined as "VK_KHR_portability_enumeration") in the ppEnabledExtensionNames array of the VkInstanceCreateInfo structure.
  2. Set the Instance Creation Flag: Set the VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR flag in the flags field of the VkInstanceCreateInfo structure.

Once both are configured, calling vkCreateInstance and subsequent enumeration functions will successfully return the available Apple Silicon or Intel-based GPUs on macOS, allowing the graphics pipeline to initialize properly.
