Vulkan Queue Family Ownership Transfer Explained

In the Vulkan API, passing resources between distinct queue families—such as graphics, compute, or transfer queues—requires strict synchronization governed by the resource's sharing mode. When resources are configured with VK_SHARING_MODE_EXCLUSIVE, applications must execute an explicit two-step Queue Family Ownership Transfer (QFOT) using release and acquire pipeline barriers. Conversely, when resources use VK_SHARING_MODE_CONCURRENT, ownership transfers do not occur because the resource is simultaneously accessible across designated queue families, though pipeline memory barriers and semaphores remain strictly necessary to avoid data hazards.

Exclusive Mode and Ownership Transfers

Resources created with VK_SHARING_MODE_EXCLUSIVE yield the highest potential performance because the driver can keep internal cache layouts and compression schemes optimized for a single queue family at a time. To transfer access between different queue families under this mode, you must perform a Queue Family Ownership Transfer.

A queue family ownership transfer consists of two matched barrier operations:

  1. The Release Operation (Source Queue): Recorded into a command buffer submitted to the source queue family. You specify a pipeline barrier (either a buffer memory barrier or image memory barrier) where srcQueueFamilyIndex is set to the current queue family and dstQueueFamilyIndex is set to the target queue family. This operation completes pending writes on the source queue, makes the memory available, and releases access rights.

  2. The Acquire Operation (Destination Queue): Recorded into a command buffer submitted to the destination queue family. You specify the identical barrier structure with matching srcQueueFamilyIndex and dstQueueFamilyIndex values. This operation invalidates destination caches, marks the memory as visible, and acquires ownership so the destination queue can safely read or write to the resource.

Synchronizing the Release and Acquire Steps

The release and acquire barriers do not automatically order execution between different queues. To ensure the destination queue does not attempt the acquire operation before the release operation finishes, you must link the submissions using a VkSemaphore.

  • The vkQueueSubmit call containing the release barrier signals the semaphore upon completion.
  • The vkQueueSubmit call containing the acquire barrier waits on that semaphore before executing the pipeline stages specified in the acquire barrier.

If the resource is an image undergoing a layout transition (for example, transitioning from VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL), the transition can occur during either the release or acquire step, but the oldLayout and newLayout values must match exactly in both barriers.

Resource Handling with Concurrent Sharing Mode

When a resource is created using VK_SHARING_MODE_CONCURRENT, explicit queue family ownership transfers are not utilized. The resource specifies an array of queue family indices (pQueueFamilyIndices) during creation, granting simultaneous access across all listed queue families.

Because ownership is shared:

  • You do not perform release or acquire operations.
  • Setting srcQueueFamilyIndex and dstQueueFamilyIndex to distinct families in barriers for concurrent resources is invalid.
  • Layout transitions cannot occur during execution barriers across different queues; concurrent images must remain in layouts compatible with concurrent access, such as VK_IMAGE_LAYOUT_GENERAL.

Even without an ownership transfer, memory access must still be synchronized. Applications must submit pipeline memory barriers with srcQueueFamilyIndex and dstQueueFamilyIndex set to VK_QUEUE_FAMILY_IGNORED, and use VkSemaphore primitives between queue submissions to order write operations before subsequent read operations. While concurrent mode simplifies command submission by eliminating transfer barriers, it can prevent hardware-specific compression optimizations, making exclusive mode with explicit transfers the preferred approach for high-performance rendering and compute pipelines.
