Vulkan Device Group Memory Coherency Guide

In the Vulkan API, memory coherency across multiple physical devices within a single logical device group is not automatic; physical memory remains architecturally separate for each GPU, requiring explicit allocation masks, peer memory features, and tailored synchronization barriers. While device groups present multiple physical devices under a unified logical device interface, hardware caches are not snooped across inter-device links like PCIe or NVLink. This article explains how memory allocation, peer access capabilities, and pipeline barriers function to govern memory coherency between physical devices in Vulkan.

Physical Memory Separation and Device Masks

When a logical device (VkDevice) is created with multiple physical devices using the VK_KHR_device_group extension (core in Vulkan 1.1), each GPU retains its own dedicated memory heaps and caches. Allocating memory via vkAllocateMemory allocates identical memory footprints across all physical devices in the group by default.

To control where physical allocations actually occur, applications use VkMemoryAllocateFlagsInfo with the VK_MEMORY_ALLOCATE_DEVICE_MASK_BIT. Setting the deviceMask field restricts physical memory allocation to a specific subset of physical devices. If a physical device attempts to read or write to an address that does not have local backing memory or peer access mapped, undefined behavior or device loss occurs.

Peer Memory Access and Capabilities

Direct cross-device memory access is enabled via peer memory mechanisms. Devices determine their cross-device access capabilities using vkGetDeviceGroupPeerMemoryFeatures. This query returns a bitmask of VkPeerMemoryFeatureFlagBits for a given pair of local and remote physical devices, as well as a specific memory heap:

  • VK_PEER_MEMORY_FEATURE_COPY_SRC_BIT: The memory can be used as a source for transfer operations directly to another physical device.
  • VK_PEER_MEMORY_FEATURE_COPY_DST_BIT: The memory can be used as a destination for transfer operations initiated by another physical device.
  • VK_PEER_MEMORY_FEATURE_GENERIC_SRC_BIT: Shaders on a remote device can read directly from this memory (e.g., storage buffers, uniform buffers, sampled images).
  • VK_PEER_MEMORY_FEATURE_GENERIC_DST_BIT: Shaders on a remote device can write directly to this memory.

If GENERIC_SRC or GENERIC_DST is missing, hardware does not support direct bus reads or writes to peer memory, meaning data must be explicitly staged and transferred via vkCmdCopyBuffer or vkCmdCopyImage instead of shared in-place.

Cache Coherency and Pipeline Barriers

Vulkan guarantees no hardware cache snooping between separate GPUs. A write operation performed by GPU 0 is stored in GPU 0’s local L1/L2 caches and is neither automatically flushed to inter-GPU accessible memory nor invalidated from GPU 1’s caches.

To achieve memory coherency across physical devices:

  1. Availability and Visibility Operations: Standard pipeline barriers (vkCmdPipelineBarrier or vkCmdPipelineBarrier2) must be used. GPU 0 must execute a barrier with an srcAccessMask that flushes its local caches (making writes available).
  2. Device Execution Synchronization: The command buffers must be synchronized across devices, typically via semaphores (VkSemaphoreSubmitInfo or VkDeviceGroupSubmitInfo) to ensure GPU 1 does not read until GPU 0 has executed its availability operations.
  3. Invalidation: GPU 1 must execute a barrier with the appropriate dstAccessMask to invalidate its internal caches and fetch the updated values over the interconnect (making writes visible).

Host Coherency vs. Peer Coherency

VK_MEMORY_PROPERTY_HOST_COHERENT_BIT only governs automatic cache coherency between the CPU (host) and a physical device's local memory. It does not apply to device-to-device transactions within a device group. CPU-visible memory mapped by multiple devices still requires application-driven flushing and explicit cross-device synchronization to ensure that updates originating on one GPU propagate to the host and subsequently to a peer GPU.
