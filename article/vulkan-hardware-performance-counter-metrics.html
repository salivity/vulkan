Vulkan Hardware Performance Counter Metrics

This article explores the specific hardware metrics exposed by the Vulkan graphics and compute API profiling queries. It covers the core pipeline statistics natively provided by the API, the dynamically exposed low-level counters available through the performance query extension, and the primary metric categories—including shader execution efficiency, cache hierarchy behavior, and fixed-function unit utilization—used to diagnose GPU bottlenecks.

Standard Pipeline Statistics Queries

Vulkan provides foundational hardware metric collection through core pipeline statistics queries enabled via VK_QUERY_TYPE_PIPELINE_STATISTICS. When recording these queries inside a command buffer, the GPU counts discrete work items passing through each architectural stage:

  • Input Assembly: Counts the total number of processed vertices (VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_VERTICES_BIT) and primitives (VK_QUERY_PIPELINE_STATISTIC_INPUT_ASSEMBLY_PRIMITIVES_BIT).
  • Vertex Shader: Tracks vertex shader invocations (VK_QUERY_PIPELINE_STATISTIC_VERTEX_SHADER_INVOCATIONS_BIT).
  • Geometry and Tessellation: Measures patch generation, evaluation shader invocations, and geometry shader invocations alongside the number of primitives emitted.
  • Clipping: Monitors primitives that enter clipping stages versus primitives that survive and are passed downstream (VK_QUERY_PIPELINE_STATISTIC_CLIPPING_PRIMITIVES_BIT).
  • Fragment Shader: Measures fragment shader invocations (VK_QUERY_PIPELINE_STATISTIC_FRAGMENT_SHADER_INVOCATIONS_BIT), helping identify overdraw and depth test efficiency.
  • Compute Shader: Tracks compute shader invocations (VK_QUERY_PIPELINE_STATISTIC_COMPUTE_SHADER_INVOCATIONS_BIT) to measure dispatch throughput.
  • Mesh and Task Shaders: Available through modern extensions, monitoring task and mesh shader invocations and generated primitive counts.

Low-Level Counters via VK_KHR_performance_query

While pipeline statistics count broad API events, the VK_KHR_performance_query extension exposes low-level, vendor-specific hardware counters directly from the GPU silicon. Because counter availability varies between hardware vendors (NVIDIA, AMD, Intel, Arm, Qualcomm), the extension provides mechanisms to enumerate available metrics at runtime, returning their names, storage formats, units (cycles, percentages, bytes, or counts), and scopes.

The metrics exposed through this interface fall into four major operational categories:

1. Clock Cycles and GPU Execution Time

  • Core Clock Cycles: Total active clock cycles spent executing the queried command segment.
  • GPU Active Time: Real-world execution duration, distinguishing between command processing, compute execution, and pipeline stalls.
  • Idle/Starvation Cycles: Cycles where execution units sit idle awaiting command processor instructions or memory fetches.

2. Shader Core and Execution Unit Utilization

  • ALU Utilization: The percentage of time arithmetic logic units execute instructions relative to theoretical peak capacity.
  • Warp/Wavefront Occupancy: Active compute waves or warps running concurrently relative to maximum supported hardware slots.
  • Instruction Mix: Breakdown of executed instructions into FP32, FP16, INT32, branch, and memory operations.
  • Branch Divergence: The frequency and performance penalty of threads within a SIMD lane taking divergent execution paths.
  • Register Spills: Incidents where high register usage forces variables into local or device memory.

3. Memory Subsystem and Cache Hierarchy

  • Cache Hit and Miss Rates: Hit/miss percentages across L1, L2, and texture caches (L0/L1 vector caches on modern microarchitectures).
  • Memory Bandwidth: Read and write byte throughput across internal crossbars, High Bandwidth Memory (HBM), or GDDR buses.
  • VRAM Latency Stalls: Cycles spent waiting for data requests from external device memory or host-visible buffers.
  • Texture Filtering Units: Sampling rate, texture unit throughput, and stall durations during anisotropic or trilinear filtering.

4. Rasterization and Fixed-Function Units

  • Early-Z / Late-Z Testing: Counts of fragments tested, passed, and culled prior to or following fragment shading to assess depth rejection efficiency.
  • Primitive Culling Rates: Vertices and triangles discarded by backface, frustum, or small-primitive culling units.
  • Color and Depth Raster Operations (ROPs): Utilization and throughput of blending, depth-write, and stencil-write hardware units.
