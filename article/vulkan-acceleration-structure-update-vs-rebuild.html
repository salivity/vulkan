Vulkan Acceleration Structure Update vs Rebuild

In Vulkan ray tracing, managing acceleration structures requires balancing GPU build time against runtime ray traversal efficiency. When geometry moves or deforms, developers must choose between updating an existing acceleration structure (refitting) or rebuilding it from scratch. While updating refits the existing bounding volume hierarchy (BVH) significantly faster with minimal scratch memory, rebuilding generates a brand-new, optimal tree topology that yields faster ray traversal at the cost of higher build overhead.

Rebuilding from Scratch

Rebuilding an acceleration structure involves generating a completely new Bounding Volume Hierarchy using the VK_BUILD_ACCELERATION_STRUCTURE_MODE_BUILD_KHR flag. The driver analyzes the current primitives and constructs an optimized tree structure from the bottom up or top down.

  • Traversal Efficiency: Rebuilding produces an optimal BVH with minimal bounding box overlap, leading to the fastest ray traversal and intersection tests.
  • Structural Flexibility: It supports arbitrary modifications, including changes in primitive counts, topology, vertex positions, or object visibility.
  • Resource Cost: Rebuilding is computationally expensive for the GPU, consuming considerable frame time and requiring a larger scratch buffer during execution.

Updating an Existing Structure

Updating—often referred to as "refitting"—uses the VK_BUILD_ACCELERATION_STRUCTURE_MODE_UPDATE_KHR flag. It adjusts the existing bounding boxes around the modified vertices without changing the underlying hierarchy or connectivity of the tree nodes.

  • Execution Speed: Refitting is significantly faster than a full rebuild, often by an order of magnitude, making it ideal for tight per-frame performance budgets.
  • Topology Constraints: The acceleration structure must have been initially created with the VK_BUILD_ACCELERATION_STRUCTURE_ALLOW_UPDATE_BIT_KHR flag. The number of primitives and geometry types must remain identical; only vertex positions and transformation matrices can change.
  • Degradation of Traversal Performance: Because the tree topology does not adapt to large structural changes, bounding boxes can grow, stretch, and heavily overlap. Over multiple frames, this degradation causes ray traversal performance to drop significantly.

Scratch Buffer Size Larger Smaller

Practical Implementation Strategy

In production engines, a hybrid approach yields the best results:

  • Top-Level Acceleration Structures (TLAS): Always rebuild the TLAS every frame. Because instances are represented as simple oriented bounding boxes, rebuilding a TLAS is computationally cheap and ensures optimal instance culling.
  • Bottom-Level Acceleration Structures (BLAS):
    • Use rebuilds for rigid bodies (apply movement via the TLAS instance matrix instead of changing the BLAS), geometry with changing primitive counts (such as particle meshes or procedural surfaces), or when dramatic topology changes occur.
    • Use updates for continuous, organic deformations like skinned skeletal meshes or cloth simulations.
    • Implement periodic rebuilds for continuously updating dynamic meshes to restore BVH quality and prevent ray traversal degradation over time.
