Vulkan Index Buffers and Indexed Drawing Explained

In 3D computer graphics, meshes frequently share vertices across adjacent triangles, leading to significant overhead if those vertices are duplicated. This article explains what an index buffer is and how indexed drawing in the Vulkan API eliminates redundant vertex storage and vertex shader executions, thereby optimizing GPU memory footprint, bus bandwidth, and hardware pipeline performance.

What is an Index Buffer?

An index buffer is an array of binary data containing integer offsets that point to elements within a vertex buffer. In Vulkan, it is represented as a standard VkBuffer created with the VK_BUFFER_USAGE_INDEX_BUFFER_BIT flag.

Instead of defining geometry by writing full vertex definitions sequentially for every primitive, an application stores each unique vertex only once inside the vertex buffer. The index buffer then defines the topology—such as triangles or lines—by listing the numerical indices of those vertices in the order they should be assembled. Vulkan natively supports these indices primarily as 16-bit (VK_INDEX_TYPE_UINT16) or 32-bit (VK_INDEX_TYPE_UINT32) unsigned integers, with optional 8-bit support via extensions.

The Problem of Redundant Vertex Processing

In standard non-indexed rendering (invoked via vkCmdDraw), every primitive requires its own distinct set of vertices. For example, a basic quad consists of two triangles, requiring six vertices. However, a quad only has four distinct geometric corners; two of the vertices are completely identical in position, texture coordinates, normals, and other attributes.

In complex 3D models, an individual vertex is typically shared by an average of three to six adjacent triangles. Without indexing, full vertex data structures—which often range from 32 to 64 bytes or more—must be duplicated for every triangle that touches them. This redundancy drastically increases memory consumption and memory bandwidth usage when transferring geometry to the GPU. Furthermore, the GPU's vertex shader must execute repeatedly for identical data points, wasting precious compute cycles.

How Indexed Drawing Eliminates Redundancy in Vulkan

Indexed drawing solves this problem through two primary mechanisms: memory footprint reduction and the GPU's Post-Transform Vertex Cache.

In Vulkan, indexed drawing is executed by binding the index buffer using vkCmdBindIndexBuffer and issuing a draw call with vkCmdDrawIndexed.

First, memory usage is minimized because replacing a large vertex attribute structure with a 2-byte or 4-byte integer saves substantial buffer space. For a quad, storing four 32-byte vertices plus six 2-byte indices requires 140 bytes, compared to 192 bytes for six unindexed vertices. As mesh density scales into millions of polygons, this drastically reduces the memory bandwidth required for the Input Assembler stage.

Second, indexed drawing allows the hardware to bypass redundant vertex shader invocations using the Post-Transform Vertex Cache (often referred to as the Parameter Cache). Modern GPUs maintain a small, high-speed cache of recently processed vertex shader outputs indexed by their buffer IDs.

When vkCmdDrawIndexed feeds an index to the graphics pipeline:

  1. The hardware checks whether that specific index currently exists in the post-transform cache.
  2. If a cache hit occurs, the GPU skips vertex shader execution entirely and directly forwards the cached, transformed vertex data to the primitive assembly stage.
  3. If a cache miss occurs, the vertex shader executes, the result is forwarded to the assembly stage, and the output is stored in the cache for subsequent triangles that reference the same index.

By combining compact integer referencing with post-transform caching, indexed drawing in Vulkan ensures that vertex data is neither stored nor computed more times than mathematically necessary.
