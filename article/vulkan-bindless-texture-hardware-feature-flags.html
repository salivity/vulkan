Vulkan Bindless Texture Hardware Feature Flags

Deploying bindless texture architectures in Vulkan requires querying and enabling specific hardware feature flags introduced via the VK_EXT_descriptor_indexing extension, which is core in Vulkan 1.2 and later. Before bypassing traditional slot-based binding models in favor of large global descriptor arrays, an application must inspect VkPhysicalDeviceDescriptorIndexingFeatures (or VkPhysicalDeviceVulkan12Features) and corresponding limits to ensure the underlying GPU supports runtime descriptor indexing, dynamic non-uniform indexing, and post-bind updates.

Essential Feature Flags to Query

To establish a standard bindless pipeline where shaders dynamically index into a massive array of textures, the following boolean flags must be queried and explicitly enabled in the physical device feature chain:

  • descriptorBindingPartiallyBound: In a bindless setup, descriptor arrays are typically allocated with a large maximum capacity, but not every slot is populated with a valid VkImageView or VkSampler. Enabling this flag informs the driver that unreferenced descriptors in an array can be left empty or unbound without triggering validation errors or undefined device behavior.
  • runtimeDescriptorArray: This flag enables shaders to declare descriptor arrays without specifying a fixed compile-time size (for example, layout(binding = 0) uniform sampler2D textures[];). Without this capability, the shading language cannot declare the dynamically sized tables required for bindless resource pools.
  • descriptorBindingSampledImageUpdateAfterBind: Standard Vulkan behavior requires all descriptors in a set to be written before the set is bound to a command buffer. For bindless workflows, textures often need to be streamed, allocated, or updated asynchronously. This flag allows descriptor sets to be modified even after they have been bound in a command buffer, provided the modification occurs before the draw call executes on the GPU.
  • shaderSampledImageArrayNonUniformIndexing: If multiple invocation threads within the same subgroup (warp or wavefront) index different textures from the same descriptor array, non-uniform execution occurs. This flag guarantees that the hardware can handle divergent resource access paths dynamically without generating artifacts or crashes.
  • descriptorBindingVariableDescriptorCount: While optional for basic bindless setups, this flag is critical for memory-efficient designs. It allows the final binding in a VkDescriptorSetLayout to possess a variable descriptor count determined at set allocation time, preventing the over-allocation of descriptor memory across different pipelines.

Corresponding Limits to Inspect

Enabling the boolean flags is only the first step; the application must also query VkPhysicalDeviceDescriptorIndexingProperties to determine the maximum array sizes supported by the hardware:

  • maxDescriptorSetUpdateAfterBindSampledImages: Defines the absolute maximum number of sampled images that can be contained within a descriptor set configured with the VK_DESCRIPTOR_BINDING_UPDATE_AFTER_BIND_BIT flag.
  • maxPerStageDescriptorUpdateAfterBindSampledImages: Specifies how many update-after-bind sampled images can be accessed simultaneously by a single shader stage (such as the fragment stage).

If any of the primary indexing flags return VK_FALSE, or if the queried limits fall below your target texture pool capacity, the application must fall back to traditional per-material descriptor binding or texture atlasing architectures.
