How Vulkan Guarantees Floating-Point Precision

This article provides an overview of how the Vulkan API ensures reliable floating-point arithmetic precision across disparate hardware and conformant drivers. Vulkan achieves this balance between cross-vendor consistency and hardware-native performance by standardizing intermediate representation semantics, providing explicit shader compilation controls, defining strict error tolerances, and enforcing adherence through the Khronos Conformance Test Suite (CTS).

SPIR-V Execution Semantics and IEEE 754 Baselines

Vulkan consumes shaders compiled into SPIR-V intermediate representation rather than high-level source code. The Vulkan specification mandates an underlying arithmetic model derived largely from the IEEE 754-2008 standard for 16-bit, 32-bit, and 64-bit floating-point types.

While full IEEE 754 compliance is not universally enforced across all operations for performance reasons, Vulkan establishes strict baselines for basic arithmetic (addition, subtraction, multiplication, and division). Implementations are bound by specific error limits expressed in Units in the Last Place (ULP). For example, basic single-precision addition and multiplication must evaluate within an error threshold of 0.5 to 1.0 ULP, preventing drivers from returning wildly divergent results across architectures.

Expression Contraction and the NoContraction Decoration

GPU optimizing compilers frequently reorder instructions or fuse multiple operations—such as combining a multiply and an add into a single Fused Multiply-Add (FMA) instruction. While FMA increases speed and often increases intermediate precision by omitting an intermediate rounding step, it can cause numerical divergence between different GPUs or between separate passes on the same GPU.

To guarantee precision across conformant drivers, Vulkan relies on the SPIR-V NoContraction decoration (exposed as precise in GLSL and HLSL). When an operation is marked with this decoration, conformant drivers are strictly prohibited from:

  • Reordering associative operations.
  • Fusing distinct operations into FMA instructions.
  • Applying algebraic identities that assume infinite precision.

This ensures invariant calculations across multiple render passes and diverse hardware architectures.

Shader Float Controls (Vulkan 1.2 Core)

With the core integration of the VK_KHR_shader_float_controls extension in Vulkan 1.2, applications gained fine-grained query and execution controls over floating-point behavior per bit-width (16-bit, 32-bit, and 64-bit).

Drivers must report their support for specific IEEE behaviors via VkPhysicalDeviceFloatControlsProperties, allowing developers to demand and enforce:

  • Rounding Modes: Selecting between Round to Nearest Even (RTE) and Round Towards Zero (RTZ).
  • Denormals: Explicitly configuring whether subnormal numbers are preserved or flushed to zero (FTZ).
  • Signed Zeros, Infinities, and NaNs: Mandating strict compliance with IEEE rules for handling exceptional values rather than allowing hardware-specific approximations.

When a shader specifies these execution modes in SPIR-V, a conformant driver must configure the hardware registers or generate instructions that adhere strictly to those modes.

Khronos Conformance Test Suite (CTS)

Vulkan's precision rules are strictly validated through the Khronos Conformance Test Suite (CTS). For a hardware vendor to market a driver as Vulkan-conformant, the driver must pass rigorous automated mathematical tests.

The CTS verifies that:

  • Arithmetic instructions output values within the allowable ULP limits across the entire dynamic range.
  • Special values like \(\pm0\), \(\pm\infty\), and quiet/signaling NaNs propagate according to the specified driver capabilities.
  • Denormals flush or persist according to requested execution modes.
  • Compilers respect NoContraction invariants.

Through this combination of standardized SPIR-V semantics, explicit compilation controls, and non-negotiable CTS testing, Vulkan ensures predictable, reproducible floating-point arithmetic across all certified drivers and GPU architectures.
