Vulkan Depth Buffers: Why Use Store Op DONT_CARE

Choosing VK_ATTACHMENT_STORE_OP_DONT_CARE for transient depth buffers in Vulkan dramatically boosts performance and lowers power consumption by eliminating unnecessary memory writes. In modern graphics pipelines, depth attachments are frequently used exclusively for visibility testing within a single render pass and are never sampled or read from again. By instructing Vulkan that the contents of the depth buffer do not need to be preserved once rendering concludes, developers prevent the GPU from wasting precious memory bandwidth transferring data back to system memory.

Eliminating Redundant Memory Bandwidth

When a render pass finishes, setting the store operation to VK_ATTACHMENT_STORE_OP_STORE forces the GPU to write the modified depth values from high-speed cache or on-chip registers out to main device memory (VRAM or unified system RAM). Writing high-resolution depth buffers—such as 32-bit floating-point depth at 1440p or 4K—consumes hundreds of megabytes per second of memory bandwidth. By using VK_ATTACHMENT_STORE_OP_DONT_CARE, you inform the driver that the final buffer state is irrelevant, allowing the hardware to discard the data instantly without writing a single byte back to memory.

Crucial for Tile-Based GPUs (Mobile and Integrated)

Tile-Based Deferred Rendering (TBDR) architectures, found in virtually all mobile devices and Apple Silicon GPUs, process rendering in small screen-space tiles stored in ultra-fast, on-chip tile memory.

On TBDR architectures, VK_ATTACHMENT_STORE_OP_DONT_CARE provides the most significant advantage:

  • Zero Main Memory Writes: The depth values are generated and consumed entirely within on-chip tile memory and discarded immediately when the tile rendering completes.
  • Transient Attachments and Lazy Allocation: When coupled with the VK_IMAGE_USAGE_TRANSIENT_ATTACHMENT_BIT image usage flag and VK_MEMORY_PROPERTY_LAZILY_ALLOCATED_BIT memory type, the operating system might not even allocate physical backing memory for the depth buffer. The depth image exists entirely within the tile memory, reducing the application's physical RAM footprint.

Benefits on Desktop and Immediate-Mode GPUs

While traditional immediate-mode desktop GPUs render directly to framebuffers backed by dedicated VRAM, VK_ATTACHMENT_STORE_OP_DONT_CARE still yields distinct benefits. It frees up the GPU’s internal memory buses and avoids polluting L2 caches with data that will never be used again. This leaves cache lines and memory bandwidth available for post-processing passes, compute dispatches, or subsequent render passes, which reduces overall frame render times.

Reduced Power and Thermal Throttling

DRAM access is one of the most power-hungry operations on modern silicon. Discarding transient depth data limits the activity of the memory controllers and external memory buses. On battery-powered platforms such as mobile phones and portable gaming PCs, reducing this bus activity directly translates to lower power draw, reduced device heat, and longer sustained peak performance without thermal throttling.
