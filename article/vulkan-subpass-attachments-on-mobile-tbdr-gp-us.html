Vulkan Subpass Attachments on Mobile TBDR GPUs

Vulkan subpass attachments provide a mechanism to execute multi-pass rendering algorithms, such as deferred shading, directly within the high-speed, on-chip memory of mobile GPUs. By allowing subsequent rendering passes to consume intermediate data while it still resides in tile memory, applications avoid flushing large render targets out to external system RAM. This architectural alignment with Tile-Based Deferred Rendering (TBDR) mobile hardware delivers the critical advantage of eliminating external memory bandwidth bottlenecks, thereby maximizing rendering performance and drastically reducing power consumption.

The Problem with Traditional Multi-Pass Rendering

In traditional immediate-mode rendering architectures commonly found on desktop GPUs, intermediate rendering phases (such as writing G-buffers for normals, albedo, and depth in deferred rendering) write their results to high-bandwidth dedicated VRAM. In mobile systems, however, the GPU shares a single pool of low-power DDR (LPDDR) RAM with the CPU.

LPDDR RAM has significantly lower bandwidth and higher access latency than desktop memory. Moreover, reading and writing large framebuffers to off-chip system memory generates massive amounts of heat and drains battery power, leading rapidly to thermal throttling on mobile devices.

How TBDR GPUs Process Frames

Mobile GPUs (such as Arm Mali, Qualcomm Adreno, and Imagination PowerVR) use Tile-Based Deferred Rendering (TBDR). The GPU subdivides the target framebuffer into small tiles (typically 16x16 or 32x32 pixels) and processes one or more tiles at a time using extremely fast, local on-chip SRAM:

  1. Geometry/Binning Phase: The scene’s primitives are transformed, culled, and sorted into bins corresponding to screen-space tiles.
  2. Rasterization Phase: Each tile is processed entirely within on-chip tile memory before moving to the next.

Once tile processing completes, the contents of the on-chip tile buffer are serialized and written out to main system memory.

The Main Advantage: On-Chip Data Forwarding

The primary advantage of Vulkan subpass attachments on TBDR hardware is the ability to read and write intermediate render target data entirely within on-chip tile memory without performing a round-trip to main system RAM.

Within a single Vulkan render pass, developers can define multiple subpasses and declare dependencies between them. When an intermediate attachment (such as a G-buffer texture) is written in Subpass 0 and sampled in Subpass 1 as an input attachment at the exact same pixel coordinate, the TBDR hardware can keep that data strictly in its local tile buffer.

To leverage this advantage fully:

  • Transient Attachments: Framebuffer images are allocated using the VK_IMAGE_USAGE_TRANSIENT_ATTACHMENT_BIT flag and backed by memory allocated with VK_MEMORY_PROPERTY_LAZILY_ALLOCATED_BIT. This informs the Vulkan driver that physical backing storage in main RAM might never be needed.
  • Load/Store Operations: Intermediate attachments are configured with VK_ATTACHMENT_LOAD_OP_DONT_CARE (or CLEAR) and VK_ATTACHMENT_STORE_OP_DONT_CARE. This instructs the hardware to discard the intermediate data from the on-chip buffer once all subpasses conclude, completely bypassing the write-back to system memory.

Impact on Performance and Power

By eliminating the round-trip through external memory for multi-target passes, Vulkan subpasses yield two decisive advantages for mobile applications:

  • Bandwidth and Latency Reduction: Texture bandwidth is typically the primary performance ceiling on mobile devices. Skipping DRAM reads and writes allows the GPU to run complex deferred pipelines and post-processing effects at sustained native frame rates.
  • Thermal and Energy Efficiency: Accessing on-chip SRAM consumes a fraction of the energy required to drive electrical signals across the bus to off-chip LPDDR memory. Reducing memory traffic directly prevents thermal saturation, enabling extended gameplay sessions without performance degradation.
