Vulkan 8-Bit and 16-Bit Integer Storage Extensions

Using reduced-precision data types is essential for maximizing memory bandwidth, cache utilization, and throughput in high-performance compute and graphics pipelines. This article details the specific extensions that enable 8-bit and 16-bit integer storage in Vulkan: VK_KHR_8bit_storage and VK_KHR_16bit_storage. It explains what capabilities these extensions unlock, how they integrate into core Vulkan specifications, the required SPIR-V capabilities, and the distinction between storage and arithmetic operations.

VK_KHR_16bit_storage

The VK_KHR_16bit_storage extension enables shaders to load from and store to 16-bit integer (and 16-bit floating-point) types in memory buffers. Promoted to Vulkan 1.1 core, this extension reduces buffer footprints for geometries, weights, and compute workloads that do not require full 32-bit precision.

When querying or enabling this extension, the VkPhysicalDevice16BitStorageFeatures structure defines fine-grained support across memory interfaces:

  • storageBuffer16BitAccess: Allows 16-bit types in Storage Buffer Objects (SSBOs).
  • uniformAndStorageBuffer16BitAccess: Allows 16-bit types in both Uniform Buffer Objects (UBOs) and SSBOs.
  • storagePushConstant16: Allows 16-bit types in push constant blocks.
  • storageInputOutput16: Allows 16-bit types in shader input and output interfaces (primarily used in graphics stages).

In SPIR-V shaders, this corresponds to the StorageBuffer16BitAccess, UniformAndStorageBuffer16BitAccess, and StoragePushConstant16 capabilities.

VK_KHR_8bit_storage

The VK_KHR_8bit_storage extension extends reduced-precision storage further by allowing 8-bit integers (int8_t, uint8_t) to be used directly in shader storage. Originally introduced as an extension, it was promoted to core in Vulkan 1.2.

Support is queried and configured via the VkPhysicalDevice8BitStorageFeatures structure, which provides similar granularity to its 16-bit counterpart:

  • storageBuffer8BitAccess: Enables 8-bit integer access within SSBOs.
  • uniformAndStorageBuffer8BitAccess: Enables 8-bit integer access within both UBOs and SSBOs.
  • storagePushConstant8: Enables 8-bit integers within push constants.

The corresponding SPIR-V capabilities mapped to these features are StorageBuffer8BitAccess, UniformAndStorageBuffer8BitAccess, and StoragePushConstant8.

Storage vs. Arithmetic Operations

Enabling VK_KHR_8bit_storage or VK_KHR_16bit_storage only guarantees that data can be loaded from and stored into memory in packed formats. When a shader loads an 8-bit or 16-bit integer using only these storage extensions, the value is typically unpacked and converted to a standard 32-bit register internally to perform arithmetic calculations, then cast back upon storage.

To execute native mathematical calculations directly on 8-bit integers without extending them to 32-bit types, implementations must also support and enable:

  • VK_KHR_shader_float16_int8 (promoted to Vulkan 1.2 core): Provides the shaderInt8 feature, mapping to the SPIR-V Int8 capability, allowing 8-bit integer operations inside shader registers.
  • VkPhysicalDeviceFeatures::shaderInt16 (core since Vulkan 1.0): Provides the SPIR-V Int16 capability for executing native 16-bit integer arithmetic.

Enabling the Extensions in Code

To use these capabilities in a Vulkan compute pipeline:

  1. Chain VkPhysicalDevice8BitStorageFeatures and VkPhysicalDevice16BitStorageFeatures into the pNext chain of VkPhysicalDeviceFeatures2 when calling vkGetPhysicalDeviceFeatures2 to verify hardware support.
  2. Chain the same structures with the desired feature flags set to VK_TRUE into the pNext chain of VkDeviceCreateInfo during logical device creation.
  3. In GLSL compute shaders, include the respective extensions to expose the types:
    • #extension GL_EXT_shader_16bit_storage : require
    • #extension GL_EXT_shader_8bit_storage : require
    • #extension GL_EXT_shader_explicit_arithmetic_types : require (if performing math on smaller integer types directly).
