Vulkan Miss Shader Indexing and Environment Maps

This article examines the mechanics of miss shader indexing and the integration of environment maps in Vulkan ray tracing. It covers how the Vulkan API selects specific miss shaders through the Shader Binding Table based on ray type, and details how these shaders utilize ray direction vectors to sample background radiance and sky lighting when a ray fails to intersect any geometry in the acceleration structure.

Miss Shader Indexing in Vulkan

In the Vulkan ray tracing pipeline (VK_KHR_ray_tracing_pipeline), rays are cast into a Top-Level Acceleration Structure (TLAS) using the GLSL built-in function traceRayEXT(). When a ray fails to intersect any bounding volume or triangle within its defined range (\(t_{\min}\) to \(t_{\max}\)), the pipeline invokes a miss shader.

Miss shader indexing determines precisely which miss shader execution record to invoke from the Shader Binding Table (SBT). The SBT organizes shader handles into contiguous memory blocks on the GPU. The selection of the miss shader is controlled directly by the missIndex argument supplied to traceRayEXT():

traceRayEXT(
    topLevelAS,           // Acceleration structure
    rayFlags,             // Ray flags (e.g., gl_RayFlagsOpaqueEXT)
    cullMask,             // Instance cull mask
    sbtRecordOffset,      // SBT offset for hit groups
    sbtRecordStride,      // SBT stride for hit groups
    missIndex,            // Index targeting the miss shader
    origin,               // Ray origin
    tMin,                 // Minimum ray distance
    direction,            // Ray direction
    tMax,                 // Maximum ray distance
    payloadLocation       // Ray payload location
);

The Shader Binding Table Calculation

When configuring a ray tracing pipeline via vkCmdTraceRaysKHR, the application provides a VkStridedDeviceAddressRegionKHR structure defining the base address, stride, and size of the miss shader table.

The GPU resolves the specific miss shader memory address using the formula:

\[\text{Target Address} = \text{Base Address} + (\text{missIndex} \times \text{Stride})\]

This indexing mechanism allows a single pipeline to maintain separate miss logic for different ray classes:

  • Primary/Camera Rays: Typically assigned missIndex = 0, directing execution to a shader that samples the skybox or environment map.
  • Shadow/Occlusion Rays: Typically assigned missIndex = 1, pointing to a lightweight miss shader that simply flags the light source as visible (unshadowed).
  • Secondary/Indirect Rays: Can share the environment miss shader or invoke dedicated ambient-fallback shaders to approximate diffuse ambient terms.

Resolving Background Light with Environment Maps

When a primary, reflection, or refraction ray misses all scene geometry, the environment map miss shader is responsible for providing the outgoing radiance along the reversed ray path.

Accessing the Ray Direction

Inside the miss shader, Vulkan exposes built-in inputs that detail the failed trajectory. The most critical variable is gl_WorldRayDirectionEXT, a normalized 3D vector representing the direction in which the ray was traveling when it left the origin or a reflective surface.

Equirectangular Mapping

If using a 2D High Dynamic Range (HDR) equirectangular texture (lat-long map), the 3D ray direction must be converted into 2D texture coordinates \((u, v)\):

  1. Spherical Coordinate Conversion: \[\theta = \text{atan2}(d_z, d_x)\] \[\phi = \text{asin}(d_y)\] (where \(d_x, d_y, d_z\) are the components of gl_WorldRayDirectionEXT)

  2. UV Normalization: \[u = \frac{\theta}{2\pi} + 0.5\] \[v = \frac{\phi}{\pi} + 0.5\]

The shader samples the HDR texture using these coordinates and writes the resulting color directly to the ray payload:

#version 460
#extension GL_EXT_ray_tracing : require

layout(location = 0) rayPayloadInEXT vec3 hitValue;
layout(binding = 1, set = 0) uniform sampler2D environmentMap;

const vec2 invAtan = vec2(0.1591549, 0.3183098); // 1/(2*PI), 1/PI

vec2 SampleSphericalMap(vec3 v) {
    vec2 uv = vec2(atan(v.z, v.x), asin(v.y));
    uv *= invAtan;
    uv += 0.5;
    return uv;
}

void main() {
    vec2 uv = SampleSphericalMap(normalize(gl_WorldRayDirectionEXT));
    hitValue = texture(environmentMap, uv).rgb;
}

Cubemap Resolution

When using a cubemap (samplerCube), coordinate transformation is handled in hardware. The miss shader passes the normalized gl_WorldRayDirectionEXT vector directly into texture(cubeMap, gl_WorldRayDirectionEXT). The hardware selects the appropriate cube face and computes texel coordinates natively, reducing arithmetic overhead compared to spherical projection.

Radiance Scaling and Shadow Integration

In physically based rendering (PBR), raw texel values from the environment map are often scaled by an exposure value or sun intensity factor before being written to the payload. For diffuse or glossy indirect bounces that miss, pre-filtered environment maps or spherical harmonics can be sampled using the reflection vector or surface normal to deliver accurate image-based lighting (IBL).

Through the pairing of SBT missIndex routing and direction-based texture sampling, Vulkan decouples geometric intersection tests from distant illumination, enabling unified resolution of both infinite sky backgrounds and shadow occlusion states.
