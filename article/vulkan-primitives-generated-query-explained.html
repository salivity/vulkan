Vulkan Primitives Generated Query Explained

The primitives generated query in the Vulkan API provides developers with an accurate mechanism to measure the exact amount of geometric data produced by a graphics pipeline. This article explains what the primitives generated query is, where it operates within the pipeline architecture, how it tracks geometry volume before rasterization and clipping, and how it is implemented to profile and optimize rendering workloads.

What Is the Primitives Generated Query?

In Vulkan, the primitives generated query—typically accessed via the query type VK_QUERY_TYPE_PRIMITIVES_GENERATED_EXT provided by the VK_EXT_primitives_generated_query extension—is a performance and diagnostic tool. It counts the total number of complete geometric primitives (such as triangles, lines, or points) generated by the pipeline's vertex-processing stages.

Unlike occlusion queries, which measure how many fragments pass depth and stencil testing, or pipeline statistics queries, which provide broad hardware metrics, the primitives generated query precisely isolates and quantifies geometry volume at the pre-rasterization boundary.

Pipeline Location and Measurement Mechanism

The query tracks primitives emitted immediately before the clipping, culling, and rasterization phases. The exact point of measurement depends on which programmable stages are active in the bound graphics pipeline:

  1. Vertex Shader Only: If tessellation and geometry shaders are disabled, the query counts the primitives assembled directly from the vertex shader output based on the input assembly topology (e.g., triangle lists or strips).
  2. Tessellation Enabled: When tessellation control and evaluation shaders are used, the query records the primitives generated by the fixed-function tessellator and evaluation shader.
  3. Geometry Shader Enabled: When a geometry shader is present, the query counts the primitives fully assembled from the vertices emitted via shader instructions, regardless of whether a tessellation stage preceded it.

Crucially, the primitives generated query counts all valid primitives before frustum clipping, viewport clipping, and back-face culling take place. This ensures that the metric reflects the absolute geometric load created by application shaders, rather than the subset that happens to land within the viewable screen space.

Tracking Multi-Stream and Transform Feedback Geometry

For advanced pipelines utilizing multiple vertex streams (frequently coupled with transform feedback via VK_EXT_transform_feedback), the primitives generated query supports indexed counting.

Using vkCmdBeginQueryIndexedEXT and vkCmdEndQueryIndexedEXT, developers can pass a specific index parameter to monitor distinct output streams (from stream 0 up to stream 3). This allows isolated tracking of geometry diverted to specific transform feedback buffers versus geometry routed to the rasterizer.

Implementation Workflow

Using the query involves standard Vulkan query pool operations:

  1. Query Pool Creation: Allocate a VkQueryPool using VkQueryPoolCreateInfo, specifying queryType as VK_QUERY_TYPE_PRIMITIVES_GENERATED_EXT.
  2. Pool Reset: Reset the query pool using vkCmdResetQueryPool within a command buffer.
  3. Query Boundary: Enclose the target draw calls with vkCmdBeginQueryIndexedEXT (or vkCmdBeginQuery) and vkCmdEndQueryIndexedEXT (or vkCmdEndQuery).
  4. Retrieval: Fetch the 64-bit integer results either on the CPU using vkGetQueryPoolResults or directly on the GPU using vkCmdCopyQueryPoolResults for compute-driven feedback loops.

Key Use Cases in Optimization

Tracking geometry volume with this query enables several critical optimizations:

  • Tessellation Amplification Profiling: Measuring whether adaptive tessellation factors are generating excessive micro-triangles that overwhelm GPU rasterizers.
  • Geometry Shader Expansion Monitoring: Detecting inefficient geometry shader implementations that emit too many vertices per primitive.
  • Dynamic Level of Detail (LOD) Calibration: Validating that mesh reduction algorithms correctly decrease primitive generation as objects move away from the camera.
