Vulkan Index Types for Indexed Drawing Commands

When issuing indexed drawing commands such as vkCmdDrawIndexed in Vulkan, the API requires an index buffer bound with a specific index type to determine the format and byte size of each index. This article provides a direct overview of the supported index types defined by the VkIndexType enumeration in Vulkan, covering both standard core types and modern extensions, along with their practical usage and performance implications.

Core Vulkan Index Types

In base Vulkan (version 1.0 and later), two index types are universally supported on all conforming implementations without needing additional extensions or features enabled:

  • VK_INDEX_TYPE_UINT16: Represents 16-bit unsigned integers (uint16_t). This format consumes 2 bytes per index and supports meshes with up to 65,536 distinct vertex indices. It is the most common choice for general rendering because it provides a strong balance between vertex capacity and memory bandwidth.
  • VK_INDEX_TYPE_UINT32: Represents 32-bit unsigned integers (uint32_t). This format consumes 4 bytes per index and supports meshes with over 4 billion vertices. It is reserved for large, dense meshes where index values exceed the 16-bit threshold.

Extended Index Types

Vulkan also provides support for smaller index sizes through extensions and newer core versions:

  • VK_INDEX_TYPE_UINT8_KHR (or VK_INDEX_TYPE_UINT8_EXT): Represents 8-bit unsigned integers (uint8_t), consuming 1 byte per index with a maximum range of 256 vertices. This type is provided by the VK_KHR_index_type_uint8 (or VK_EXT_index_type_uint8) extension and integrated into Vulkan 1.4 core. It is ideal for UI elements, simple primitives, or compact geometry to minimize memory bandwidth and storage overhead. Use of this type requires checking and enabling the indexTypeUint8 feature in VkPhysicalDeviceIndexTypeUint8FeaturesKHR.

(Note: While VK_INDEX_TYPE_NONE_KHR or VK_INDEX_TYPE_NONE_NV exists in the VkIndexType enumeration for acceleration structure builds in ray tracing, it cannot be used for traditional indexed draw commands.)

Applying Index Types in Draw Commands

To use an index type, specify it when binding the index buffer via vkCmdBindIndexBuffer:

vkCmdBindIndexBuffer(
    commandBuffer,
    indexBuffer,
    offset,
    VK_INDEX_TYPE_UINT16 // Specifies the index type
);

Once bound, drawing commands like vkCmdDrawIndexed or vkCmdDrawIndexedIndirect read indices from the bound buffer according to the byte stride dictated by the chosen VkIndexType.

Performance Considerations

  • Bandwidth Efficiency: Smaller index types reduce memory bus traffic and improve post-transform vertex cache utilization. Use UINT16 or UINT8 whenever the vertex count allows.
  • Buffer Alignment: The offset passed to vkCmdBindIndexBuffer must be an integer multiple of the index type size (e.g., a multiple of 2 for UINT16, or 4 for UINT32).
