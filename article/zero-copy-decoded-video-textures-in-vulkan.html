Zero-Copy Decoded Video Textures in Vulkan

This article examines how the Vulkan graphics and compute API enables developers to sample hardware-decoded video frames directly as textures without round-trip memory copies. It covers the specific Vulkan Video extensions, memory sharing mechanisms, YCbCr format conversion, and synchronization requirements necessary to maintain a fully GPU-resident zero-copy pipeline from video decoding to final rendering.

Direct Frame Sampling in Vulkan

Decoded video frames can be sampled directly as textures without round-trip memory copies to the host (CPU) or redundant intermediate copies on the device (GPU). Vulkan provides native capabilities to stream, decode, and render video content entirely within GPU-accessible memory.

Achieving a zero-copy pipeline depends on whether the decoding process takes place via native Vulkan Video extensions or through an external hardware decoding API.

Native Vulkan Video Pipeline

The Khronos Group standardized native video decoding directly within the API using core extensions:

  • VK_KHR_video_queue
  • VK_KHR_video_decode_queue
  • Codec-specific extensions (such as VK_KHR_video_decode_h264, VK_KHR_video_decode_h265, and VK_KHR_video_decode_av1)

Under this native framework, destination frames—often stored in the Decoded Picture Buffer (DPB)—are allocated as standard VkImage handles backed by VkDeviceMemory.

Dual-Usage Image Allocation

To avoid intermediate copies, the destination VkImage must be created with combined usage flags:

  • VK_IMAGE_USAGE_VIDEO_DECODE_DST_BIT_KHR (allows the video decode hardware to write output frames).
  • VK_IMAGE_USAGE_SAMPLED_BIT (allows graphics and compute pipelines to sample the image in shaders).

By setting both flags at creation time, the decoded frame resides directly in memory that shaders can read without an intervening blit or copy operation.

Handling YCbCr Formats

Video codecs output data in multi-planar YCbCr formats, such as NV12 (8-bit) or P010 (10-bit), rather than traditional RGBA formats. Vulkan handles these natively via the Sampler YCbCr Conversion feature (VK_KHR_sampler_ycbcr_conversion, integrated into core Vulkan 1.1).

  1. VkSamplerYcbcrConversion: Configures the color model, range (full vs. narrow), chroma siting, and component swizzle.
  2. Combined Image Sampler: The sampler converts YCbCr color spaces to RGB directly during texture lookups in the fragment or compute shader.
  3. Multi-Planar Views: Shaders sample the multi-planar image seamlessly through a unified descriptor, bypassing the need for manual shader-side matrix math or multi-pass texture blending.

Synchronization and Queue Family Ownership

Because video decoding and graphics rendering typically run on different hardware engines on the GPU, they use distinct Vulkan queue families:

  1. Queue Family Transfer: After decoding completes, a pipeline barrier (VkImageMemoryBarrier2) must release ownership of the VkImage from the decode queue family and acquire it on the graphics or compute queue family.
  2. Layout Transition: The barrier transitions the image layout from VK_IMAGE_LAYOUT_VIDEO_DECODE_DST_KHR to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL.
  3. Synchronization: Execution dependencies ensure the decoder finishes writing to the specific DPB slot before the fragment shader begins reading it, preventing read-after-write hazards.

External Decoders and Zero-Copy Imports

When using platform-specific hardware decoders—such as NVIDIA NVDEC, Intel VA-API, or Android MediaCodec—Vulkan supports zero-copy texturing through external memory and synchronization extensions:

  • VK_KHR_external_memory paired with platform extensions (e.g., VK_KHR_external_memory_fd on Linux, VK_KHR_external_memory_win32 on Windows, or VK_ANDROID_external_memory_android_hardware_buffer on Android).
  • VK_KHR_external_semaphore to coordinate completion signals between the external decoder and the Vulkan queue.

These extensions allow Vulkan to bind an existing native GPU buffer directly to a VkImage, enabling shaders to sample decoded video frames with zero CPU round-trips and zero memory duplication.
