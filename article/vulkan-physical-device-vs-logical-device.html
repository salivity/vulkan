Vulkan Physical Device vs Logical Device

In the Vulkan graphics and compute API, the distinction between a physical device and a logical device separates the actual hardware installed on a system from an application's configured interface to that hardware. A physical device is a read-only representation of the underlying GPU and its fixed capabilities, while a logical device is an actively created software construct that specifies exactly which features, extensions, and execution queues an application intends to use. Understanding the structural differences between these two concepts is essential for managing hardware resources, memory, and command execution efficiently.

Physical Device (VkPhysicalDevice)

A physical device represents a concrete piece of hardware, such as a discrete GPU, an integrated graphics chip, or a software rasterizer. It is not created by the application; instead, it is enumerated directly from an initialized VkInstance using vkEnumeratePhysicalDevices.

Structurally and functionally, a physical device acts as a static query mechanism:

  • Query-Only Interface: Applications use physical device handles to query hardware capabilities, such as supported Vulkan versions, vendor details, memory heaps, hardware limits, and available queue families.
  • Lifecycle Management: Because a physical device represents physical silicon tied to the system, it has no vkCreate or vkDestroy functions. Its lifecycle is bound to the VkInstance.
  • Resource Inability: A physical device cannot allocate memory, create buffers, create pipelines, or record and execute commands. It serves solely to describe what the hardware can do, not to perform work.

Logical Device (VkDevice)

A logical device represents an initialized, configured channel of communication between the application and a physical device. It is created explicitly using vkCreateDevice, where the developer provides a VkDeviceCreateInfo structure specifying the exact parameters required by the application.

Key characteristics of a logical device include:

  • Feature and Extension Activation: While a physical device may support hundreds of features and extensions, the logical device activates only the subset explicitly requested by the developer (such as geometry shaders, ray tracing pipelines, or specific memory models).
  • Queue Instantiation: Physical devices expose queue families with various capabilities (graphics, compute, transfer). The logical device actually instantiates specific queues from these families, returning VkQueue handles used to submit command buffers.
  • Resource Ownership and Creation: The logical device is the primary factory for Vulkan objects. It creates render passes, pipelines, command pools, buffers, images, and manages memory allocations.
  • Lifecycle and Destruction: A logical device is explicitly managed. It must be destroyed with vkDestroyDevice once all submitted work is complete and all associated resources have been freed.

Key Structural Differences

Attribute Physical Device (VkPhysicalDevice) Logical Device (VkDevice)
Nature Hardware abstraction handle Software communication interface
Creation Enumerated via VkInstance Created via vkCreateDevice
Destruction Implicit (destroyed with VkInstance) Explicit (vkDestroyDevice)
State Stateless and read-only Stateful and active
Work Execution Cannot allocate resources or submit work Allocates resources and manages execution queues
Multiplicity Fixed count based on installed hardware Multiple logical devices can be created from one physical device

The One-to-Many Relationship

A single physical device can spawn multiple logical devices. This structural separation allows different components of an application—or entirely different threads—to operate with independent configurations, separate queue allocations, and isolated feature sets on the same physical GPU without interfering with one another.
