Understanding Transform Feedback in Vulkan

This article provides an overview of transform feedback, detailing its origins in OpenGL as a mechanism for streaming processed geometry back to the GPU, and explaining how Vulkan replicates this functionality through dedicated extensions. Readers will learn the core mechanics of transform feedback, why modern APIs initially favored alternative approaches, and how Vulkan supports native geometry streaming primarily to facilitate direct compatibility and translation layers from legacy graphics APIs.

What Is Transform Feedback?

Transform feedback is a hardware feature in the graphics pipeline that captures primitive data—such as vertices produced by vertex, tessellation, or geometry shaders—before they reach the rasterizer. Instead of immediately drawing these primitives to the screen, the GPU writes the transformed vertex attributes directly into one or more buffer objects. This allows applications to process geometry once on the GPU and reuse the calculated results in subsequent rendering passes or simulation steps without involving the CPU.

Geometry Streaming in OpenGL

In OpenGL, transform feedback functions as a dedicated pipeline stage. Developers specify which varying variables to record using glTransformFeedbackVaryings, bind target buffer objects to indexed binding points using glBindBufferBase or glBindBufferRange, and control recording with glBeginTransformFeedback and glEndTransformFeedback.

Rasterization can be disabled using glEnable(GL_RASTERIZER_DISCARD) when an application only needs to generate data, such as running a GPU-based particle simulation or calculating cloth physics. Once captured, these buffers can be drawn using glDrawTransformFeedback, which renders the exact number of primitives recorded without requiring the CPU to query the primitive count.

Replicating Transform Feedback in Vulkan

When Vulkan was initially released, transform feedback was intentionally omitted. Modern GPU architectures generally favor general-purpose compute shaders writing to Storage Buffers (SSBOs) over fixed-function geometry capture. However, the rise of API translation layers like DXVK (Direct3D 9/10/11 to Vulkan) and Zink (OpenGL to Vulkan) demanded native transform feedback support to run legacy games efficiently without expensive compute-shader emulations.

To solve this, the Khronos Group introduced the VK_EXT_transform_feedback extension, replicating the exact geometry streaming capabilities found in OpenGL and DirectX Stream Output.

Pipeline Configuration

In Vulkan, capturing geometry requires enabling the extension during device creation and configuring the graphics pipeline accordingly:

  • Shader Interfaces: Shaders (written in GLSL or HLSL and compiled to SPIR-V) use the Xfb execution mode and explicit XfbBuffer, Offset, and Stride layout qualifiers on output variables.
  • Rasterization Control: Setting rasterizerDiscardEnable to VK_TRUE inside VkPipelineRasterizationStateCreateInfo disables rasterization, mimicking OpenGL's GL_RASTERIZER_DISCARD.

Buffer Management and Execution

Rather than global state toggles, Vulkan handles transform feedback through explicit command recording:

  1. Binding Buffers: Buffers allocated with the VK_BUFFER_USAGE_TRANSFORM_FEEDBACK_BUFFER_BIT_EXT flag are bound into the command stream via vkCmdBindTransformFeedbackBuffersEXT.
  2. Recording Data: The capture window is bounded by calling vkCmdBeginTransformFeedbackEXT and vkCmdEndTransformFeedbackEXT.
  3. Tracking Primitive Counts: Vulkan uses counter buffers (VK_BUFFER_USAGE_TRANSFORM_FEEDBACK_COUNTER_BUFFER_BIT_EXT) to store the byte offset and number of vertices written.
  4. Drawing Streamed Geometry: To render the recorded vertices without CPU synchronization, Vulkan provides vkCmdDrawIndirectByteCountEXT. This command consumes the counter buffer directly, matching the behavior of OpenGL's glDrawTransformFeedback.

Through VK_EXT_transform_feedback, Vulkan maintains full functional parity with OpenGL's geometry streaming pipeline, enabling efficient legacy API translation while providing explicit control over synchronization and memory management.
