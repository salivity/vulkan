How to Compile HLSL to SPIR-V for Vulkan

DirectX Shader Compiler (DXC) allows developers to write shaders in Microsoft High-Level Shader Language (HLSL) and compile them directly into SPIR-V bytecode for use with the Vulkan API. Historically, targeting Vulkan required writing shaders in GLSL, but modern graphics pipelines often standardize on HLSL across both DirectX and Vulkan platforms. This guide details how to configure DXC, map HLSL semantics and bindings to Vulkan constructs, and integrate the compilation process into both offline build systems and runtime engines.

The Core Tool: DirectX Shader Compiler (DXC)

Microsoft’s open-source DirectX Shader Compiler (DXC), based on LLVM, includes a dedicated SPIR-V backend developed in collaboration with Khronos Group. While the older fxc.exe only outputs DXBC bytecode for DirectX 9–11, DXC supports modern shader models (SM 6.0+) and can output either DXIL for DirectX 12 or SPIR-V for Vulkan.

Pre-built binaries of DXC (dxc.exe on Windows or dxc on Linux) are available through the official DirectXShaderCompiler GitHub repository and are also bundled inside the LunarG Vulkan SDK.

Compiling from the Command Line

To generate SPIR-V binaries, pass the -spirv flag to the DXC executable along with your target profile, entry point, and output path.

dxc -spirv -T vs_6_0 -E main -Fo vertex_shader.spv shader.hlsl

Key arguments include:

  • -spirv: Enables the SPIR-V code generation backend instead of DXIL.
  • -T <profile>: Specifies the target profile (e.g., vs_6_6 for vertex shaders, ps_6_6 for pixel/fragment shaders, cs_6_6 for compute shaders, lib_6_6 for ray tracing).
  • -E <name>: Identifies the entry point function within the HLSL source.
  • -Fo <file>: Designates the output file name for the compiled SPIR-V binary.

Configuring Vulkan Target Environments

You can tune the generated SPIR-V to match specific Vulkan versions and SPIR-V specifications using the -fspv-target-env flag:

dxc -spirv -T ps_6_5 -E PSMain -fspv-target-env=vulkan1.3 -Fo pixel.spv shader.hlsl

Supported targets include vulkan1.0, vulkan1.1, vulkan1.2, and vulkan1.3. Choosing a higher version allows DXC to emit advanced SPIR-V capabilities, such as native 16-bit types and modern synchronization primitives.

Managing Resource Bindings

HLSL utilizes register assignments (b, t, u, s), whereas Vulkan uses explicit descriptor sets and bindings (set = X, binding = Y). There are two primary strategies to bridge this gap:

1. Using Vulkan Attributes in HLSL

DXC supports Vulkan-specific attributes directly in HLSL code. This gives you exact control over descriptor layout:

// Bind a constant buffer to Set 0, Binding 0
[[vk::binding(0, 0)]]
cbuffer SceneData : register(b0)
{
    float4x4 viewProjection;
};

// Bind a texture to Set 1, Binding 0
[[vk::binding(0, 1)]]
Texture2D mainTexture : register(t0);

// Bind a sampler to Set 1, Binding 1
[[vk::binding(1, 1)]]
SamplerState mainSampler : register(s0);

// Vulkan Push Constant
struct PushConstants
{
    float4 customColor;
};
[[vk::push_constant]] PushConstants pc;

2. Automatic Binding Shifts via CLI

If you prefer to keep your HLSL code agnostic of Vulkan attributes, DXC can automatically assign registers to descriptor sets using command-line shift flags:

dxc -spirv -T ps_6_0 -E main \
    -fvk-b-shift 0 0 \
    -fvk-t-shift 100 0 \
    -fvk-u-shift 200 0 \
    -fvk-s-shift 300 0 \
    -Fo shader.spv shader.hlsl

The arguments define [shift amount] [descriptor set]. For instance, -fvk-t-shift 100 0 maps register(t0) to Vulkan set 0, binding 100.

Memory Layout and Alignment

DirectX and Vulkan use different default buffer packing rules. HLSL traditionally packs data tightly according to DirectX rules, whereas Vulkan defaults to standard layouts like std140 or std430.

To avoid alignment mismatches when populating Uniform Buffers or Storage Buffers:

  • Use the -fvk-use-dx-layout flag to force the generated SPIR-V to preserve DirectX-style memory layouts.
  • Alternatively, structure your data structures to conform to std430 standards using explicit scalar or 16-byte alignments.

In-Engine Compilation with the DXC API

You can compile HLSL to SPIR-V at runtime by linking against dxcompiler.dll (or libdxcompiler.so) and using the IDxcCompiler3 interface.

To enable SPIR-V output in code:

  1. Initialize the DXC library via DxcCreateInstance.
  2. Construct your argument list as an array of wide-character strings (LPCWSTR), making sure to include L"-spirv".
  3. Call IDxcCompiler3::Compile().
  4. Extract the resulting byte buffer from the IDxcResult object and pass it directly to vkCreateShaderModule.

This programmatic approach allows engines to maintain a unified shader codebase without precompiling variants across multiple platform targets.
