Vulkan Timestamp Queries: Measure GPU Pass Duration

Measuring GPU pass duration using Vulkan timestamp query pools allows developers to capture exact execution times directly on the graphics hardware, bypassing the inaccuracies caused by asynchronous CPU-to-GPU command submission. By allocating a query pool specifically for timestamps, inserting query writes before and after targeted rendering or compute commands, and converting raw device ticks to nanoseconds using the physical device’s timestamp period, developers achieve microsecond-accurate profiling without stalling the execution pipeline.

Why CPU Timing Fails for GPU Workloads

In modern graphics APIs like Vulkan, the CPU builds and submits command buffers to queues asynchronously. Measuring execution time from the CPU using standard clocks (such as std::chrono) records only the submission time or requires manual pipeline stalls via vkQueueWaitIdle or vkWaitForFences. Stalling the GPU alters its pipeline behavior, empties queues, and introduces artificial latency that renders the profiling data meaningless. To measure true GPU pass execution, measurement hooks must be embedded directly into the GPU command stream.

Understanding Timestamp Query Pools

Vulkan manages hardware timing events through a VkQueryPool. To profile duration, a pool is created with the query type VK_QUERY_TYPE_TIMESTAMP via vkCreateQueryPool.

VkQueryPoolCreateInfo poolInfo = {
    .sType = VK_STRUCTURE_TYPE_QUERY_POOL_CREATE_INFO,
    .queryType = VK_QUERY_TYPE_TIMESTAMP,
    .queryCount = 2 // One for the start of the pass, one for the end
};
VkQueryPool queryPool;
vkCreateQueryPool(device, &poolInfo, NULL, &queryPool);

Before recording timestamps, the pool indices must be reset using vkCmdResetQueryPool within a command buffer (or vkResetQueryPool on the host, if supported).

Capturing Execution Windows in Command Buffers

To measure a pass accurately, a pair of timestamps must frame the target workload using vkCmdWriteTimestamp:

  1. Pass Start: Recorded using the pipeline stage flag VK_PIPELINE_STAGE_TOP_OF_PIPE_BIT. This captures the exact moment the GPU begins processing the first command of the pass.
  2. Pass Execution: The draw calls, compute dispatches, or state bindings of the pass.
  3. Pass End: Recorded using VK_PIPELINE_STAGE_BOTTOM_OF_PIPE_BIT. This ensures the timestamp is written only when all prior operations in the pipeline have completed execution.
// Reset queries
vkCmdResetQueryPool(cmdBuffer, queryPool, 0, 2);

// Mark start of the pass
vkCmdWriteTimestamp(cmdBuffer, VK_PIPELINE_STAGE_TOP_OF_PIPE_BIT, queryPool, 0);

// Record pass commands (render passes, dispatches, etc.)
vkCmdDraw(cmdBuffer, ...);

// Mark end of the pass
vkCmdWriteTimestamp(cmdBuffer, VK_PIPELINE_STAGE_BOTTOM_OF_PIPE_BIT, queryPool, 1);

Retrieving and Converting Timing Data

After the command buffer completes its execution on the queue—typically signaled by a fence or signaled semaphore in a subsequent frame—the recorded values are retrieved on the host using vkGetQueryPoolResults.

uint64_t timestamps[2];
vkGetQueryPoolResults(
    device,
    queryPool,
    0, // First query
    2, // Query count
    sizeof(timestamps),
    timestamps,
    sizeof(uint64_t),
    VK_QUERY_RESULT_64_BIT | VK_QUERY_RESULT_WAIT_BIT
);

The values returned represent raw hardware clock ticks. To convert these ticks into real-world units (nanoseconds), the delta must be multiplied by the timestampPeriod value found in VkPhysicalDeviceLimits:

\[\text{Duration (ns)} = (\text{timestamps}[1] - \text{timestamps}[0]) \times \text{VkPhysicalDeviceLimits::timestampPeriod}\]

Hardware Considerations and Accuracy

Not all queue families support timestamp queries. Support must be verified by checking that the timestampValidBits member of VkQueueFamilyProperties for the targeted queue family is greater than zero. If the property indicates 36 bits, for example, the raw timestamp counter will wrap around every \(2^{36}\) ticks, which must be handled if profiling operations spanning extended durations.

Because vkCmdWriteTimestamp executes entirely within the GPU scheduler without interrupting the instruction stream or synchronizing with the CPU, timestamp query pools provide the lowest-overhead and most precise measurement of GPU pass performance achievable in Vulkan.
