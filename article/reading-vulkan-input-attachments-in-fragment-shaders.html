Reading Vulkan Input Attachments in Fragment Shaders

This article provides an overview of input attachments in the Vulkan graphics API, detailing their architectural purpose and performance advantages. It explains how to declare and access these attachments within GLSL fragment shaders using subpass inputs, highlighting the pipeline setup and dependencies required for effective multipass rendering techniques such as deferred shading.

What is an Input Attachment?

In Vulkan, an input attachment is a dedicated image attachment that can be read from within a fragment shader during a render pass subpass. Unlike standard sampled images, input attachments are restricted to pixel-local access: a fragment shader can only read the texel corresponding directly to the fragment’s current pixel coordinate \((x, y)\) and layer/view index.

This access restriction exists specifically to optimize rendering on tile-based architectures (common in mobile GPUs and modern desktop hardware). Because the reads are constrained to the current pixel, the GPU does not need to flush intermediate color or depth buffers out to system VRAM. Instead, data written in an earlier subpass can remain directly in fast, on-chip tile memory and be sampled immediately by a subsequent subpass, significantly reducing memory bandwidth consumption.

Configuring the Pipeline and Descriptors

To utilize an image as an input attachment, it must be designated appropriately across the render pass, descriptor sets, and pipeline layouts:

  1. Render Pass Setup: In the VkSubpassDescription, the image attachment reference is passed into the pInputAttachments array. The image layout during the subpass must be set to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL or VK_IMAGE_LAYOUT_GENERAL.
  2. Subpass Dependencies: A VkSubpassDependency must be defined between the writing subpass and the reading subpass. The srcAccessMask typically includes VK_ACCESS_COLOR_ATTACHMENT_WRITE_BIT, while the dstAccessMask includes VK_ACCESS_INPUT_ATTACHMENT_READ_BIT, synchronized via VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT.
  3. Descriptor Set Layout: The descriptor type in VkDescriptorSetLayoutBinding is configured as VK_DESCRIPTOR_TYPE_INPUT_ATTACHMENT.

Declaring and Reading in GLSL Fragment Shaders

Within the fragment shader, input attachments are declared using the subpassInput type (or subpassInputMS for multisampled attachments). In addition to the standard set and binding layout qualifiers, each input attachment requires an input_attachment_index qualifier. This index maps directly to the index of the attachment reference in the current subpass’s pInputAttachments array.

Data is fetched using the built-in subpassLoad() function rather than a standard texture sampling function. Because the coordinate is implicit, subpassLoad() does not require texture coordinates.

#version 450

// Binding corresponding to the input attachment descriptor
layout(input_attachment_index = 0, set = 0, binding = 0) uniform subpassInput inputGPosition;
layout(input_attachment_index = 1, set = 0, binding = 1) uniform subpassInput inputGNormal;
layout(input_attachment_index = 2, set = 0, binding = 2) uniform subpassInput inputGAlbedo;

layout(location = 0) out vec4 outFinalColor;

void main() 
{
    // Read the values written at this pixel location in the previous subpass
    vec3 fragPos = subpassLoad(inputGPosition).rgb;
    vec3 normal  = subpassLoad(inputGNormal).rgb;
    vec4 albedo  = subpassLoad(inputGAlbedo);

    // Apply lighting calculations using the fetched G-buffer data
    vec3 lightDir = normalize(vec3(0.0, 10.0, 10.0) - fragPos);
    float diffuse = max(dot(normal, lightDir), 0.0);

    outFinalColor = vec4(albedo.rgb * diffuse, albedo.a);
}

For multisampled targets, subpassInputMS is used along with a sample index parameter:

layout(input_attachment_index = 0, set = 0, binding = 0) uniform subpassInputMS inputColorMS;

void main() 
{
    int sampleIndex = gl_SampleID;
    vec4 sampledValue = subpassLoad(inputColorMS, sampleIndex);
}

Through this mechanism, Vulkan allows fragment shaders to read intermediate frame data efficiently without leaving the local GPU cache.
