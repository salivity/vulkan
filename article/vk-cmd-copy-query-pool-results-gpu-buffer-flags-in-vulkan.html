vkCmdCopyQueryPoolResults GPU Buffer Flags in Vulkan

In the Vulkan graphics and compute API, writing query pool results directly to a GPU buffer without stalling the host CPU is achieved using vkCmdCopyQueryPoolResults. To make this operation valid, the destination VkBuffer must be created with the VK_BUFFER_USAGE_TRANSFER_DST_BIT flag, which designates the buffer as a valid target for transfer operations. Additionally, developers supply VkQueryResultFlags—most notably VK_QUERY_RESULT_WAIT_BIT—to manage synchronization and execution behavior when writing results to the destination buffer.

The Destination Buffer Flag: VK_BUFFER_USAGE_TRANSFER_DST_BIT

The primary flag that enables a VkBuffer to receive query results from vkCmdCopyQueryPoolResults is VK_BUFFER_USAGE_TRANSFER_DST_BIT.

When instantiating the destination buffer via vkCreateBuffer, the usage member of VkBufferCreateInfo must include this bit. Per the Vulkan specification, vkCmdCopyQueryPoolResults operates as a device-side transfer operation. If the buffer is created without VK_BUFFER_USAGE_TRANSFER_DST_BIT, attempting to bind and write into it via vkCmdCopyQueryPoolResults will trigger a validation layer error and result in undefined behavior.

Query Result Flags (VkQueryResultFlagBits)

While VK_BUFFER_USAGE_TRANSFER_DST_BIT is required on the buffer itself, the flags parameter inside vkCmdCopyQueryPoolResults takes a bitmask of VkQueryResultFlagBits. These flags dictate how and when the values are written:

  • VK_QUERY_RESULT_WAIT_BIT: Forces the GPU to wait for the query to become available before writing the results into the destination buffer. Without this flag, if the results are not ready when the command executes, the written values may be undefined or remain unchanged.
  • VK_QUERY_RESULT_64_BIT: Instructs the command to write 64-bit unsigned integers instead of the default 32-bit values.
  • VK_QUERY_RESULT_WITH_AVAILABILITY_BIT: Appends an extra value immediately following the query result indicating whether the query result is available.
  • VK_QUERY_RESULT_PARTIAL_BIT: Allows partial results to be written to the buffer for certain query types if the full result is not yet resolved.

Differences from vkGetQueryPoolResults

Vulkan offers two distinct mechanisms to read back query pool data:

  1. vkGetQueryPoolResults: Executed immediately on the host (CPU). It copies query data directly into host memory pointers, which can cause CPU stalls if waiting for pending GPU work.
  2. vkCmdCopyQueryPoolResults: Recorded into a VkCommandBuffer and executed asynchronously on a GPU queue. It writes data entirely within GPU-accessible memory (VkBuffer), allowing timestamps, occlusion metrics, or pipeline statistics to be consumed directly by downstream shaders or compute dispatches without CPU intervention.
