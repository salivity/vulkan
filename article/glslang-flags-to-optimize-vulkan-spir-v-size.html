Glslang Flags to Optimize Vulkan SPIR-V Size

This article details the primary compiler flags available in the glslang reference compiler (glslangValidator) to reduce SPIR-V binary sizes for Vulkan graphics and compute pipelines. By stripping redundant metadata, eliminating dead code, and enabling integrated size-reduction optimization passes, developers can significantly decrease shader storage requirements, cut down distribution payloads, and improve runtime pipeline caching performance.

Essential Flags for Size Optimization

1. -Os (Optimize for Size)

The -Os flag instructs glslang to run optimization passes specifically targeted at minimizing bytecode size. When built with SPIRV-Tools integration (standard in the Vulkan SDK), this flag invokes a sequence of size-focused transforms. It aggregates uniform structures, merges identical constants, folds redundant operations, and aggressively performs dead code elimination without sacrificing runtime performance.

glslangValidator -V -Os shader.frag -o shader.frag.spv

2. -g0 or -s (Strip Debug Information)

By default, debug symbols such as variable names (OpName), source file listings (OpSource), and line mapping statements (OpLine) are embedded into the output bytecode.

  • Use -g0 to explicitly disable the generation of any debug information.
  • Use -s (strip) to remove symbols and structural debug decorations from the generated SPIR-V binary.

Removing these non-functional instructions provides the largest single-step reduction in binary size, often shrinking unoptimized shaders by 40% to 70%.

glslangValidator -V -g0 -s shader.vert -o shader.vert.spv

3. --target-env vulkan1.x (Target Explicit Environment)

Specifying the precise Vulkan target environment prevents glslang from inserting legacy compatibility workarounds or enabling unnecessary SPIR-V extensions and capabilities.

Supported environments include:

  • --target-env vulkan1.0
  • --target-env vulkan1.1
  • --target-env vulkan1.2
  • --target-env vulkan1.3

Targeting modern Vulkan versions allows the compiler to generate more concise instruction sets (such as native scalar block layouts or simplified descriptor indexing) that translate into smaller binary footprints.

glslangValidator -V1.3 --target-env vulkan1.3 -Os -g0 shader.comp -o shader.comp.spv

Recommended Production Command

To achieve the smallest possible SPIR-V output directly from glslang, combine these flags into a single build command:

glslangValidator -V --target-env vulkan1.3 -Os -g0 -s input.frag -o output.frag.spv

Post-Processing Consideration

While glslang covers primary compilation and size reduction via -Os, further compression can be achieved in a build pipeline by feeding the output into spirv-opt with -Os, followed by spirv-remap to shorten identifier IDs across multiple shader stages.
