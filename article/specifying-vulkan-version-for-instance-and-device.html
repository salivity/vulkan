Specifying Vulkan Version for Instance and Device

Setting the target Vulkan core version is a critical initial step when building a Vulkan application, ensuring that the runtime environment, driver, and GPU support the features your application relies on. This article covers how to determine the highest available instance version, how to specify your requested core version during instance initialization using VkApplicationInfo, how to validate physical device support, and how to enable version-specific core functionality when creating a logical device.

Querying Supported Instance Versions

Before requesting a specific version, you should determine the maximum version supported by the system's Vulkan loader and drivers. Starting in Vulkan 1.1, the runtime provides vkEnumerateInstanceVersion to check this:

uint32_t supportedApiVersion = VK_API_VERSION_1_0;

if (vkEnumerateInstanceVersion != NULL) {
    vkEnumerateInstanceVersion(&supportedApiVersion);
}

If vkEnumerateInstanceVersion returns a version lower than your required core version, the host system cannot satisfy your application's requirements.

Specifying the Version During Instance Creation

To request a core version for your Vulkan instance, populate a VkApplicationInfo structure and assign the desired version to the apiVersion member using the VK_MAKE_API_VERSION macro or predefined aliases such as VK_API_VERSION_1_3.

VkApplicationInfo appInfo = {};
appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO;
appInfo.pApplicationName = "Vulkan Application";
appInfo.applicationVersion = VK_MAKE_VERSION(1, 0, 0);
appInfo.pEngineName = "Custom Engine";
appInfo.engineVersion = VK_MAKE_VERSION(1, 0, 0);
appInfo.apiVersion = VK_API_VERSION_1_3; // Desired core version

VkInstanceCreateInfo createInfo = {};
createInfo.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO;
createInfo.pApplicationInfo = &appInfo;
// Specify extensions and layers as needed...

VkInstance instance;
VkResult result = vkCreateInstance(&createInfo, NULL, &instance);

The apiVersion specified here defines the API version boundary for the instance. Vulkan will return an error (such as VK_ERROR_INCOMPATIBLE_DRIVER) if the driver cannot support the version specified in appInfo.apiVersion.

Validating Physical Device Version Support

An instance capable of Vulkan 1.3 does not guarantee that every attached GPU supports that same version. During physical device selection, inspect the device's properties:

VkPhysicalDeviceProperties properties;
vkGetPhysicalDeviceProperties(physicalDevice, &properties);

if (properties.apiVersion < VK_API_VERSION_1_3) {
    // This GPU does not meet the core version requirement
}

Compare properties.apiVersion against your target version to filter out incompatible hardware before proceeding to logical device creation.

Enabling Core Features at Device Creation

The logical device creation structure, VkDeviceCreateInfo, does not contain an apiVersion field. Instead, core API features introduced in versions such as 1.1, 1.2, and 1.3 are enabled by attaching specific feature structures to the pNext chain of VkDeviceCreateInfo.

To enable features introduced in Vulkan 1.3, configure a VkPhysicalDeviceVulkan13Features struct:

VkPhysicalDeviceVulkan13Features vulkan13Features = {};
vulkan13Features.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_VULKAN_1_3_FEATURES;
vulkan13Features.dynamicRendering = VK_TRUE;
vulkan13Features.synchronization2 = VK_TRUE;

VkDeviceCreateInfo deviceCreateInfo = {};
deviceCreateInfo.sType = VK_STRUCTURE_TYPE_DEVICE_CREATE_INFO;
deviceCreateInfo.pNext = &vulkan13Features;
// Populate queue create infos and required device extensions...

VkDevice device;
VkResult deviceResult = vkCreateDevice(physicalDevice, &deviceCreateInfo, NULL, &device);

By chaining the appropriate version-specific feature structures (e.g., VkPhysicalDeviceVulkan11Features, VkPhysicalDeviceVulkan12Features, VkPhysicalDeviceVulkan13Features) or utilizing VkPhysicalDeviceFeatures2, you explicitly activate the core capabilities standardized within that Vulkan release.
