Vulkan VK_KHR_multiview: Single-Pass Stereo VR

This article explores the purpose and mechanics of the VK_KHR_multiview extension in the Vulkan graphics API, focusing on its role in single-pass stereo rendering for virtual reality (VR). It details how the extension eliminates redundant CPU work, optimizes the GPU graphics pipeline by processing multiple viewpoints in a single draw call, and fundamentally improves frame rate consistency in VR applications.

In traditional VR rendering pipelines, producing a stereoscopic 3D image requires drawing the entire scene twice—once from the perspective of the left eye and once from the right. This dual-pass approach effectively doubles the number of draw calls sent from the CPU to the GPU. For complex scenes with high object counts, the CPU frequently becomes a major bottleneck, struggling to meet the strict latency and refresh rate requirements (typically 90 Hz or higher) essential for preventing motion sickness in VR.

The VK_KHR_multiview extension—which was integrated into the core Vulkan 1.1 specification—solves this problem by allowing a single render pass instance to broadcast primitives across multiple framebuffer layers. Instead of issuing distinct draw calls for each eye, a developer submits geometry once, and Vulkan directs the output to distinct render targets according to a defined view mask.

At the shader level, the extension exposes a built-in variable named gl_ViewIndex (in GLSL) or ViewIndex (in SPIR-V). This index identifies which specific viewpoint is currently being processed. Rather than maintaining separate pipelines or executing distinct shader dispatches, shaders can use gl_ViewIndex to index into an array of view and projection matrices stored in a uniform buffer. The vertex shader can dynamically apply the correct eye transformation based on this index, adjusting vertex positions for both the left and right eyes within the same pass.

By shifting perspective calculations to a single pass, VK_KHR_multiview provides several technical advantages:

  • Drastic CPU Overhead Reduction: The host application only records and submits rendering commands once, effectively cutting draw call counts and driver validation overhead in half.
  • Efficient GPU Caching and State Management: Shared scene resources, such as textures, materials, and constant buffers, remain bound on the GPU across both views, maximizing cache locality and minimizing state changes.
  • Hardware-Accelerated View Replication: Many modern GPU architectures include specialized hardware to replicate geometry across multiple viewports at the primitive stage, avoiding duplicate vertex fetches and transforming operations.

Through these optimizations, VK_KHR_multiview significantly reduces frame generation time and variance, making it an essential tool for achieving stable, high-performance stereo rendering in modern Vulkan-based VR runtimes and applications.
