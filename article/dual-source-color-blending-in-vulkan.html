Dual-Source Color Blending in Vulkan

Dual-source color blending is an advanced rasterization feature that allows a fragment shader to output two separate color vectors to a single render target simultaneously. This article explains the fundamentals of dual-source blending, its primary use cases like subpixel font rendering, how it maps secondary colors in the blending equation, and the precise Vulkan API pipeline configurations and GLSL shader qualifiers needed to implement it.

What is Dual-Source Color Blending?

In standard rasterization, a fragment shader outputs a single color value (the source) per color attachment, which is then blended with the existing value in the framebuffer (the destination). Conventional blending factors—such as source alpha or destination color—allow for transparency and additive effects, but they limit the mathematical complexity of how source and destination data interact.

Dual-source color blending expands this model by allowing a single fragment shader execution to produce two distinct source outputs: a primary color (src0) and a secondary color (src1), both routed to color attachment index 0. This enables advanced blend equations, most notably component-wise alpha blending for subpixel font anti-aliasing (such as ClearType). In subpixel text rendering, the red, green, and blue components of a pixel require independent blending factors rather than a single uniform alpha value. Dual-source blending allows the shader to output the RGB color on the first output and the per-component RGB mask on the second output, completing the blend in a single pass.

Routing Two Fragment Colors to One Render Target

To direct two colors to a single target, Vulkan relies on shader interface binding indices rather than multiple output locations.

GLSL Output Qualifiers

In a standard shader, multiple render targets use distinct location indices. For dual-source blending, both outputs share location = 0, but they are differentiated by an index qualifier:

#version 450

// Primary source color (src0)
layout(location = 0, index = 0) out vec4 outColor;

// Secondary source color (src1)
layout(location = 0, index = 1) out vec4 outSecondaryColor;

void main() {
    outColor = vec4(1.0, 1.0, 1.0, 1.0);          // Base color
    outSecondaryColor = vec4(0.8, 0.5, 0.2, 1.0); // Per-component blend weights
}

The hardware treats index = 0 as the standard source term and index = 1 as the secondary source term. Because physical hardware routing lines are consumed by this secondary output, dual-source blending is typically restricted to the first render target (location = 0), and the total number of simultaneous render targets is reduced.

Vulkan API Implementation

Using dual-source blending in Vulkan requires verifying hardware support, enabling the device feature, and setting up the pipeline blend state.

1. Enabling the Device Feature

Dual-source blending is not enabled by default. Query VkPhysicalDeviceFeatures to ensure dualSrcBlend is supported, then enable it during logical device creation:

VkPhysicalDeviceFeatures deviceFeatures{};
deviceFeatures.dualSrcBlend = VK_TRUE;

VkDeviceCreateInfo createInfo{};
createInfo.sType = VK_STRUCTURE_TYPE_DEVICE_CREATE_INFO;
createInfo.pEnabledFeatures = &deviceFeatures;
// ... populate queues, extensions, and create the VkDevice

2. Configuring the Blend State

When setting up the graphics pipeline, configure the VkPipelineColorBlendAttachmentState for the target attachment. Vulkan provides specific blend factors prefixed with SRC1 to reference the secondary output:

  • VK_BLEND_FACTOR_SRC1_COLOR
  • VK_BLEND_FACTOR_ONE_MINUS_SRC1_COLOR
  • VK_BLEND_FACTOR_SRC1_ALPHA
  • VK_BLEND_FACTOR_ONE_MINUS_SRC1_ALPHA

For example, to implement component-wise text blending where the text color is multiplied by the mask and the destination is subtracted by the mask:

VkPipelineColorBlendAttachmentState blendAttachment{};
blendAttachment.blendEnable = VK_TRUE;
blendAttachment.srcColorBlendFactor = VK_BLEND_FACTOR_ONE;
blendAttachment.dstColorBlendFactor = VK_BLEND_FACTOR_ONE_MINUS_SRC1_COLOR;
blendAttachment.colorBlendOp = VK_BLEND_OP_ADD;
blendAttachment.srcAlphaBlendFactor = VK_BLEND_FACTOR_ONE;
blendAttachment.dstAlphaBlendFactor = VK_BLEND_FACTOR_ONE_MINUS_SRC1_ALPHA;
blendAttachment.alphaBlendOp = VK_BLEND_OP_ADD;
blendAttachment.colorWriteMask = VK_COLOR_COMPONENT_R_BIT | 
                                VK_COLOR_COMPONENT_G_BIT | 
                                VK_COLOR_COMPONENT_B_BIT | 
                                VK_COLOR_COMPONENT_A_BIT;

In this setup, the hardware takes the primary color (index = 0), multiplies it by VK_BLEND_FACTOR_ONE, and blends it with the destination color multiplied by 1.0 - index = 1, achieving precise component-level compositing in a single draw call.
