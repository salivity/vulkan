Vulkan Indirect Draws: Instance IDs and Draw Parameters

Indirect drawing in Vulkan offloads draw call generation to the GPU, enabling massive draw batching without CPU intervention. However, because commands execute from indirect buffers rather than direct CPU dispatches, shaders require built-in draw parameters to track which object is being rendered. By exposing hardware-level parameters like draw call indices and instance offsets directly to SPIR-V, Vulkan allows shaders to compute globally unique identifiers for every instance, facilitating direct indexing into storage buffers and descriptor arrays for per-instance transforms and material data.

The Indirect Rendering Challenge

When executing direct draw calls, developers typically update push constants or rebind descriptor sets to provide unique data to individual meshes. With functions like vkCmdDrawIndirect and vkCmdDrawIndexedIndirect—especially when driven by drawCount buffers via vkCmdDrawIndirectCount—thousands of draw calls execute in a single GPU-driven pipeline.

Because the CPU is bypassed, uniform state cannot be rebound between these batched operations. Shaders must dynamically infer where their instance fits within the broader render pass using data exposed by the execution pipeline.

Key Built-in Shader Variables

Vulkan handles instance and draw identification through specific SPIR-V execution built-ins, standard in Vulkan 1.2 through the shaderDrawParameters feature (previously available in Vulkan 1.1 or via the VK_KHR_shader_draw_parameters extension):

  1. gl_InstanceIndex (SPIR-V: InstanceIndex): Unlike OpenGL’s gl_InstanceID, which always begins at zero for each draw call, Vulkan’s gl_InstanceIndex includes the firstInstance offset defined in the indirect draw command structure (VkDrawIndirectCommand or VkDrawIndexedIndirectCommand). The value is calculated as: \[\text{gl\_InstanceIndex} = \text{firstInstance} + \text{current instance offset}\]

  2. gl_DrawID (SPIR-V: DrawIndex): When issuing multi-draw indirect calls, gl_DrawID provides the zero-based index of the specific draw command currently executing within the indirect buffer. If an indirect buffer contains 500 commands, gl_DrawID ranges from 0 to 499.

  3. gl_BaseInstance (SPIR-V: BaseInstance): This parameter retrieves the raw firstInstance integer that was populated in the indirect command structure.

Calculating Unique Identifiers in the Shader

Depending on how scene data is organized in GPU buffers, shaders can resolve identifiers in two distinct ways:

1. Flat Global Indexing via firstInstance

If the application allocates a single large buffer containing all instance data across every draw call, the indirect command generator can assign each draw call a unique firstInstance offset. Because gl_InstanceIndex naturally incorporates this base offset, it can be used directly as a global array index:

// GLSL Vertex Shader
layout(std430, set = 0, binding = 0) readonly buffer InstanceBuffer {
    mat4 modelMatrices[];
};

void main() {
    // gl_InstanceIndex inherently equals (firstInstance + instanceOffset)
    mat4 model = modelMatrices[gl_InstanceIndex];
    gl_Position = ubo.viewProj * model * vec4(inPosition, 1.0);
}

2. Multi-Draw Structuring via gl_DrawID

When data is organized by draw call—such as having an array of meshes where each mesh holds an array of instances—shaders use gl_DrawID to locate the draw command and derive the local instance index to find the specific transform:

#extension GL_ARB_shader_draw_parameters : enable

layout(std430, set = 0, binding = 0) readonly buffer DrawBuffer {
    DrawData draws[];
};

void main() {
    // Derive the local zero-based instance index for this specific draw
    uint localInstanceID = gl_InstanceIndex - gl_BaseInstance;

    DrawData currentDraw = draws[gl_DrawID];
    mat4 model = currentDraw.instanceMatrices[localInstanceID];

    gl_Position = ubo.viewProj * model * vec4(inPosition, 1.0);
}

Enabling the Required Vulkan Features

To access gl_DrawID and base parameter offsets, the Vulkan application must query and enable the capability during device creation:

  • Vulkan 1.2+: Set shaderDrawParameters = VK_TRUE in VkPhysicalDeviceVulkan11Features (chained to VkDeviceCreateInfo).
  • Vulkan 1.1: Enable the VK_KHR_shader_draw_parameters device extension.

In the shader code, enable the corresponding extension if targeting GLSL:

#extension GL_ARB_shader_draw_parameters : require

Through this mechanism, the GPU seamlessly correlates the hardware-driven indirect command buffer with the shader's internal addressing logic, ensuring that high-throughput, compute-generated draw calls map correctly to memory.
