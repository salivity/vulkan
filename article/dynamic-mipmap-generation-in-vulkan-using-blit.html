Dynamic Mipmap Generation in Vulkan Using Blit

Dynamic mipmap generation in Vulkan allows developers to generate lower-resolution levels of detail directly on the GPU at runtime rather than pre-computing them on the CPU or loading pre-baked mip chains from disk. This process utilizes the vkCmdBlitImage command inside an iterative loop, leveraging hardware downsampling and synchronization barriers to successively copy, filter, and transition each mip level from the one before it until the entire texture chain is complete and ready for shader sampling.

Prerequisites and Format Capabilities

Before initiating dynamic mipmap generation, the target VkImage must be created with specific usage flags: VK_IMAGE_USAGE_TRANSFER_SRC_BIT, VK_IMAGE_USAGE_TRANSFER_DST_BIT, and VK_IMAGE_USAGE_SAMPLED_BIT. The total number of mip levels is calculated based on the base dimensions:

\[\text{mipLevels} = \lfloor\log_2(\max(\text{width}, \text{height}))\rfloor + 1\]

Because vkCmdBlitImage relies on hardware filtering, you must verify that the physical device supports linear filtering for the chosen format as a blit destination and source. Query this using vkGetPhysicalDeviceFormatProperties and check the optimalTilingFeatures field for both VK_FORMAT_FEATURE_BLIT_SRC_BIT and VK_FORMAT_FEATURE_BLIT_DST_BIT, along with VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT. If linear blitting is unsupported, alternative approaches such as custom compute shaders or software generation must be used.

The Blit Loop Mechanism

Once the base texture data (mip level 0) is transferred from a staging buffer into the image, all mip levels exist in the VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL layout. Generating the remaining levels requires processing them sequentially from level 1 to mipLevels - 1.

For each mip level \(i\) (where \(i\) ranges from 1 to \(\text{mipLevels} - 1\)):

  1. Transition Source Level (\(i - 1\)): A pipeline barrier (vkCmdPipelineBarrier) transitions level \(i - 1\) from VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL to VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL. The barrier specifies srcAccessMask = VK_ACCESS_TRANSFER_WRITE_BIT and dstAccessMask = VK_ACCESS_TRANSFER_READ_BIT, using VK_PIPELINE_STAGE_TRANSFER_BIT for both source and destination stages.

  2. Execute the Blit: Populate a VkImageBlit struct defining the source and destination regions:

    • Source coordinates: From (0, 0, 0) to (mipWidth, mipHeight, 1) at mipLevel = i - 1.
    • Destination coordinates: From (0, 0, 0) to (nextMipWidth, nextMipHeight, 1) at mipLevel = i, where each dimension is calculated as \(\max(1, \lfloor\text{currentDimension} / 2\rfloor)\).

    Invoke vkCmdBlitImage, specifying VK_FILTER_LINEAR for the filter parameter. This instructs the GPU's fixed-function texture hardware to filter and downsample the source region into the destination region.

  3. Transition Source Level (\(i - 1\)) to Shader Read: A second pipeline barrier transitions level \(i - 1\) from VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL. The access mask transitions from VK_ACCESS_TRANSFER_READ_BIT to VK_ACCESS_SHADER_READ_BIT, and the pipeline stage transitions from VK_PIPELINE_STAGE_TRANSFER_BIT to VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT.

  4. Dimension Reduction: Update the width and height trackers by dividing them by 2 (ensuring values do not drop below 1) for the next iteration.

Finalizing the Chain

The final mip level (mipLevels - 1) never acts as a blit source; it only serves as the destination for the final blit. As a result, it remains in VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL after the loop completes.

A final pipeline barrier must be submitted specifically for mipLevels - 1, transitioning it from VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL to VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL. This barrier uses:

  • srcAccessMask = VK_ACCESS_TRANSFER_WRITE_BIT
  • dstAccessMask = VK_ACCESS_SHADER_READ_BIT
  • srcStageMask = VK_PIPELINE_STAGE_TRANSFER_BIT
  • dstStageMask = VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT

Once this command buffer is submitted and execution finishes on the GPU queue, every subresource level within the VkImage will reside in VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL, completely initialized and synchronized for rendering pipelines.
