Vulkan Ray Query vs Full Ray Tracing Pipeline

Hardware-accelerated ray tracing in Vulkan is exposed through two distinct mechanisms: the dedicated ray tracing pipeline (VK_KHR_ray_tracing_pipeline) and inline ray queries (VK_KHR_ray_query). While both interfaces traverse identical bounding volume hierarchy (BVH) acceleration structures, they differ fundamentally in execution model, shader dispatch, memory overhead, and scheduling control. This article contrasts how inline ray traversal compares against full pipeline dispatch, outlining their architectural tradeoffs, performance profiles, and ideal use cases.

Execution Model and Pipeline Architecture

The Ray Tracing Pipeline introduces a dedicated, asynchronous execution model using specialized shader stages: Ray Generation, Intersection, Any-Hit, Closest-Hit, Miss, and Callable shaders. Work is dispatched using vkCmdTraceRaysKHR. The driver and GPU hardware handle the traversal loop, dynamic thread dispatch, and execution state switching. When a ray hits geometry, the system automatically resolves the appropriate Closest-Hit or Any-Hit shader based on records in the Shader Binding Table (SBT).

In contrast, Ray Query provides inline ray traversal capabilities inside existing shader stages, including compute, fragment, vertex, and mesh shaders. Instead of dispatching a specialized pipeline via vkCmdTraceRaysKHR, execution remains within standard commands like vkCmdDraw or vkCmdDispatch. Traversal is driven imperatively within the shader code using intrinsic objects and functions that initialize the query, step through the BVH, and process intersection candidates explicitly.

Shader Binding Table and Setup Complexity

A primary differentiator is runtime and setup complexity:

  • Ray Tracing Pipeline: Requires creating complex VkRayTracingPipelineCreateInfoKHR structures and managing a Shader Binding Table (SBT). The SBT maps geometry instances to specific shader handles and parameters in device memory. Managing SBT alignment, stride requirements, and resource binding across dozens of unique materials requires significant boilerplate and memory management.
  • Ray Query: Bypasses the SBT entirely. The ray query is treated like an intrinsic variable inside a standard shader. Shaders access global buffers, bindless descriptor arrays, or push constants to resolve materials and data. This drastically lowers integration friction and pipeline creation overhead.

Scheduling, Divergence, and Coherence

Hardware handling of thread coherence and divergence varies significantly between both approaches:

  • Thread Scheduling: Ray tracing pipelines allow the hardware scheduler to reorganize and sort rays (on architectures that support shader execution reordering) to maintain SIMD coherence across complex hit shaders. Rays can spawn recursively (up to hardware limits) or chain secondary rays through separate stages.
  • SIMD Divergence: Ray queries execute strictly inside the invoking shader's execution lane. If adjacent threads within a warp or wavefront trace divergent rays (e.g., rays going in opposite directions or hitting widely different BVH depths), the entire warp stalls until all lanes finish their inline traversal loop. Ray queries offer no native execution reordering across threads.

Traversal Control

Ray queries grant fine-grained, manual control over the traversal process. A developer can choose between a fully unrolled loop that yields control only on potential hits (useful for procedural geometry or manual alpha testing) or a fast, opaque traversal that runs to completion. Ray queries also allow early exits and conditional branching directly in the middle of standard rendering logic.

Ray tracing pipelines delegate traversal control to the hardware. Traversal logic is fragmented across discrete stages, making it impossible to inline mid-shader checks without completing a hit or miss pass.

Optimal Use Cases

  • Use Ray Queries for:
    • Screen-space shadows, ambient occlusion, and simple visibility checks.
    • Adding ray-traced validation to existing rasterization pipelines (e.g., in a deferred lighting fragment shader or compute pass).
    • Direct probing and sound propagation in compute workloads.
    • Scenarios where materials are homogeneous, or where standard bindless textures can quickly resolve surface hits without distinct hit shaders.
  • Use Ray Tracing Pipelines for:
    • Full path tracers and multi-bounce global illumination.
    • Scenes with highly diverse shading models and materials that benefit from isolated Closest-Hit shaders.
    • Complex geometry requiring dynamic custom intersections and procedural primitives.
    • Primary visibility replacement where the SBT acts as a dynamic rasterization substitute.
