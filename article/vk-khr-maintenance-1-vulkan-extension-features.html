VK_KHR_maintenance1 Vulkan Extension Features

The VK_KHR_maintenance1 extension is a collection of minor features, clarifications, and quality-of-life adjustments for the Vulkan API that was later promoted to the core Vulkan 1.1 specification. This extension addressed several practical limitations encountered by developers after Vulkan's initial launch, introducing inverted viewports for coordinate system alignment, 2D views for 3D textures, more flexible image copy constraints, and dedicated memory error codes.

Negative Viewport Heights (Y-Axis Inversion)

Before VK_KHR_maintenance1, Vulkan strictly required the height member of VkViewport to be positive, enforcing Vulkan’s default normalized device coordinate (NDC) system where the Y-axis points downwards. This extension allows VkViewport::height to be negative. Setting a negative height and offsetting the y coordinate inverts the viewport along the Y-axis, enabling developers to map Vulkan’s screen coordinates to match APIs like DirectX or OpenGL without needing to flip geometry inside vertex shaders or alter front-face winding rules.

2D Array Views of 3D Images

The extension introduced the VK_IMAGE_CREATE_2D_ARRAY_COMPATIBLE_BIT image creation flag. When this flag is enabled on a 3D image (VK_IMAGE_TYPE_3D), developers can create VK_IMAGE_VIEW_TYPE_2D and VK_IMAGE_VIEW_TYPE_2D_ARRAY image views from it. This allows individual depth slices of a 3D volume texture to be bound and manipulated as independent 2D render targets or texture inputs without copying data.

Relaxed Image Copying Constraints

VK_KHR_maintenance1 updated vkCmdCopyImage rules to allow transfers between images of different formats, as long as the formats share the same texel block size and are compatible within the same format class (such as copying between uncompressed formats of identical bit depth, or between compressed and uncompressed representations of matching block sizes).

Dedicated Descriptor Pool Error Code

Prior to this extension, exhausting memory inside a VkDescriptorPool during allocation would typically return generic errors such as VK_ERROR_OUT_OF_DEVICE_MEMORY or VK_ERROR_FRAGMENTED_POOL. The extension introduced the explicit return code VK_ERROR_OUT_OF_POOL_MEMORY, allowing applications to accurately identify when a descriptor pool needs to be grown or freed.

Secondary Command Buffer Query Inheritance

The extension clarified and expanded how queries operate across command buffer boundaries. It allows secondary command buffers to inherit pipeline statistics queries from primary command buffers, ensuring continuous query measurement without manually stopping and restarting queries across buffer boundaries.
