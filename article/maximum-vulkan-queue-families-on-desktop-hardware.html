Maximum Vulkan Queue Families on Desktop Hardware

This article examines the maximum number of queue families that can be queried via the Vulkan graphics and compute API on modern desktop hardware. While the Vulkan specification technically permits an arbitrary number governed only by integer capacity, standard consumer desktop GPUs from NVIDIA, AMD, and Intel realistically expose between 3 and 5 distinct queue families, rarely exceeding 8 even when specialized multimedia and optical flow engines are exposed.

The API Specification vs. Hardware Reality

In the Vulkan API, queue families are queried using the function vkGetPhysicalDeviceQueueFamilyProperties. The count parameter passed to this function is an unsigned 32-bit integer (uint32_t). Theoretically, the Vulkan specification sets no arbitrary hard ceiling on the number of queue families an implementation can expose, meaning the programmatic limit is \(2^{32} - 1\).

In practice, physical silicon design strictly dictates this number. A queue family represents a group of queues with identical capabilities and execution properties mapped to physical hardware engines on the GPU. Because desktop GPUs only possess a discrete set of execution engines, drivers expose only a few distinct families.

Queue Family Counts on Desktop GPUs

On standard consumer desktop platforms running modern drivers, the typical queue family counts are distributed as follows:

  • NVIDIA (GeForce GTX / RTX): Typically exposes 3 to 5 queue families. These generally include:
    1. A primary universal family supporting Graphics, Compute, and Transfer.
    2. A dedicated Transfer (DMA) family for asynchronous data uploads.
    3. An Async Compute family.
    4. Specialized families for hardware video decoding, encoding, or optical flow (depending on driver version and extension support).
  • AMD (Radeon RX series): Typically exposes 4 to 5 queue families. These generally cover:
    1. A universal Graphics/Compute/Transfer family.
    2. Dedicated Asynchronous Compute families (often mapped to hardware Asynchronous Compute Engines or ACEs).
    3. Dedicated Transfer/DMA copy engines.
    4. Video decode and encode queues (via Vulkan Video extensions).
  • Intel (Arc Graphics): Typically exposes 2 to 4 queue families, dividing workloads between the main render/compute pipeline, dedicated compute engines, transfer/copy blitters, and media processing.

Why the Number Remains Low

Hardware manufacturers keep the number of queue families low because each family represents fundamentally different hardware scheduling pipelines. Granular parallelism is achieved by allocating multiple individual queues within a single queue family—such as multiple compute queues—rather than creating an excessive number of separate families. Consequently, standard desktop systems virtually never expose more than a single-digit number of queue families.
