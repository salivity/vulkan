Vulkan Present Modes Latency and Tearing Guide

In the Vulkan graphics API, present modes govern how rendered images in a swapchain are queued and delivered to the physical display device. Selecting the right present mode is the primary mechanism developers use to balance input latency against visual artifacts like screen tearing. This guide examines how the three primary Vulkan present modes—VK_PRESENT_MODE_FIFO_KHR, VK_PRESENT_MODE_MAILBOX_KHR, and VK_PRESENT_MODE_IMMEDIATE_KHR—interact with the display refresh cycle, directly impacting frame pacing, display lag, and image integrity.

Understanding the Presentation Engine and V-Blank

To understand present modes, it is essential to understand the vertical blanking interval (V-Blank). Displays refresh sequentially line by line, typically from top to bottom. V-Blank is the brief interval between the completion of one full scanout and the beginning of the next. Screen tearing occurs when a new frame is copied to the display buffer mid-scanout, resulting in the top half showing an older frame and the bottom half showing a newer one.

VK_PRESENT_MODE_FIFO_KHR

VK_PRESENT_MODE_FIFO_KHR acts as a strict First-In, First-Out queue and is the only mode guaranteed by the Vulkan specification to be supported on all compliant platforms.

  • How it works: When the GPU finishes rendering an image, the image is appended to the back of the presentation queue. The display engine removes an image from the front of the queue only during a V-Blank interval. If the queue is full when the application requests another presentation, the application's thread is blocked until an image is consumed.
  • Tearing: Nonexistent. Because swaps only occur during V-Blank, screen tearing is entirely eliminated.
  • Display Latency: High. This mode represents standard V-Sync. If the queue contains multiple frames (e.g., a double- or triple-buffered swapchain), an action taken by a user might sit in the queue for two or three display refresh cycles before appearing on screen. Furthermore, if the application renders faster than the display's refresh rate, it will stall, introducing significant input lag.

VK_PRESENT_MODE_IMMEDIATE_KHR

VK_PRESENT_MODE_IMMEDIATE_KHR is the rawest presentation path available in Vulkan, bypassing synchronization mechanisms entirely.

  • How it works: As soon as an image is ready, it is sent straight to the display pipeline without waiting for the next V-Blank interval. There is no queue; rendering can swap into the active scanout buffer instantly.
  • Tearing: Severe and frequent. Because the presentation engine updates the frame buffer whenever the GPU finishes rendering, buffer swaps regularly happen halfway through a display scanout, producing visible horizontal tear lines.
  • Display Latency: Lowest possible. Because frames are not held in a queue or delayed until a refresh interval, the time between a completed frame and its visual output is minimized. This mode is favored in competitive gaming contexts where twitch reaction times are prioritized over visual cohesion.

VK_PRESENT_MODE_MAILBOX_KHR

VK_PRESENT_MODE_MAILBOX_KHR—often referred to as fast sync or non-blocking triple buffering—is an optimal middle ground that reduces latency while avoiding visual artifacts.

  • How it works: Like FIFO, images are only presented to the display during the V-Blank interval. However, unlike FIFO, the queue holds a single active pending slot. If the application finishes rendering a new frame while a previous frame is already waiting in the queue, the newer frame overwrites (replaces) the older one.
  • Tearing: Nonexistent. Frame swaps remain synchronized with the display's V-Blank interval.
  • Display Latency: Low. The application is never blocked by a full queue; it can render as fast as the hardware allows. When the monitor is ready to refresh, it displays the most recent completely rendered frame available, significantly reducing input delay compared to standard FIFO. The main trade-off is higher GPU utilization and power consumption, as frames that are rendered and overwritten are never seen by the user.

Summary Comparison

  • FIFO: Guarantees zero tearing, supported everywhere, but introduces the highest input latency and can cap frame generation.
  • Immediate: Minimizes latency entirely, but introduces constant screen tearing across variable frame rates.
  • Mailbox: Guarantees zero tearing while offering low latency by replacing stale frames, but consumes more energy and is not supported by every hardware platform.
