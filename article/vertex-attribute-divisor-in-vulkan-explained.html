Vertex Attribute Divisor in Vulkan Explained

This article explores the vertex attribute divisor in Vulkan and demonstrates how it controls the stepping rate of vertex buffer data across multiple instances. Readers will learn the operational mechanics of Vulkan's vertex input rates, how the VK_KHR_vertex_attribute_divisor extension (and Vulkan 1.4 core feature) alters data fetching, and the practical use cases for customizing instance stepping rates in graphics pipelines.

Understanding Vertex Input Rates in Vulkan

In Vulkan, the fixed-function vertex input stage reads vertex data from bound VkBuffer resources based on bindings and attributes defined in VkPipelineVertexInputStateCreateInfo. By default, the VkVertexInputBindingDescription structure provides two modes via the inputRate member:

  • VK_VERTEX_INPUT_RATE_VERTEX: The buffer offset advances by the specified stride for each vertex processed within a primitive.
  • VK_VERTEX_INPUT_RATE_INSTANCE: The buffer offset advances by the specified stride for each instance processed during an instanced draw command (such as vkCmdDraw or vkCmdDrawIndexed).

In standard instancing, every single instance advances the buffer reading position by one stride. While suitable for uniquely transformed objects, this 1:1 relationship between instance index and attribute data becomes restrictive when instances share specific parameters.

What Is a Vertex Attribute Divisor?

A vertex attribute divisor specifies the frequency at which vertex attributes bound at VK_VERTEX_INPUT_RATE_INSTANCE advance relative to the rendered instance index. Instead of advancing to the next data element on every single instance, the divisor determines that the offset advances only once every N instances.

Mathematically, when fetching an attribute from an instance-rate buffer with a divisor \(D\), the data element index accessed for an instance with index \(I\) is calculated as:

\[\text{Element Index} = \left\lfloor \frac{I}{D} \right\rfloor\]

Depending on the value assigned to the divisor, different behaviors occur:

  • Divisor = 1: The default behavior. The buffer advances by one stride for every new instance (\(I / 1 = I\)).
  • Divisor = \(N\) (\(N > 1\)): The attribute advances only after every \(N\) instances. For example, with a divisor of 4, instances 0, 1, 2, and 3 all read from element index 0; instances 4, 5, 6, and 7 read from element index 1.
  • Divisor = 0: The attribute does not advance at all with subsequent instances. All instances in the draw call access element index 0.

Configuring the Divisor in Vulkan

Support for vertex attribute divisors is provided through the VK_KHR_vertex_attribute_divisor extension (or previously VK_EXT_vertex_attribute_divisor), and is integrated directly into Vulkan 1.4.

To implement a divisor, the application extends VkPipelineVertexInputStateCreateInfo by chaining VkPipelineVertexInputDivisorStateCreateInfoKHR through the pNext pointer:

VkVertexInputBindingDivisorDescriptionKHR divisorDescription{};
divisorDescription.binding = 1; // The instance buffer binding
divisorDescription.divisor = 4; // Advance every 4 instances

VkPipelineVertexInputDivisorStateCreateInfoKHR divisorState{};
divisorState.sType = VK_STRUCTURE_TYPE_PIPELINE_VERTEX_INPUT_DIVISOR_STATE_CREATE_INFO_KHR;
divisorState.pNext = nullptr;
divisorState.bindingDivisorCount = 1;
divisorState.pBindingDivisors = &divisorDescription;

VkPipelineVertexInputStateCreateInfo vertexInputInfo{};
vertexInputInfo.sType = VK_STRUCTURE_TYPE_PIPELINE_VERTEX_INPUT_STATE_CREATE_INFO;
vertexInputInfo.pNext = &divisorState;
// Populate remaining vertex input descriptions...

Hardware Capabilities and Constraints

Before configuring divisors, applications must query hardware support using VkPhysicalDeviceVertexAttributeDivisorFeaturesKHR and VkPhysicalDeviceVertexAttributeDivisorPropertiesKHR. Hardware constraints include:

  • vertexAttributeInstanceRateDivisor: A boolean flag indicating whether divisors greater than 1 are supported.
  • vertexAttributeInstanceRateZeroDivisor: A boolean flag indicating whether a divisor value of 0 is permitted.
  • maxVertexAttribDivisor: The maximum supported integer value for a divisor on the underlying physical device.

Common Use Cases

  • Multi-Part Instanced Geometry: Rendering complex meshes composed of multiple distinct sub-meshes where parts share spatial properties, such as a localized group of foliage models sharing identical wind or lighting parameters.
  • Hierarchical Instancing: Simulating hierarchical structures where clusters of instances share parent transformation matrices, while maintaining their own local offsets.
  • Global Overrides via Zero Divisor: Supplying draw-call-wide constant parameters through vertex buffers without modifying descriptor sets, push constants, or uniform buffers.
