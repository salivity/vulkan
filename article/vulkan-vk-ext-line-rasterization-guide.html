Vulkan VK_EXT_line_rasterization Guide

The VK_EXT_line_rasterization device extension solves cross-vendor rendering discrepancies in Vulkan by providing explicit, standardized control over how lines are rasterized. By exposing configurable rasterization modes, this extension allows developers to explicitly select between Bresenham lines, smooth anti-aliased lines, and rectangular lines, while also adding optional support for line stippling. This eliminates the unpredictability of core Vulkan's implementation-dependent line rendering and ensures visual consistency across different GPU hardware.

Why VK_EXT_line_rasterization Is Needed

In the core Vulkan specification, line rasterization is loosely defined. Hardware vendors historically implemented line drawing using different techniques—such as converting lines to screen-aligned quads or using hardware Bresenham engines. This produced inconsistent visual results, varying line widths, and differing pixel-coverage rules across AMD, NVIDIA, Intel, and mobile GPUs.

The VK_EXT_line_rasterization extension resolves this problem by introducing VkLineRasterizationModeEXT, which allows developers to bypass default driver heuristics and dictate exact rasterization behavior inside the graphics pipeline.

Supported Line Rasterization Modes

The extension defines four distinct modes via the VkLineRasterizationModeEXT enumeration:

  1. VK_LINE_RASTERIZATION_MODE_DEFAULT_EXT
    Retains standard, implementation-defined line rasterization as specified by core Vulkan. This offers no consistency guarantees across different devices.

  2. VK_LINE_RASTERIZATION_MODE_RECTANGULAR_EXT
    Treats lines as geometric rectangles extruded along the line segment by a specified width perpendicular to the line vector. Fragments are generated if their sample points fall inside the resulting screen-space bounding box. This mode supports widths other than 1.0 (subject to device limits) and works seamlessly with standard Multisample Anti-Aliasing (MSAA).

  3. VK_LINE_RASTERIZATION_MODE_BRESENHAM_EXT
    Renders lines using classic grid-based algorithms adhering to the strict diamond-exit rule. This produces aliased, single-pixel-wide segments that match legacy CAD applications, DirectX 9, and OpenGL standard line behaviors. Bresenham lines guarantee that exactly one fragment is produced per column or row (depending on slope), avoiding overdraw or gaps at segment joints. Line width for this mode is fixed at 1.0.

  4. VK_LINE_RASTERIZATION_MODE_RECTANGULAR_SMOOTH_EXT
    Extrudes lines as rectangular regions but computes fragment coverage based on the distance between the fragment center and the line segment. The resulting coverage value modulates the fragment’s output alpha channel, producing smooth, anti-aliased edges without requiring MSAA targets. This mimics legacy OpenGL smoothed lines (GL_LINE_SMOOTH).

Checking Device Capabilities

Hardware support must be verified at runtime by querying VkPhysicalDeviceLineRasterizationFeaturesEXT through vkGetPhysicalDeviceFeatures2:

  • rectangularLines: Indicates whether rectangular line rasterization is supported.
  • bresenhamLines: Indicates support for diamond-exit Bresenham lines.
  • smoothLines: Indicates support for alpha-coverage smooth lines.
  • stippledRectangularLines, stippledBresenhamLines, stippledSmoothLines: Indicate support for dashed or dotted pattern generation on the respective modes.

Developers must enable these feature booleans in the pNext chain of VkDeviceCreateInfo when creating the logical device.

Pipeline Configuration

To activate a specific rasterization mode, append a VkPipelineRasterizationLineStateCreateInfoEXT structure to the pNext chain of VkPipelineRasterizationStateCreateInfo during graphics pipeline creation:

VkPipelineRasterizationLineStateCreateInfoEXT lineRasterState = {};
lineRasterState.sType = VK_STRUCTURE_TYPE_PIPELINE_RASTERIZATION_LINE_STATE_CREATE_INFO_EXT;
lineRasterState.lineRasterizationMode = VK_LINE_RASTERIZATION_MODE_BRESENHAM_EXT;
lineRasterState.stippledLineEnable = VK_FALSE;

VkPipelineRasterizationStateCreateInfo rasterInfo = {};
rasterInfo.sType = VK_STRUCTURE_TYPE_PIPELINE_RASTERIZATION_STATE_CREATE_INFO;
rasterInfo.pNext = &lineRasterState;
rasterInfo.lineWidth = 1.0f;
// ... other rasterization parameters

Line Stippling Support

In addition to rasterization shapes, the extension restores legacy line stippling (patterned or dashed rendering). When stippledLineEnable is set to VK_TRUE, developers configure the pattern using:

  • lineStippleFactor: An integer multiplier between 1 and 256 that stretches each bit of the pattern.
  • lineStipplePattern: A 16-bit mask dictating which fragments along the line segment are drawn or discarded.

If VK_DYNAMIC_STATE_LINE_STIPPLE_EXT is included in the pipeline’s dynamic state array, the stipple properties can be altered at draw time without pipeline recompilation using the vkCmdSetLineStippleEXT command.
