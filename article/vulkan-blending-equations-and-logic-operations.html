Vulkan Blending Equations and Logic Operations

In the Vulkan graphics API, color blending controls how fragment shader outputs are combined with values already present in a framebuffer attachment. This article provides an overview of how Vulkan configures this stage using fixed-function pipeline states, detailing the setup of arithmetic color blending equations, blend factors, color write masks, and alternative bitwise logic operations.

The Pipeline Color Blend State

Blending configuration in Vulkan is divided between global pipeline settings and per-attachment configurations. The VkPipelineColorBlendStateCreateInfo structure defines the overall stage for a VkGraphicsPipelineCreateInfo setup. It contains a pointer to an array of VkPipelineColorBlendAttachmentState structs—one for each color attachment bound to the render pass subpass—as well as global parameters for logic operations and blend constants.

Configuring Arithmetic Color Blending Equations

When blendEnable is set to VK_TRUE inside a VkPipelineColorBlendAttachmentState, Vulkan applies arithmetic blending to combine the fragment shader output (source) with the target framebuffer pixel (destination).

Color channels (RGB) and the alpha channel (A) are evaluated independently using their own configurable blend factors and operations:

  • Source and Destination Factors: Represented by VkBlendFactor, these factors scale the input components. Common choices include VK_BLEND_FACTOR_SRC_ALPHA, VK_BLEND_FACTOR_ONE_MINUS_SRC_ALPHA, VK_BLEND_FACTOR_ONE, and VK_BLEND_FACTOR_ZERO. You can also supply custom RGBA values using VK_BLEND_FACTOR_CONSTANT_COLOR, which utilizes the four-element float array blendConstants defined in VkPipelineColorBlendStateCreateInfo.
  • Blend Operations: Represented by VkBlendOp, these define how the scaled source and destination are mathematically combined. Standard operations include:
    • VK_BLEND_OP_ADD: (source * srcFactor) + (destination * dstFactor)
    • VK_BLEND_OP_SUBTRACT: (source * srcFactor) - (destination * dstFactor)
    • VK_BLEND_OP_REVERSE_SUBTRACT: (destination * dstFactor) - (source * srcFactor)
    • VK_BLEND_OP_MIN: min(source, destination)
    • VK_BLEND_OP_MAX: max(source, destination)

A standard implementation of alpha-blending sets srcColorBlendFactor to VK_BLEND_FACTOR_SRC_ALPHA, dstColorBlendFactor to VK_BLEND_FACTOR_ONE_MINUS_SRC_ALPHA, and colorBlendOp to VK_BLEND_OP_ADD.

Color Write Masks

Regardless of whether blending is enabled, each attachment specifies a colorWriteMask composed of VkColorComponentFlagBits (VK_COLOR_COMPONENT_R_BIT, G_BIT, B_BIT, A_BIT). This bitmask acts as a filter, allowing developers to disable writes to specific color channels in the target framebuffer.

Configuring Logic Operations

Vulkan allows arithmetic blending to be substituted with bitwise logic operations. To use this feature:

  1. The device must support logic operations, verified through the logicOp boolean in VkPhysicalDeviceFeatures.
  2. In VkPipelineColorBlendStateCreateInfo, set logicOpEnable to VK_TRUE.
  3. Select an operation via the logicOp field using an enumerator from VkLogicOp, such as VK_LOGIC_OP_CLEAR, VK_LOGIC_OP_AND, VK_LOGIC_OP_OR, VK_LOGIC_OP_XOR, or VK_LOGIC_OP_INVERT.

Enabling logic operations overrides arithmetic blending across all bound attachments, applying the chosen bitwise manipulation directly between the raw binary representations of the fragment color and the framebuffer contents. Logic operations are only valid for framebuffers with signed or unsigned integer formats, or normalized integer formats.
