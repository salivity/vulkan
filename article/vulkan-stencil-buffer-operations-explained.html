Vulkan Stencil Buffer Operations Explained

This article provides an overview of how Vulkan evaluates depth-stencil states, detailing the execution pipeline of stencil testing, how stencil operations interact with depth test results, and the exact mechanics of operations such as keep, replace, and increment within the VkPipelineDepthStencilStateCreateInfo configuration.

The Stencil Evaluation Pipeline

In Vulkan, stencil testing occurs during the per-fragment operations stage of the graphics pipeline, tightly coupled with depth testing. When a fragment is generated, its stencil evaluation is governed by comparing a reference value to the value already stored in the framebuffer's stencil attachment.

The evaluation relies on a three-stage outcome condition:

  1. Stencil Fail: The stencil test itself fails.
  2. Stencil Pass, Depth Fail: The stencil test passes, but the subsequent depth test fails.
  3. Depth-Stencil Pass: Both the stencil test and the depth test pass (or depth testing is disabled).

Vulkan evaluates these conditions independently for front-facing and back-facing polygons using separate VkStencilOpState structures (front and back) defined within VkPipelineDepthStencilStateCreateInfo.

Stencil Comparison Logic

Before an operation is executed, Vulkan determines whether the stencil test passes using the configured VkCompareOp (such as VK_COMPARE_OP_LESS, VK_COMPARE_OP_EQUAL, or VK_COMPARE_OP_ALWAYS). The comparison is evaluated as:

\[\text{Result} = (\text{Reference} \ \& \ \text{compareMask}) \ \mathbf{compareOp} \ (\text{BufferValue} \ \& \ \text{compareMask})\]

  • Reference: A dynamic or static scalar value provided to the pipeline or set via vkCmdSetStencilReference.
  • compareMask: An integer bitmask (VkStencilOpState::compareMask) that isolates specific bits for comparison.
  • BufferValue: The current value residing in the bound stencil buffer at the fragment's coordinates.

If this condition evaluates to true, the fragment proceeds to the depth test. If false, processing immediately halts for depth, and the pipeline executes the operation assigned to failOp.

How Stencil Operations Modify State

Once the pipeline resolves whether the fragment caused a stencil failure, a depth failure, or a total pass, it applies the corresponding VkStencilOp to update the buffer. Any write to the buffer is further masked by writeMask (BufferValue = (BufferValue & ~writeMask) | (NewValue & writeMask)).

VK_STENCIL_OP_KEEP

VK_STENCIL_OP_KEEP leaves the current stencil buffer value unchanged. It is typically used for failOp or depthFailOp when you only want to record fragments that pass all tests, or for passOp when the stencil buffer is acting strictly as a read-only mask (such as masking UI elements or portal views).

VK_STENCIL_OP_REPLACE

VK_STENCIL_OP_REPLACE writes the current reference value into the stencil buffer, subject to the writeMask. If applied on passOp, every fragment that clears both depth and stencil hurdles updates the buffer to the active reference value. This is widely used in object-outlining algorithms and shadow volume generation to mark object footprints.

VK_STENCIL_OP_INCREMENT_AND_CLAMP

VK_STENCIL_OP_INCREMENT_AND_CLAMP increments the existing stencil buffer value by 1. If the value has reached the maximum representable unsigned value determined by the stencil attachment format (e.g., 255 for VK_FORMAT_D32_SFLOAT_S8_UINT), the value stays clamped at that maximum. This is essential for counting algorithms, such as order-independent transparency or multi-pass coverage algorithms, where wrapping around to zero would invalidate the count.

VK_STENCIL_OP_INCREMENT_AND_WRAP

VK_STENCIL_OP_INCREMENT_AND_WRAP increments the current stencil value by 1, but wraps the value to zero if incremented past the maximum representable value. This operation is common in stencil shadow volumes (specifically the "depth-fail" or Carmack's Reverse technique), where winding numbers require standard modular arithmetic.

Other Supporting Operations

  • VK_STENCIL_OP_ZERO: Explicitly sets the stencil buffer value to zero.
  • VK_STENCIL_OP_INVERT: Bitwise inverts all bits in the stencil buffer value.
  • VK_STENCIL_OP_DECREMENT_AND_CLAMP: Decrements the value by 1, stopping at zero.
  • VK_STENCIL_OP_DECREMENT_AND_WRAP: Decrements the value by 1, wrapping to the maximum possible value if decremented below zero.

Interaction with the Depth Buffer

The evaluation order creates dependencies between depth and stencil buffers:

  • If depthTestEnable is set to VK_FALSE in VkPipelineDepthStencilStateCreateInfo, the depth test is skipped entirely, meaning a passing stencil test automatically triggers the passOp.
  • If early fragment tests are enabled by the shader execution mode, the depth-stencil evaluation occurs before the fragment shader executes, preserving memory bandwidth if the fragment fails the tests.
  • When depthFailOp is invoked, it indicates the geometry was physically visible according to the stencil mask but occluded by existing geometry in the depth buffer, allowing specialized algorithms to count occluded surfaces without rendering colors.
