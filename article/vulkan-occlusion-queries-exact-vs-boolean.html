Vulkan Occlusion Queries: Exact vs. Boolean

Occlusion queries in the Vulkan API allow developers to determine whether geometry is visible after depth and stencil testing, serving as a foundational tool for rendering optimizations. This article provides a comparative breakdown between exact occlusion queries and boolean occlusion queries, detailing how each is configured, how the underlying GPU processes them, their performance implications, and their primary use cases in graphics pipelines.

Understanding Occlusion Queries in Vulkan

In Vulkan, occlusion queries are recorded within a command buffer using vkCmdBeginQuery and vkCmdEndQuery, specifying a query pool created with the VK_QUERY_TYPE_OCCLUSION type. The key distinction between an exact query and a boolean query lies in a single flag passed to the flags parameter of vkCmdBeginQuery: VK_QUERY_CONTROL_PRECISE_BIT.

Exact Occlusion Queries

An exact occlusion query is activated by including the VK_QUERY_CONTROL_PRECISE_BIT flag in vkCmdBeginQuery.

  • Functionality: The GPU tracks and returns the exact integer count of samples (or fragments, if multisampling is disabled) that pass both depth and stencil tests.
  • Hardware Behavior: Because the GPU must tally every single passing sample, it cannot terminate processing early. Hardware features like hierarchical depth testing (Hi-Z) may be constrained or bypassed, forcing the rasterizer to process all covered pixels to ensure an accurate count.
  • Performance Impact: Exact queries introduce higher GPU overhead. They increase memory bandwidth consumption and can cause pipeline stalls if synchronization is not managed asynchronously.
  • Primary Use Cases: Exact queries are ideal when precise quantification is required, such as calculating the intensity of lens flare effects based on how much of a light source is visible, or gathering profiling data and rendering statistics.

Boolean Occlusion Queries

A boolean (or binary) occlusion query is executed by passing 0 (no flags) to vkCmdBeginQuery, omitting the VK_QUERY_CONTROL_PRECISE_BIT.

  • Functionality: Instead of returning a precise sample tally, a boolean query simply determines whether any sample passed the depth and stencil tests. The query result returns 0 if no samples passed (fully occluded) or an implementation-defined non-zero value if at least one sample passed (visible).
  • Hardware Behavior: The GPU can leverage early-out hardware optimizations. As soon as a single sample passes the depth and stencil tests, the hardware knows the object is visible and can abort deeper tracking for that query, significantly reducing work.
  • Performance Impact: Boolean queries are substantially faster and lighter on GPU resources than exact queries because the hardware does not maintain a synchronized global counter for passing samples.
  • Primary Use Cases: Boolean queries are the standard choice for occlusion culling. Developers routinely render simplified bounding boxes of complex geometry; if the boolean query returns 0, the entire complex mesh can be safely skipped in subsequent render passes.

Summary of Differences

Feature Exact Occlusion Query Boolean Occlusion Query
Control Flag VK_QUERY_CONTROL_PRECISE_BIT 0 (None)
Result Value Precise number of passing samples 0 (occluded) or non-zero (visible)
GPU Optimizations Limited; must tally all fragments High; early termination permitted
Performance Overhead Moderate to High Low
Common Application Lens flares, statistical measurements Visibility culling, bounding box tests

For performance-critical rendering loops, boolean queries should always be favored unless application logic explicitly requires the exact sample count.
