Vulkan Ray Tracing Motion Blur for Moving Geometry

This article explains how the Vulkan API resolves temporal geometric changes to produce accurate motion blur using ray tracing. By extending hardware acceleration structures to support temporal domains, Vulkan allows rays to evaluate moving boundaries across exposure intervals. Through conservative bounding volumes, matrix and vertex-level interpolation, and temporal ray payloads, the API ensures precise intersection tests against dynamic geometry without catastrophic performance penalties.

The Temporal Ray Tracing Pipeline

Standard ray tracing assumes a static snapshot of geometry at a discrete point in time. Motion blur ray tracing in Vulkan—primarily implemented via the VK_NV_ray_tracing_motion_blur extension—introduces the dimension of time to both acceleration structures and ray queries.

In this model, the camera shutter duration is mapped to a normalized floating-point time interval, typically \([0.0, 1.0]\). Every generated ray is assigned a specific time stamp within this range. As the ray traverses the scene, intersection tests evaluate the geometry precisely at the ray's assigned time.

Conservative Bounding Volumes

Moving objects traverse spatial coordinates over the course of a frame, meaning their bounding limits are not fixed. To maintain spatial acceleration, Vulkan constructs conservative Axis-Aligned Bounding Boxes (AABBs).

  1. Spatial Expansion: For any geometry with motion, the Bottom-Level Acceleration Structure (BLAS) and Top-Level Acceleration Structure (TLAS) construct expanded bounding boxes. These boxes enclose the union of the geometry’s bounds from the start of the time interval (\(t = 0\)) to the end (\(t = 1\)).
  2. Temporal Pruning: Because conservative bounds are larger than static bounds, rays might trigger false positive box intersections. During traversal, the traversal hardware calculates time-dependent bounds on the fly to discard rays whose temporal parameter does not align with the object's position at that instant.

Handling Rigid Body Motion (Transform Interpolation)

For rigid objects that translate, rotate, or scale without changing surface topology, Vulkan handles motion at the instance level within the TLAS.

  • Matrix Motion: Instances can define multiple transformation matrices across discrete time steps. Vulkan interpolates between these matrices linearly or via specialized matrix decomposition to position the BLAS correctly at ray time \(t\).
  • SRT (Scale-Rotate-Translate) Decompositions: Linear matrix interpolation can cause unnatural shearing or volume loss during rotations. Vulkan allows transform motion to be defined using separate components: quaternion rotations, scale factors, and translation vectors. At traversal time, the hardware interpolates these components independently, preserving rigid geometric boundaries without distorting the mesh.

Handling Deformable Geometry (Vertex Motion)

For meshes whose topology alters across time, such as animated characters or cloth, transform interpolation is insufficient. Vulkan accommodates this via vertex-level motion within the BLAS.

  • Multi-Segment Geometry: The application supplies multiple vertex buffers corresponding to key positions across the time interval.
  • Vertex Interpolation: When a ray traverses a dynamic BLAS, the hardware or software intersection engine uses the ray's time parameter to linearly interpolate the positions of the primitive's vertices between the bounding snapshots.
  • Boundary Precision: Ray-triangle intersection tests are executed against the newly interpolated vertices, ensuring that the silhouette and spatial boundaries of deformable meshes are geometrically exact for the specific time sample.

Ray Traversal and Intersection Testing

When a shader invokes traceRayEXT, the ray payload includes the temporal coordinate:

  1. Ray Generation: The camera or primary ray generation shader samples a random time value \(t \in [0.0, 1.0]\) based on the camera shutter interval and distribution function.
  2. Acceleration Traversal: The hardware traversal unit checks the ray against the conservative bounding boxes. If an intersection occurs, the unit evaluates the instance transform at time \(t\) to enter the local coordinate system of the BLAS.
  3. Primitive Evaluation: The primitive bounds or vertices are sampled at time \(t\). The intersection shader or fixed-function triangle test determines if the ray intersects the surface boundary at that precise moment.

By delegating the interpolation of both instance transforms and mesh vertices directly to the acceleration structures and ray traversal hardware, Vulkan accounts for moving geometric boundaries continuously across the shutter interval, eliminating temporal discretization artifacts.
