Vulkan Custom Border Color with VK_EXT_custom_border_color

This article examines the VK_EXT_custom_border_color extension in Vulkan, explaining how it eliminates the traditional restriction of fixed border colors during texture sampling. It covers why this extension was introduced, the core data structures used to pass arbitrary RGBA values to the sampler creation pipeline, hardware limits and feature flags to consider, and the technical workflow required to apply custom border clamping in modern rendering pipelines.

The Problem with Core Vulkan Border Colors

In core Vulkan implementations, texture sampling using VK_SAMPLER_ADDRESS_MODE_CLAMP_TO_BORDER restricts the border color to predefined values defined by the VkBorderColor enumeration. These options are limited to transparent black (0, 0, 0, 0), opaque black (0, 0, 0, 1), and opaque white (1, 1, 1, 1) in either floating-point or integer formats.

If an application requires out-of-bounds coordinates to resolve to an arbitrary color—such as a specific skybox tint, UI background, or fog tone—developers historically had to handle bounds checking manually inside shader code. This introduced branch overhead, increased register pressure, and reduced texture cache efficiency.

How VK_EXT_custom_border_color Operates

The VK_EXT_custom_border_color extension addresses this limitation by allowing applications to supply an arbitrary VkClearColorValue directly to the texture sampler hardware.

The extension introduces two new enumeration values for VkBorderColor:

  • VK_BORDER_COLOR_FLOAT_CUSTOM_EXT
  • VK_BORDER_COLOR_INT_CUSTOM_EXT

When using either of these values, the developer extends the VkSamplerCreateInfo structure by chaining a new struct via the pNext pointer: VkSamplerCustomBorderColorCreateInfoEXT.

The VkSamplerCustomBorderColorCreateInfoEXT Structure

The extension defines VkSamplerCustomBorderColorCreateInfoEXT with the following key members:

typedef struct VkSamplerCustomBorderColorCreateInfoEXT {
    VkStructureType             sType;
    const void*                 pNext;
    VkClearColorValue           customBorderColor;
    VkFormat                    format;
} VkSamplerCustomBorderColorCreateInfoEXT;
  • customBorderColor: A VkClearColorValue union containing four 32-bit channels (floating-point, signed integer, or unsigned integer). This holds the exact color returned when coordinates fall outside the [0, 1] range.
  • format: Specifies the VkFormat of the image view with which the sampler will be used. Certain hardware platforms require knowing the underlying format to correctly pack the border color into hardware-specific registers. If the hardware supports formatless custom colors, this field can be set to VK_FORMAT_UNDEFINED.

Device Features and Limits

Before creating a sampler with custom border colors, applications must query and enable the relevant device features using VkPhysicalDeviceCustomBorderColorFeaturesEXT:

  • customBorderColors: Indicates whether the physical device supports arbitrary custom border colors.
  • customBorderColorWithoutFormat: Indicates whether samplers can be created with format = VK_FORMAT_UNDEFINED. If this is VK_FALSE, the sampler can only be safely used with image views matching the specified format.

Hardware implementations frequently store custom border colors in dedicated, fixed-size hardware palettes or register files. Consequently, the extension provides VkPhysicalDeviceCustomBorderColorPropertiesEXT to expose capacity constraints:

  • maxCustomBorderColorSamplers: The maximum number of active samplers with custom border colors that can exist concurrently on the device.

Implementation Workflow

  1. Feature Verification: Query VkPhysicalDeviceFeatures2 with VkPhysicalDeviceCustomBorderColorFeaturesEXT chained to pNext. Ensure customBorderColors is VK_TRUE, and enable it during logical device creation (vkCreateDevice).
  2. Sampler Configuration: Initialize VkSamplerCustomBorderColorCreateInfoEXT:
    • Set customBorderColor to the target RGBA values.
    • Provide the target format (or VK_FORMAT_UNDEFINED if supported).
  3. Chaining to Sampler Creation:
    • Set addressModeU, addressModeV, and addressModeW to VK_SAMPLER_ADDRESS_MODE_CLAMP_TO_BORDER.
    • Set borderColor to VK_BORDER_COLOR_FLOAT_CUSTOM_EXT or VK_BORDER_COLOR_INT_CUSTOM_EXT.
    • Attach VkSamplerCustomBorderColorCreateInfoEXT to the pNext chain of VkSamplerCreateInfo.
  4. Creation: Call vkCreateSampler.

By using this extension, the GPU handles border coordinate clamping and arbitrary color substitution natively in the fixed-function texture filtering hardware, maintaining peak sampling throughput without shader intervention.
