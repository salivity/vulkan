Vulkan Clip Volume Depth: [0, 1] vs [-1, 1] Explained

In real-time computer graphics, the clip volume defines the visible boundaries of a 3D scene before primitives are rasterized into pixels. While legacy APIs like OpenGL traditionally mapped depth to a \([-1, 1]\) range in Normalized Device Coordinates (NDC), modern APIs like Vulkan default to a \([0, 1]\) depth range. Understanding the difference between zero-to-one and negative-one-to-one clip volume depth is critical for properly constructing projection matrices, maximizing depth buffer precision, and successfully porting rendering pipelines between graphics APIs.

Clip Space and Normalized Device Coordinates (NDC)

In a typical vertex processing pipeline, vertices are transformed from model space into world space, view space, and finally clip space via a projection matrix. Following the vertex shader, perspective division occurs: the \(x\), \(y\), and \(z\) coordinates are divided by the homogeneous coordinate \(w\).

This division produces Normalized Device Coordinates (NDC). Any primitive outside the designated NDC volume is clipped:

  • Negative-One-to-One (\([-1, 1]\)): Primitives are retained if \(-w \le z \le w\), resulting in an NDC range of \(-1.0 \le z_{ndc} \le 1.0\). This is the standard traditionally used by OpenGL.
  • Zero-to-One (\([0, 1]\)): Primitives are retained if \(0 \le z \le w\), resulting in an NDC range of \(0.0 \le z_{ndc} \le 1.0\). This is the default standard in Vulkan, Direct3D, and Metal.

Advantages of the \([0, 1]\) Depth Range

Vulkan uses the \([0, 1]\) depth range primarily due to hardware architecture and numerical precision:

  1. Direct Mapping to the Depth Buffer: Framebuffer depth attachments are stored as normalized values between \(0.0\) and \(1.0\). In a \([-1, 1]\) system, the hardware must perform an additional scale-and-bias transformation (\(z_{window} = 0.5 \cdot z_{ndc} + 0.5\)) to map the coordinate to memory. A \([0, 1]\) NDC depth maps directly to viewport coordinates without extra conversion.
  2. Superior Floating-Point Precision: Floating-point representations (such as IEEE 754 used in D32_SFLOAT) have high precision close to \(0.0\) and lose precision as values increase. By using \([0, 1]\), games can utilize techniques like "Reverse-Z" (mapping the near plane to \(1.0\) and the far plane to \(0.0\)). Reverse-Z distributes precision evenly across logarithmic distance, virtually eliminating Z-fighting across massive view distances. A \([-1, 1]\) range complicates this optimization because precision is clustered around the middle of the frustum rather than the near or far planes.

Projection Matrix Differences

Because the clipping boundaries differ, a perspective projection matrix built for OpenGL will not work correctly in standard Vulkan.

An OpenGL perspective matrix transforms the near plane to \(-1\) and the far plane to \(+1\):

\[ P_{\text{OpenGL}} = \begin{bmatrix} \frac{2n}{r-l} & 0 & \frac{r+l}{r-l} & 0 \\ 0 & \frac{2n}{t-b} & \frac{t+b}{t-b} & 0 \\ 0 & 0 & -\frac{f+n}{f-n} & -\frac{2fn}{f-n} \\ 0 & 0 & -1 & 0 \end{bmatrix} \]

A standard Vulkan perspective matrix transforms the near plane to \(0\) and the far plane to \(+1\):

\[ P_{\text{Vulkan}} = \begin{bmatrix} \frac{2n}{r-l} & 0 & \frac{r+l}{r-l} & 0 \\ 0 & \frac{2n}{t-b} & \frac{t+b}{t-b} & 0 \\ 0 & 0 & -\frac{f}{f-n} & -\frac{fn}{f-n} \\ 0 & 0 & -1 & 0 \end{bmatrix} \]

(Note: Vulkan also inverts the Y-axis relative to OpenGL, which is often accounted for by negating the \((1,1)\) entry in the matrix or using a negative viewport height).

Supporting \([-1, 1]\) in Vulkan: VK_EXT_depth_clip_control

While \([0, 1]\) is the native standard, porting existing OpenGL rendering engines to Vulkan often introduced visual artifacts or required rebuilding all projection math.

To solve this, the Khronos Group introduced the extension VK_EXT_depth_clip_control. When enabled, developers can configure the pipeline's viewport state using VkPipelineViewportDepthClipControlCreateInfoEXT:

  • Setting negativeOneToOne to VK_TRUE forces the clip volume to treat depth as \([-1, 1]\).
  • Setting negativeOneToOne to VK_FALSE retains Vulkan's default \([0, 1]\) behavior.

This extension enables seamless reuse of legacy projection matrices and depth calculations without modifying shader code or injecting runtime transformation adjustments.
