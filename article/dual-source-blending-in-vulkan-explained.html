Dual-Source Blending in Vulkan Explained

Dual-source blending is a graphics pipeline technique that allows a single fragment shader to output two distinct color values to a single render target attachment, enabling advanced blending mathematics in a single hardware pass. This article covers the fundamental mechanics of dual-source blending, how it is implemented and configured in Vulkan, and the specific graphics rendering scenarios—such as subpixel text anti-aliasing—where this capability is essential.

What is Dual-Source Blending?

In standard rasterization blending, a fragment shader outputs a single color value (Source) that the Fixed-Function Color Blending stage combines with the existing pixel value in the render target (Destination). The blend factors are typically derived from constants, the destination pixel, or the single source pixel's components (such as its alpha channel).

Dual-source blending extends this mechanism by allowing the fragment shader to emit two separate outputs—designated as Src0 (Source 0) and Src1 (Source 1)—aimed at the exact same framebuffer attachment. Rather than writing to multiple render targets, Src0 typically supplies the primary color data, while Src1 serves as an additional, arbitrary blending factor directly accessible by the hardware blend unit.

Enabling Dual-Source Blending in Vulkan

Utilizing dual-source blending in Vulkan requires specific device capabilities, shader configurations, and pipeline state adjustments:

  1. Feature Query and Device Creation: The target GPU must support the feature. Applications must query VkPhysicalDeviceFeatures and verify that dualSrcBlend is set to VK_TRUE. When creating the VkDevice, this feature must be explicitly enabled.

  2. Render Target Limitation: The Vulkan specification limits dual-source blending: when dual-source blend factors are used, the pipeline can generally only bind a single color attachment (index 0). The maximum number of dual-source color attachments supported by the device is exposed by the maxFragmentDualSrcAttachments limit in VkPhysicalDeviceLimits. On most desktop hardware, this limit is 1.

  3. Shader Outputs: In the fragment shader (GLSL/SPIR-V), outputs targeting the same render attachment are distinguished using the index layout qualifier alongside the standard location qualifier:

    layout(location = 0, index = 0) out vec4 outPrimaryColor;  // Src0
layout(location = 0, index = 1) out vec4 outBlendFactor;   // Src1

  4. Pipeline Blend State Configuration: Inside VkPipelineColorBlendAttachmentState, blend factors can explicitly reference the secondary source via Vulkan enums:

    • VK_BLEND_FACTOR_SRC1_COLOR
    • VK_BLEND_FACTOR_ONE_MINUS_SRC1_COLOR
    • VK_BLEND_FACTOR_SRC1_ALPHA
    • VK_BLEND_FACTOR_ONE_MINUS_SRC1_ALPHA

When is Dual-Source Blending Used?

Dual-source blending is employed whenever a blending equation requires per-component, dynamically computed weighting factors that standard single-source blending cannot provide without multi-pass rendering or programmable blending extensions.

Subpixel Font Rendering

The primary use case for dual-source blending is subpixel text rasterization (such as Microsoft ClearType or FreeType LCD filtering). Displays use separate red, green, and blue physical subpixels. Smoothing text on an LCD involves treating each color component as an individual coverage channel.

Standard blending only provides a single scalar alpha for all three color channels (SrcColor * SrcAlpha + DstColor * (1 - SrcAlpha)). Subpixel rendering instead requires component-wise blending:

FinalColor.rgb = Src0.rgb * Src1.rgb + DstColor.rgb * (1.0 - Src1.rgb)

In this scenario, Src0 outputs the uniform text color, and Src1 outputs the per-component RGB coverage mask sampled from the glyph cache. Dual-source blending allows this calculation to execute in a single draw call without needing to read back or fetch the destination pixel inside the shader.

Order-Independent Transparency Approximations

Certain real-time transparency techniques (such as weighted blended order-independent transparency) require accumulating multiple intermediate terms simultaneously. Dual-source blending allows an application to compute and route separate weights and color values into destination targets without splitting the work across distinct draw passes.

Custom Single-Pass Compositing

When implementing non-standard digital image compositing modes that involve dynamic attenuation factors independent of the output alpha, dual-source blending avoids the performance overhead of input attachments, rasterization order attachment access, or compute-based resolve passes.
