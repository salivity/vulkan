Vulkan Conditional Rendering with GPU Queries

Conditional rendering in Vulkan, provided by the VK_EXT_conditional_rendering extension, allows the GPU to discard rendering or dispatch commands dynamically based on values stored in a buffer. By evaluating visibility or occlusion query results directly on the device, this feature eliminates the need to read data back to the CPU to decide whether an object should be drawn, preventing redundant vertex processing, fragment shading, and pipeline stalls.

In traditional occlusion culling workflows without conditional rendering, the CPU must submit a bounding volume query, wait for the GPU to write the results back to host-accessible memory, and then parse the results before recording the actual draw calls. This round-trip introduces significant CPU-GPU synchronization latency and pipeline bubbles. If developers avoid waiting by using query results from previous frames, they risk visual latency and rendering artifacts.

Conditional rendering resolves this synchronization bottleneck by keeping the decision-making process entirely on the GPU. The workflow operates through a sequence of command buffer recordings:

  1. Occlusion Query Execution: A simplified bounding box of an object is rendered within an occlusion query (VK_QUERY_TYPE_OCCLUSION), counting how many samples or primitives pass the depth and stencil tests.
  2. Writing Results to a Buffer: The query results are written to a VkBuffer using vkCmdCopyQueryPoolResults with appropriate synchronization flags, eliminating any CPU readback requirement.
  3. Condition Declaration: The application calls vkCmdBeginConditionalRenderingEXT, referencing the VkBuffer, an offset, and a VkConditionalRenderingFlagsEXT flag. This flag specifies whether the condition is met when the buffer value is non-zero (visible) or inverted.
  4. Command Execution or Discard: Subsequent draw calls, dispatch calls, or clear commands recorded between vkCmdBeginConditionalRenderingEXT and vkCmdEndConditionalRenderingEXT are evaluated by the GPU.

When the GPU reaches the conditioned commands, the hardware command processor checks the value in the specified buffer. If the query result indicates that zero samples passed the occlusion test, the GPU discards the contained draw commands at the front-end stage. The vertex fetch, vertex shading, rasterization, and fragment processing stages are completely bypassed for the occluded geometry.

Because the GPU hardware predicates the execution of draw calls at runtime, CPU command buffer generation remains fully decoupled from frame-to-frame visibility changes. The CPU records the draw calls unconditionally, while the GPU drops redundant commands with near-zero latency, maximizing pipeline throughput and reducing memory bandwidth consumption.
