How Vulkan Variable Rate Shading Works

Variable Rate Shading (VRS) in Vulkan allows developers to dynamically decouple the fragment shading rate from the render target resolution, executing fragment shaders across pixel blocks rather than strictly per-pixel. By varying the invocation density based on scene context, such as peripheral vision in VR, motion blur, or areas of low detail, Vulkan reduces fragment processing workloads without noticeably impacting visual fidelity. This article explains the technical mechanics behind Vulkan’s VRS implementation, detailing the core extensions, shading rate sources, combiners, and how they jointly optimize rasterization and shading overhead.

The Mechanics of Variable Rate Shading

In traditional rendering, the GPU runs the fragment shader once for each pixel covered by a primitive. Variable Rate Shading alters this model by grouping adjacent pixels—such as 1x2, 2x1, 2x2, 2x4, or 4x4 blocks—and computing lighting and material properties using a single fragment shader invocation. The resulting color value is then broadcast across all covered pixels within that footprint.

Crucially, VRS preserves geometric edge quality. Rasterization, coverage evaluation, and depth/stencil testing still occur at native pixel (or MSAA sub-pixel) resolution. This means silhouette edges and depth transitions remain sharp, while only the computationally expensive fragment arithmetic (e.g., complex BRDF evaluation, multiple texture fetches, ray queries) is reduced.

Vulkan Extensions for VRS

Vulkan primarily standardizes VRS through the cross-vendor extension VK_KHR_fragment_shading_rate. Prior vendor-specific approaches, such as VK_NV_shading_rate_image and VK_EXT_fragment_density_map, paved the way for this unified standard.

The VK_KHR_fragment_shading_rate extension defines the framework for querying hardware capabilities, configuring pixel grid sizes, and dynamically applying shading rates across different stages of the graphics pipeline.

The Three Shading Rate Sources

Vulkan allows the fragment shading rate to be driven by three distinct mechanisms:

  1. Pipeline State (Draw-Call Level): A uniform rate is applied across an entire draw call. Developers can set this statically within the pipeline creation structures or dynamically command-by-command using vkCmdSetFragmentShadingRateKHR. This is ideal for broad optimizations, such as lowering the rate for distant background geometry.

  2. Primitive Rate (Per-Vertex or Per-Primitive Level): The shading rate can be generated inside the vertex, geometry, or mesh shaders using the built-in PrimitiveShadingRateKHR output. This allows per-triangle control, making it useful for coarse-shading primitives with high motion vectors or triangles determined to be small or out of focus.

  3. Attachment Rate (Screen-Space Shading Rate Image): A low-resolution 2D image is bound to the render pass as a shading rate attachment via VkFragmentShadingRateAttachmentInfoKHR. Each texel in this image specifies the shading rate for a corresponding block of screen-space pixels (e.g., a 16x16 pixel tile). This pattern is central to foveated rendering in head-mounted displays and screen-space temporal variation based on velocity buffers.

Shading Rate Combiners

Because an application can supply shading rates from multiple sources simultaneously, Vulkan defines explicit combiner operations (VkFragmentShadingRateCombinerOpKHR) to resolve the final rate for each fragment.

Vulkan uses two combiner stages:

  • Combiner 1: Merges the pipeline-level rate and the primitive-level rate.
  • Combiner 2: Merges the result of Combiner 1 with the attachment-level rate.

The API supports several combiner operations to resolve conflicting rates:

  • Keep (KEEP): Prioritizes one specific rate source while ignoring the other.
  • Replace (REPLACE): Overwrites previous values with the secondary source.
  • Minimum (MIN): Selects the finer shading rate (higher quality, more invocations).
  • Maximum (MAX): Selects the coarser shading rate (lower performance cost, fewer invocations).
  • Multiply (MUL): Multiplies the shading rates together along each axis, clamped to device-supported limits.

Optimizing Rasterization and Performance

To gain performance improvements from VRS in Vulkan:

  • Identify Fragment-Bound Passes: VRS only optimizes fragment shader execution. Geometry-bound or bandwidth-bound (e.g., simple depth pre-passes) passes will yield minimal benefits and may introduce minor overhead.
  • Align with Temporal Feedback: Pair attachment-based VRS with motion vector buffers. Pixels moving quickly across the screen naturally blur, allowing the GPU to run shaders at 2x2 or 4x4 rates without perceptual visual degradation.
  • Match Tile Sizes: Query VkPhysicalDeviceFragmentShadingRatePropertiesKHR to identify the hardware’s minFragmentShadingRateAttachmentTexelSize and maxFragmentShadingRateAttachmentTexelSize to ensure shading rate images match the GPU's native execution tiles.
