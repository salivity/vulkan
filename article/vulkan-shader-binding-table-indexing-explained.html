Vulkan Shader Binding Table Indexing Explained

The Vulkan Shader Binding Table (SBT) bridges the gap between hardware ray tracing pipelines and scene geometry by mapping pipeline shader stages to GPU memory buffers. This article explains how Vulkan organizes and calculates memory addresses to index Ray Generation, Miss, and Hit shader groups during ray traversal, detailing the specific mathematical formulas defined by the VK_KHR_ray_tracing_pipeline extension.

The Anatomy of the Shader Binding Table

An SBT is a standard VkBuffer populated with shader group handles retrieved via vkGetRayTracingShaderGroupHandlesKHR, optionally followed by inline parameters (root arguments or local resources). When executing vkCmdTraceRaysKHR, the developer provides four VkStridedDeviceAddressRegionKHR structures defining the base device address, stride, and size for:

  1. Ray Generation shaders
  2. Miss shaders
  3. Hit groups (Intersection, Any-Hit, Closest-Hit)
  4. Callable shaders

Each record within the table must align to properties specified in VkPhysicalDeviceRayTracingPipelinePropertiesKHR, primarily shaderGroupHandleAlignment and shaderGroupBaseAlignment.

Indexing Ray Generation Shaders

Ray Generation shaders initiate ray traversal and are the most straightforward to index.

  • Invocation: Ray generation shaders are triggered directly by the ray dispatch grid dimensions defined in vkCmdTraceRaysKHR(width, height, depth).
  • Addressing: Typically, only one ray generation shader is executed per dispatch. Its memory location is defined directly by the base address:

\[\text{Address} = \text{pRayGenShaderBindingTable}\rightarrow\text{deviceAddress}\]

If an application provides multiple ray generation records, selection cannot be driven dynamically per ray from within the shader; the base pointer must simply be offset in the dispatch call to invoke a different ray generation shader.

Indexing Miss Shaders

Miss shaders execute when a ray traversed through the Top-Level Acceleration Structure (TLAS) and Bottom-Level Acceleration Structure (BLAS) encounters no intersecting geometry, or when all intersections are rejected.

  • Invocation: Selected dynamically within a Ray Generation or Closest Hit shader via the missIndex argument passed to the shading language intrinsic (e.g., traceRayEXT(...) in GLSL).
  • Addressing: The GPU computes the exact record address using a linear stride calculation:

\[\text{Address} = \text{pMissShaderBindingTable}\rightarrow\text{deviceAddress} + (\text{missIndex} \times \text{pMissShaderBindingTable}\rightarrow\text{stride})\]

This allows developers to map distinct miss behaviors—such as different skyboxes, ambient lighting, or shadow misses—by incrementing missIndex.

Indexing Hit Groups

Hit groups handle ray-primitive intersections and contain any combination of Intersection, Any-Hit, and Closest-Hit shaders. Because scene geometry varies by material, instance, and geometry index, hit group indexing combines static acceleration structure data with dynamic parameters passed at trace time.

When an intersection is confirmed, the GPU calculates the index of the hit group record using the following standardized formula:

\[\text{HitGroupIndex} = \text{instanceCustomIndexOffset} + (\text{geometryIndex} \times \text{sbtRecordStride}) + \text{sbtRecordOffset}\]

Where:

  • instanceCustomIndexOffset is the instanceShaderBindingTableRecordOffset defined per-instance inside the VkAccelerationStructureInstanceKHR descriptor.
  • geometryIndex is the implicit, zero-based index of the geometry within a given BLAS.
  • sbtRecordStride is the stride multiplier passed into the trace function (e.g., sbtRecordStride parameter in traceRayEXT). This is commonly used to allocate consecutive records for different ray types (such as radiance rays vs. shadow rays).
  • sbtRecordOffset is the dynamic offset passed into the trace call, selecting which ray-type slot to use for the hit.

Once the integer HitGroupIndex is calculated, the physical memory address in the SBT is derived:

\[\text{Address} = \text{pHitShaderBindingTable}\rightarrow\text{deviceAddress} + (\text{HitGroupIndex} \times \text{pHitShaderBindingTable}\rightarrow\text{stride})\]

Summary of Indexing Flow

During ray execution, the SBT acts as a dynamic function lookup table. Ray Generation uses a direct address lookup to launch work. Miss shaders use a single dynamic index passed at the trace call site. Hit groups reconcile scene topology (instance offset and BLAS geometry index) with ray classifications (ray-type offset and stride) to locate the exact shader handle and inline resources required for shading.
