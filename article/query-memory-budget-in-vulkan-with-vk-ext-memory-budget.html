Query Memory Budget in Vulkan with VK_EXT_memory_budget

This article explains how to determine runtime physical memory availability in Vulkan using the VK_EXT_memory_budget extension. It outlines the required extensions, demonstrates how to structure and execute the query using extended physical device property structures, and explains how to interpret heap budget and usage values to manage memory dynamically during rendering workloads.

1. Enable Required Extensions

To query real-time memory budgets, the application must enable the VK_EXT_memory_budget device extension during logical device creation:

  • Device Extension: VK_EXT_MEMORY_BUDGET_EXTENSION_NAME
  • Dependency: If using Vulkan 1.0, the instance extension VK_KHR_get_physical_device_properties2 must also be enabled. In Vulkan 1.1 and later, this functionality is part of the core specification.

2. Set Up the Query Structures

The memory budget query uses the Vulkan pNext chain mechanism to extend standard physical device properties. Two main structures are required:

  • VkPhysicalDeviceMemoryBudgetPropertiesEXT: Receives the current budget and usage statistics.
  • VkPhysicalDeviceMemoryProperties2: The base container that accepts the extension struct in its pNext chain.
VkPhysicalDeviceMemoryBudgetPropertiesEXT memoryBudgetProperties = {};
memoryBudgetProperties.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_MEMORY_BUDGET_PROPERTIES_EXT;
memoryBudgetProperties.pNext = nullptr;

VkPhysicalDeviceMemoryProperties2 memoryProperties2 = {};
memoryProperties2.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_MEMORY_PROPERTIES_2;
memoryProperties2.pNext = &memoryBudgetProperties;

3. Execute the Query

Call vkGetPhysicalDeviceMemoryProperties2 (or its KHR equivalent in Vulkan 1.0) passing the physical device handle and the address of memoryProperties2:

vkGetPhysicalDeviceMemoryProperties2(physicalDevice, &memoryProperties2);

Upon execution, the driver populates both standard memory properties (heaps and types) in memoryProperties2.memoryProperties and the real-time memory budget details in memoryBudgetProperties.

4. Interpret the Budget and Usage Data

VkPhysicalDeviceMemoryBudgetPropertiesEXT provides two key arrays, indexed up to VK_MAX_MEMORY_HEAPS:

  • heapUsage[i]: The total number of bytes currently allocated by the application and external OS processes within heap i.
  • heapBudget[i]: The rough estimate of total bytes the application is allowed to allocate in heap i at that specific moment without causing performance degradation, paging to system memory, or out-of-memory errors.

Unlike the static capacity defined in memoryProperties2.memoryProperties.memoryHeaps[i].size, heapBudget dynamically shifts based on background OS activity and other running applications.

5. Application Usage Guidelines

  • Calculate Headroom: Available memory for new allocations can be estimated as heapBudget[i] - heapUsage[i].
  • Handle Oversubscription: If heapUsage[i] approaches or exceeds heapBudget[i], the engine should trigger asset streaming purges, reduce texture mip levels, or delay non-critical resource allocations.
  • Polling Frequency: Querying the budget incurs minimal CPU overhead, making it practical to poll periodically (e.g., once every few frames or before beginning a new streaming phase) rather than on every single draw call.
