Vulkan Coverage Reduction and Variable Rate Shading

This article examines how coverage reduction modes interact with Variable Rate Shading (VRS) in the Vulkan API. It details the functional pipeline stages where these two features intersect, covering sample coverage evaluation, coarse fragment execution, depth/stencil handling, and the resulting performance and fidelity trade-offs when combining sample-count reduction with coarse-rate shading.

Core Concepts in Vulkan

Variable Rate Shading in Vulkan (standardized via VK_KHR_fragment_shading_rate) decouples the fragment shader execution frequency from the rasterization resolution. Instead of executing the fragment shader once per pixel or once per MSAA sample, VRS allows a single fragment shader invocation to process a region of pixels (such as 1x2, 2x1, 2x2, or 4x4) known as a coarse pixel.

Coverage reduction modes (typically managed through VK_NV_coverage_reduction_mode) decouple the number of coverage samples from the number of stored color and depth/stencil samples. This allows the rasterizer to test geometry coverage at a high sample count while writing to a lower sample count surface, reducing memory bandwidth during multisample antialiasing (MSAA) workloads.

The Rasterization Pipeline Sequence

When coverage reduction and VRS operate simultaneously, the graphics pipeline executes specific stages in a defined order:

  1. Primitive Generation and Coverage Determination: The rasterizer tests the primitive against the pixel grid using the coverage sample count specified by the active coverage reduction mode.
  2. Coarse Shading Rate Allocation: The shading rate for the primitive or screen tile is determined through pipeline state, primitive attributes, or a shading rate image.
  3. Fragment Shader Invocation: A single fragment shader runs for the coarse pixel area.
  4. Sample Write and Merging: The single output color from the fragment shader is broadcast and applied to all covered samples within that coarse footprint according to the coverage reduction rules.

Interaction Mechanics

1. Coverage Mask Granularity

Coverage reduction alters how many sub-pixel points are evaluated for primitive containment. VRS does not reduce this coverage precision; coverage masks remain defined at the sample level. When a coarse fragment is evaluated (for instance, over a 2x2 pixel footprint), the rasterizer evaluates the high-frequency coverage mask for all pixels within that footprint. The coverage reduction mode determines how those individual sub-pixel coverage tests map to the reduced set of physical color and depth samples.

2. Fragment Output Broadcasting

The fragment shader executes once per coarse pixel, yielding one set of output data (color, user attributes). Vulkan then broadcasts this output to every sample that passed the coverage test within the coarse pixel's footprint. If the coverage reduction mode specifies fewer color targets than coverage samples, the color write only applies to the surviving color samples, but coverage tracking remains intact for antialiasing resolves.

3. Centroid and Sample Interpolation

VRS alters attribute interpolation. Standard pixel-center interpolation evaluates attributes at the center of the coarse pixel. If centroid interpolation is used alongside coverage reduction, the interpolation point must lie within the intersection of the primitive and the covered samples. Because coverage reduction can alter which sub-pixel locations correspond to actual storage samples, the centroid location is evaluated based on the active, reduced sample locations rather than the full coverage grid.

4. Depth and Stencil Testing

Coverage reduction directly governs the physical resolution of depth and stencil testing. When VRS is active, depth testing can still occur per sample to preserve geometric edge sharpness. The coverage reduction mode defines the actual number of depth comparisons performed. VRS does not coarsen the depth buffer resolution; it only coarsens the invocation frequency of the fragment shader. Consequently, depth-stencil operations retain the precision configured by the coverage reduction mode.

Visual Quality and Bandwidth Implications

Combining coverage reduction with VRS targets two different bottlenecks simultaneously:

  • ALU Bound Stages: VRS reduces mathematical and texture sampling overhead by lowering fragment invocations over areas with low geometric or texture variation.
  • ROP and Bandwidth Bound Stages: Coverage reduction minimizes the bandwidth required to write and store multisample buffers without dropping back to standard single-sample rasterization.

When combined properly, geometric edge definition remains high due to coverage testing, depth precision is preserved according to the coverage reduction specification, and shading complexity is scaled down where high-frequency color detail is unnecessary. Artifacts can occur if coarse shading rates are too large over complex, thin geometry where coverage reduction has already minimized the sample footprint, potentially leading to temporal shimmering or aliasing on high-contrast edges.
