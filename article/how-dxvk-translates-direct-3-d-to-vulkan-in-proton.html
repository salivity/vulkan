How DXVK Translates Direct3D to Vulkan in Proton

DXVK is a core component of Valve’s Proton compatibility layer that enables Linux systems to run Windows games with near-native graphics performance. By acting as a drop-in replacement for Microsoft's Direct3D runtime libraries, DXVK intercepts Direct3D 9, 10, and 11 API calls and translates them into equivalent Vulkan commands in real time. This process bridges the gap between legacy, proprietary Microsoft graphics interfaces and modern, low-overhead Vulkan architecture, allowing the underlying Linux operating system to render complex 3D scenes without requiring native Linux game ports.

Intercepting Direct3D Calls

DXVK operates at the dynamic-link library (DLL) level. Within Proton, it replaces standard Windows system DLLs—specifically d3d9.dll, d3d10core.dll, d3d11.dll, and dxgi.dll—with custom implementations. When a Windows game running under Proton requests a Direct3D device or issues draw calls, those commands are directed to DXVK instead of Microsoft's runtime. DXVK exposes the exact interfaces, methods, and behaviors expected by the game, making the translation layer completely transparent to the game engine.

Shader Translation via DXBC to SPIR-V

One of the most complex tasks DXVK handles is shader conversion. Direct3D 9 through 11 rely on High-Level Shading Language (HLSL) compiled into DirectX Bytecode (DXBC). Vulkan, conversely, consumes shaders in the Standard Portable Intermediate Representation (SPIR-V) format.

DXVK parses DXBC instructions on the fly and generates equivalent SPIR-V bytecode. Because Direct3D and Vulkan handle features like coordinate systems, clip spaces, and resource bindings differently, DXVK's shader compiler injects necessary math and binding shifts into the resulting SPIR-V code to ensure pixel-perfect rendering parity.

State Mapping and Pipeline Compilation

Direct3D 9, 10, and 11 use relatively high-level, mutable state models where games can change blend modes, depth states, and rasterizer settings individually on a single context. Vulkan, by design, uses immutable Pipeline State Objects (PSOs), where all render states, shaders, and formats must be baked into a monolithic object before rendering occurs.

To bridge this architectural divide:

  • DXVK tracks all discrete state updates made by the game.
  • When a draw call is initiated, DXVK hashes the current state combination and looks it up in an internal pipeline cache.
  • If the pipeline already exists, it is bound immediately.
  • If the pipeline has not been compiled yet, DXVK compiles it on demand. To reduce the stutter caused by compiling new pipelines mid-game, DXVK caches compiled pipelines to disk across sessions, and Proton uses Steam's Fossilize system to pre-compile pipelines before gameplay begins.

Resource and Memory Synchronization

Direct3D handles memory and pipeline synchronization with varying degrees of abstraction, often relying on the graphics driver to insert implicit hardware barriers. Vulkan requires explicit control over resource transitions, memory barriers, and execution synchronization.

DXVK manages this by wrapping Direct3D resources (such as textures, vertex buffers, and constant buffers) into corresponding Vulkan objects (VkImage, VkBuffer, and VkDeviceMemory). The translation layer maintains internal tracking of resource usage across frames. When a resource transitions from being a render target to a shader input, DXVK automatically emits the required Vulkan pipeline barriers, subpass dependencies, and image layout transitions to maintain memory coherency without causing unnecessary GPU stalls.

Command Execution in Proton

Once DXVK has translated states, shaders, and resources into native Vulkan primitives, it records these operations into Vulkan command buffers (VkCommandBuffer). DXVK manages worker threads to handle command processing asynchronously, decoupling CPU-heavy state translation from GPU submission queues. These command buffers are submitted directly to the host system’s native Vulkan graphics driver, enabling Proton to execute Windows games with minimal CPU overhead.
