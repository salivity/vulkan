Vulkan Geometry Shaders vs Mesh and Compute Performance

Geometry shaders in the Vulkan graphics API have historically enabled dynamic primitive generation and modification, but they frequently introduce severe hardware-level performance bottlenecks. Modern GPU architectures struggle with the unpredictable amplification and serialization inherent to the traditional geometry pipeline. Consequently, developers increasingly rely on compute shaders for GPU-driven geometry processing or transition to the modern mesh shading pipeline (VK_EXT_mesh_shader), both of which significantly outperform geometry shaders by matching hardware parallelism and memory architectures more efficiently.

The Architectural Bottlenecks of Geometry Shaders

Geometry shaders (GS) sit between the vertex (or tessellation evaluation) stage and the rasterizer. Their primary performance degradation stems from their execution model:

  • Unbalanced Amplification and Culling: A geometry shader can output a variable number of vertices per invocation. GPUs allocate internal scratch space based on the shader's declared max_vertices. If a shader declares a high maximum output but only generates a few vertices (e.g., for culling or particle expansion), substantial on-chip memory is reserved but wasted, severely limiting thread occupancy.
  • Primitive Assembly Serialization: Geometry shaders must output primitives in a strictly defined order to match the API's draw calls. Enforcing this primitive ordering requires synchronization barriers across execution units, which causes pipeline stalls and underutilizes compute execution units (ALUs).
  • Memory Spills: If the total payload of generated primitives exceeds dedicated on-chip parameter cache or scratch memory, the hardware must spill intermediate vertices to slower VRAM, turning a compute task into a high-latency memory bandwidth bottleneck.

Compute Shaders: GPU-Driven Geometry Processing

Compute shaders provide a general-purpose, cooperative thread model that avoids the raster pipeline's rigid sequencing. While compute shaders cannot output primitives directly to the rasterizer without modern extensions, they dramatically outperform geometry shaders in data manipulation through GPU-driven pipelines.

  • GPU-Driven Culling: Instead of discarding triangles inside a geometry shader, a compute shader performs frustum, occlusion, and back-face culling upfront on compute threads. Valid indices and vertices are written to compact buffers, and arguments for subsequent draws are dispatched using vkCmdDrawIndexedIndirect.
  • Predictable Thread Allocation: Compute shaders operate over fixed workgroups (e.g., 64 or 128 threads), maximizing hardware occupancy and register reuse without reserving variable scratch space.
  • Shared Memory Usage: Compute shaders have access to high-speed shared memory (workgroup local storage), allowing threads to cooperate on tasks like bounding-box calculations or LOD selection with minimal bandwidth overhead.

Mesh Shading: The Modern Replacement for Geometry Shaders

The mesh shading pipeline, exposed in Vulkan via the VK_EXT_mesh_shader extension, replaces the fixed-function input assembly, vertex shader, and geometry shader with a two-stage cooperative pipeline: Task Shaders and Mesh Shaders.

  • Threadgroup-Centric Topology: Unlike geometry shaders, which process one primitive at a time, mesh shaders operate on small chunks of geometry known as meshlets (typically 32 to 64 vertices and up to 126 primitives). The entire workgroup cooperatively calculates vertices and primitive topologies, completely removing the single-invocation amplification bottleneck.
  • On-Chip Allocation: Mesh shaders output fixed-size vertex and primitive arrays directly into on-chip cache memory, eliminating the memory spilling typical of geometry shaders.
  • Hierarchical Culling (Task Shaders): Task shaders act as an optional preprocessing stage capable of emitting variable counts of mesh shader workgroups. This allows developers to discard non-visible geometry at a coarse level before vertex processing or primitive assembly ever occurs, providing far higher throughput than geometry shader-based culling.

Performance Summary

In Vulkan rendering pipelines, geometry shaders should generally be avoided for performance-critical workloads. Compute shaders remain the standard choice for general-purpose mesh processing, physics, and GPU culling pipelines targeting broad hardware compatibility. For hardware that supports modern extensions, mesh shaders are the definitive successor to geometry shaders, offering linear scaling, high occupancy, and full developer control over geometry generation directly within the rasterization pipeline.
