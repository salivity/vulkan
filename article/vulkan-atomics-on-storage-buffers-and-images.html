Vulkan Atomics on Storage Buffers and Images

In Vulkan, atomic operations provide hardware-synchronized, thread-safe memory manipulation across concurrent compute and graphics shader invocations. This article covers the specific atomic operations supported on storage buffers (Shader Storage Buffer Objects or SSBOs) and storage images, the basic integer operations available by default, the requirements for storage images, and extended capabilities such as 64-bit integer and floating-point atomics enabled through modern extensions.

Core Atomic Operations

Standard SPIR-V shaders and GLSL/HLSL compilers targeting Vulkan support a fundamental suite of atomic read-modify-write instructions. In core Vulkan, these operations natively apply to 32-bit signed and unsigned integers (int32_t, uint32_t):

  • Atomic Add (atomicAdd / OpAtomicIAdd): Adds a value to the target memory location and returns the original value.
  • Atomic Subtract (atomicSub / OpAtomicISub): Subtracts a value from the target memory location and returns the original value (frequently implemented as an atomic addition of the two's complement negation).
  • Atomic Minimum (atomicMin / OpAtomicSMin, OpAtomicUMin): Computes the signed or unsigned minimum between the current memory value and a given parameter, storing the result.
  • Atomic Maximum (atomicMax / OpAtomicSMax, OpAtomicUMax): Computes the signed or unsigned maximum between the current memory value and a given parameter, storing the result.
  • Atomic Bitwise AND (atomicAnd / OpAtomicAnd): Performs a bitwise AND operation on the target location.
  • Atomic Bitwise OR (atomicOr / OpAtomicOr): Performs a bitwise OR operation on the target location.
  • Atomic Bitwise XOR (atomicXor / OpAtomicXor): Performs a bitwise XOR operation on the target location.
  • Atomic Exchange (atomicExchange / OpAtomicExchange): Replaces the value at the target location unconditionally and returns the previous value.
  • Atomic Compare and Swap (atomicCompSwap / OpAtomicCompareExchange): Compares the value in memory with a reference value; if equal, swaps in the new value, returning the original value.

Storage Buffers vs. Storage Images

While storage buffers and storage images share similar atomic functions, their format requirements and hardware support differ significantly:

  • Storage Buffers: SSBOs represent raw, linear byte allocations, making atomic support virtually universal across Vulkan-compliant hardware for 32-bit integer types. Buffer atomics generally have fewer limitations and require only general compute/fragment execution capabilities.
  • Storage Images: Storage images require specialized hardware capabilities because pixel access involves tiling, caching, and coordinate conversion. To perform atomics on an image:
    • The image format must support the VK_FORMAT_FEATURE_STORAGE_IMAGE_ATOMIC_BIT flag in its format properties.
    • Typically, only single-component 32-bit integer formats like VK_FORMAT_R32_UINT and VK_FORMAT_R32_SINT offer atomic support.
    • The shader must declare the image with the appropriate layout (e.g., layout(r32ui) uniform uimage2D).

Extended Atomic Capabilities

Vulkan supports advanced data types and additional operations through optional features and extensions:

64-Bit Integer Atomics

Core in Vulkan 1.2 (or via VK_KHR_shader_atomic_int64), 64-bit integer atomics extend operations like atomicAdd, atomicMin, atomicMax, and bitwise logic to int64_t and uint64_t. Support is split across features:

  • shaderBufferInt64Atomics: Enables 64-bit atomics on storage buffers.
  • shaderSharedInt64Atomics: Enables 64-bit atomics on compute workgroup shared memory.
  • shaderImageInt64Atomics: Enables 64-bit atomics on storage images (e.g., VK_FORMAT_R64_UINT), supported on fewer hardware platforms.

Floating-Point Atomics

Standard Vulkan does not support floating-point atomic operations natively. To use atomic instructions on floating-point data, implementations must support specific extensions:

  • VK_EXT_shader_atomic_float: Adds support for 32-bit and 64-bit floating-point atomic additions (OpAtomicFAddEXT) and basic exchanges on storage buffers, workgroup shared memory, and images.
  • VK_EXT_shader_atomic_float2: Expands floating-point atomic support to include 16-bit floating-point (float16_t) addition, as well as atomicMin and atomicMax equivalents for floating-point values (OpAtomicFMinEXT, OpAtomicFMaxEXT).
