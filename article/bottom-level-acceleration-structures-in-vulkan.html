Bottom-Level Acceleration Structures in Vulkan

Bottom-Level Acceleration Structures (BLAS) are foundational components in Vulkan's hardware-accelerated ray tracing pipeline, responsible for organizing and optimizing raw geometric primitives for rapid ray-intersection testing. This article details the primary roles of a BLAS, including storing actual triangle and procedural geometry, enabling GPU-driven spatial partitioning, facilitating efficient mesh instancing alongside Top-Level Acceleration Structures (TLAS), and balancing performance through build and update strategies.

Geometric Representation and Storage

In the Vulkan ray tracing extensions (VK_KHR_acceleration_structure), a BLAS directly references the actual vertex and index buffers that define a 3D model. Unlike rasterization, which processes triangles sequentially through a graphics pipeline, ray tracing requires random spatial access to geometry.

A BLAS supports two distinct types of geometry:

  • Triangles: Defined by vertex positions, formats, strides, and optional index buffers.
  • Axis-Aligned Bounding Boxes (AABBs): Defined by minimum and maximum extents, used to encapsulate procedural primitives that require custom intersection shaders.

Multiple geometries of the same type can be combined into a single BLAS, allowing related meshes to share the same local spatial hierarchy.

Spatial Partitioning for Ray Traversal

The primary computational role of a BLAS is to structure raw geometry into a Bounding Volume Hierarchy (BVH). The Vulkan driver compiles the underlying geometric data into a tree of nested bounding boxes optimized for the specific GPU architecture.

During ray traversal, hardware RT cores traverse this hierarchy rather than testing every polygon in a scene. When a ray enters a BLAS, it tests against parent bounding boxes first, culling large portions of the mesh instantly and only performing ray-triangle intersection tests on the leaf nodes where intersections are probable.

Enabling Efficient Instancing

Vulkan employs a two-level acceleration structure hierarchy consisting of the BLAS and the Top-Level Acceleration Structure (TLAS). The BLAS defines geometry in local object space, while the TLAS defines instances of these BLAS objects placed into world space via transformation matrices.

This separation provides critical advantages:

  • Memory Efficiency: A complex mesh (such as a tree or vehicle) is built into a single BLAS once in GPU memory, while dozens or thousands of instances can reference it via the TLAS, each with unique transformation matrices and shader binding table offsets.
  • Transform Independence: Moving, rotating, or scaling an object does not require modifying the BLAS. Only the corresponding instance in the TLAS needs to be updated.

Build and Update Management

Creating a BLAS in Vulkan requires explicit memory management using vkCmdBuildAccelerationStructuresKHR. Because constructing the BVH is computationally intensive, Vulkan provides build flags to optimize the BLAS based on its intended usage:

  • Prefer Fast Trace: Spends more compute time during the build phase to generate a tighter BVH, maximizing runtime ray traversal speeds for static meshes.
  • Prefer Fast Build: Reduces BVH construction time at the cost of slight traversal efficiency, ideal for dynamic or frequently generated geometry.
  • Allow Update: Enables fast refitting of an existing BVH when vertex positions move without changing topology (e.g., skinned meshes), avoiding a complete rebuild.

The BLAS serves as the concrete link between raw vertex buffers and the spatial data structures required for real-time ray tracing, dictating both the memory footprint and the intersection performance of 3D geometry in Vulkan.
