Vulkan Transform Feedback: Streaming Geometry to Buffers

Vulkan captures and streams processed vertex and geometry primitives directly into GPU buffers through the VK_EXT_transform_feedback extension. This mechanism intercepts vertices after the vertex, tessellation, or geometry processing stages—prior to rasterization—and writes their attribute data sequentially into dedicated buffer storage. It enables workflows such as GPU-driven particle simulations, cloth physics, dynamic tessellation caching, and primitive queries without requiring compute shader workarounds or round-trips to the CPU.

Enabling the Extension and Pipeline States

Because core Vulkan natively relies on compute shaders or storage buffers for writing arbitrary data from the pipeline, transform feedback is supported via the VK_EXT_transform_feedback device extension. Applications must query physical device support and enable VkPhysicalDeviceTransformFeedbackFeaturesEXT, specifically setting the transformFeedback feature flag to VK_TRUE.

During graphics pipeline creation, you can selectively disable the fragment stage if the sole intent is to generate geometry. Setting rasterizerDiscardEnable = VK_TRUE in VkPipelineRasterizationStateCreateInfo halts the pipeline immediately after the pre-rasterization stages, allowing the GPU to capture vertices into the bound buffers without invoking rasterization or fragment shading overhead.

SPIR-V and Shader Configuration

The shader determines which vertex attributes are captured, their layout, and which buffer index they target. In GLSL, variables are explicitly marked with transform feedback layout qualifiers:

layout(xfb_buffer = 0, xfb_offset = 0, xfb_stride = 32) out vec4 outPosition;
layout(xfb_buffer = 0, xfb_offset = 16) out vec4 outNormal;

When compiled to SPIR-V, these declarations generate XfbBuffer, XfbOffset, and XfbStride execution decorations. Vulkan supports streaming to multiple buffers simultaneously (up to the hardware-defined maxTransformFeedbackBuffers), allowing interleaved attributes in a single buffer or separate attributes distributed across distinct buffer arrays.

Buffer Allocation and Binding

Destination storage requires buffers created with the VK_BUFFER_USAGE_TRANSFORM_FEEDBACK_BUFFER_BIT_EXT flag. If the application tracks the exact number of primitives written, it can also allocate counter buffers created with VK_BUFFER_USAGE_TRANSFORM_FEEDBACK_COUNTER_BUFFER_BIT_EXT.

Before issuing drawing commands, the buffers are bound within a command buffer using:

vkCmdBindTransformFeedbackBuffersEXT(
    commandBuffer,
    firstBinding,
    bindingCount,
    pBuffers,
    pOffsets,
    pSizes
);

Command Recording and Execution

Streaming geometry into the bound memory is controlled explicitly through command recording:

  1. Begin Capture: Call vkCmdBeginTransformFeedbackEXT. This call can optionally take counter buffers to resume recording from previous draw offsets or reset the stream to offset zero.
  2. Execute Draws: Standard rendering commands (vkCmdDraw, vkCmdDrawIndexed, or indirect equivalents) are dispatched. The output primitives generated by the active pre-rasterization shader stages stream into the bound transform feedback buffers.
  3. End Capture: Call vkCmdEndTransformFeedbackEXT. This stops primitive recording and can write the final byte or primitive count into a counter buffer.

Synchronization and Data Reuse

Data written by transform feedback is not automatically coherent with subsequent pipeline reads. To safely consume the output in later stages—such as using the buffer as a vertex buffer for another draw call or reading it in a compute shader—you must insert a pipeline barrier using vkCmdPipelineBarrier:

  • Source Stage: VK_PIPELINE_STAGE_TRANSFORM_FEEDBACK_BIT_EXT
  • Source Access: VK_ACCESS_TRANSFORM_FEEDBACK_WRITE_BIT_EXT
  • Destination Stage: Target stage (e.g., VK_PIPELINE_STAGE_VERTEX_INPUT_BIT or VK_PIPELINE_STAGE_DRAW_INDIRECT_BIT)
  • Destination Access: Target access mask (e.g., VK_ACCESS_VERTEX_ATTRIBUTE_READ_BIT or VK_ACCESS_INDIRECT_COMMAND_READ_BIT)

When paired with vkCmdDrawIndirectByteCountEXT, applications can render the exact number of generated primitives recorded in the counter buffer directly, completely bypassing CPU interaction for dynamic geometry generation.
