Binding SPS and PPS to Vulkan Video Decode Pipelines

Vulkan Video leverages the VK_KHR_video_queue and codec-specific decode extensions, such as VK_KHR_video_decode_h264 and VK_KHR_video_decode_h265, to integrate hardware-accelerated video decoding directly into the Vulkan ecosystem. A critical phase of the decode pipeline is handling codec-specific configuration metadata—specifically Sequence Parameter Sets (SPS) and Picture Parameter Sets (PPS). This article explains how host applications parse these parameter sets from a compressed bitstream, package them into standard Vulkan video structures, store them inside a dedicated session parameters object, and bind them to command buffers during decode execution.

The Role of VkVideoSessionParametersKHR

In the Vulkan Video API, state management is separated into two tiers: the long-lived execution context (VkVideoSessionKHR) and the dynamic state configuration (VkVideoSessionParametersKHR). Sequence Parameter Sets and Picture Parameter Sets are not bound directly as raw byte buffers at draw or dispatch time; instead, they are converted into host-accessible structures and registered within a VkVideoSessionParametersKHR object.

This object acts as an on-device dictionary or parameter cache that stores active SPS and PPS entries by their standard bitstream identifiers (such as seq_parameter_set_id and pic_parameter_set_id).

Parsing and Structuring Parameter Sets

Before parameter sets reach the Vulkan API, the application must extract the network abstraction layer (NAL) units from the bitstream using a demuxer or bitstream parser. Once extracted, the application maps the parsed bitstream headers into Vulkan's standardized Video API types defined in the <vk_video/vulkan_video_codecs_common.h> and codec-specific headers (e.g., <vk_video/vulkan_video_codec_h264std.h>).

For H.264, these parameter sets are mapped into standard structures:

  • StdVideoH264SequenceParameterSet
  • StdVideoH264PictureParameterSet

For H.265 (HEVC), the pipeline also incorporates Video Parameter Sets:

  • StdVideoH265VideoParameterSet
  • StdVideoH265SequenceParameterSet
  • StdVideoH265PictureParameterSet

Registering SPS and PPS with Session Parameters

Once populated, the standard structs are passed into the pipeline during the creation or update of the session parameter object:

  1. Initial Creation: When calling vkCreateVideoSessionParametersKHR, the application chains a codec-specific creation structure via the pNext pointer of VkVideoSessionParametersCreateInfoKHR. For example, with H.264, the application attaches a VkVideoDecodeH264SessionParametersCreateInfoKHR struct. This struct contains arrays of StdVideoH264SequenceParameterSet and StdVideoH264PictureParameterSet, along with counts indicating how many parameter sets are being initialized.
  2. Dynamic Updates: If the stream introduces new SPS or PPS configurations mid-playback, recreating the session is unnecessary. The application can invoke vkUpdateVideoSessionParametersKHR using a VkVideoDecodeH264SessionParametersAddInfoKHR structure (or its H.265 equivalent) to append or replace parameter sets without disrupting the hardware session.

Binding to the Command Buffer

Parameter sets are applied to decode commands across two levels inside a recording command buffer:

1. Session-Level Binding via vkCmdBeginVideoCodingKHR

The decoding scope is initiated by calling vkCmdBeginVideoCodingKHR. The accompanying VkVideoBeginCodingInfoKHR struct includes the handle to the VkVideoSessionParametersKHR object in its videoSessionParameters field. This binds the dictionary containing all registered SPS and PPS structures to the current command scope.

2. Per-Picture Invocation via vkCmdDecodeVideoKHR

When invoking vkCmdDecodeVideoKHR, the application passes a VkVideoDecodeInfoKHR struct containing codec-specific picture parameters in its pNext chain (such as VkVideoDecodeH264PictureInfoKHR).

Rather than sending the full parameter set data again, this structure merely references the ID of the desired parameter set (e.g., matching the pic_parameter_set_id inside the picture header). The hardware decoder uses this ID to query the previously bound VkVideoSessionParametersKHR object, retrieve the corresponding PPS (which in turn references its parent SPS), and configure the decoding hardware for that specific frame slice.
