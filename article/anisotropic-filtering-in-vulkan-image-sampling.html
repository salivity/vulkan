Anisotropic Filtering in Vulkan Image Sampling

This article provides an overview of how anisotropic filtering integrates into the Vulkan graphics API's image sampling pipeline. It details the hardware feature requirements, the configuration parameters within VkSamplerCreateInfo, how the GPU calculates non-square sample footprints across oblique angles, and the practical implementation steps required to enhance texture quality without compromising pipeline performance.

Device Feature Verification and Enablement

Before utilizing anisotropic filtering, an application must verify that the underlying physical device supports it. Vulkan exposes this functionality through the samplerAnisotropy member of the VkPhysicalDeviceFeatures structure.

To query and enable anisotropic filtering:

  1. Query available features using vkGetPhysicalDeviceFeatures.
  2. Inspect VkPhysicalDeviceLimits::maxSamplerAnisotropy using vkGetPhysicalDeviceProperties to determine the maximum supported level of anisotropy (typically up to 16.0f on modern discrete GPUs).
  3. Explicitly set samplerAnisotropy to VK_TRUE within the VkPhysicalDeviceFeatures struct passed to VkDeviceCreateInfo during logical device creation. If this feature is not enabled at device creation, requesting it in subsequent sampler states will result in validation errors or undefined behavior.

Sampler Configuration (VkSamplerCreateInfo)

In Vulkan, anisotropic filtering is configured as a state of the texture sampler object (VkSampler). When creating a sampler with vkCreateSampler, the following fields in VkSamplerCreateInfo control anisotropic behavior:

  • anisotropyEnable: Set to VK_TRUE to activate anisotropic filtering for this sampler, or VK_FALSE to restrict the sampler to isotropic filtering.
  • maxAnisotropy: A floating-point value that defines the maximum ratio of anisotropy to apply. Higher values (such as 8.0f or 16.0f) allow the sampler to stretch the sampling footprint further along the axis of maximum distortion, preserving detail on steep surfaces at the cost of additional texture read operations. This value is clamped by the implementation to maxSamplerAnisotropy.

The Sampling Execution Pipeline

During shader execution, texture sampling typically occurs via SPIR-V sampling instructions (such as OpImageSampleImplicitLod generated by GLSL functions like texture()). The integration of anisotropic filtering alters how the hardware computes the Level of Detail (LoD) and texture footprint:

  1. Derivative Calculation: The GPU determines screen-space derivatives of texture coordinates (\(\frac{\partial u}{\partial x}, \frac{\partial v}{\partial x}, \frac{\partial u}{\partial y}, \frac{\partial v}{\partial y}\)) across pixel quads.
  2. Footprint Construction: For surfaces viewed at oblique angles, isotropic filtering maps a square pixel to an elongated ellipse in texture space, selecting a blurry mipmap level to prevent aliasing along the major axis. Anisotropic filtering instead models this distortion directly.
  3. Multi-tap Fetching: Rather than selecting a single blurred mip level, the hardware samples multiple texels along the major axis of the ellipse at an appropriate, sharper mip level determined by the minor axis.
  4. Filtering and Blending: The gathered samples are weighted and blended together (alongside standard bilinear or trilinear interpolation defined by minFilter, magFilter, and mipmapMode) to produce the final sampled color.

Interaction with Sampler States

  • Mipmap Modes: Anisotropic filtering works in tandem with VkSamplerMipmapMode. When anisotropic filtering is active, it modifies the calculation of the isotropic mip level, using multiple samples to compensate for the difference between the major and minor texture coordinate derivatives.
  • Magnification: Anisotropic filtering only takes effect during minification. When a surface is close enough to the camera that texels are larger than screen pixels, magFilter settings govern the output.
  • Unnormalized Coordinates: Anisotropic filtering is incompatible with unnormalized texture coordinates (unnormalizedCoordinates = VK_TRUE). Standard normalized coordinates in the range \([0.0, 1.0]\) must be used.
