Vulkan Provoking Vertex Control for Flat Shading

Provoking vertex control in Vulkan dictates which vertex in a primitive provides the attribute values—such as flat-shaded colors—to the fragment shader when interpolation is disabled. By utilizing the VK_EXT_provoking_vertex extension, developers can configure whether the first or the last vertex of a primitive acts as the data source for flat-shaded attributes. This mechanism ensures accurate visual reproduction when porting rendering pipelines from APIs with different default conventions, such as OpenGL and Direct3D, without requiring manual geometry manipulation.

Flat Shading and the Provoking Vertex

In standard 3D rendering, fragment shaders typically interpolate vertex attributes across the surface of a primitive (such as a triangle or line). When an attribute is marked with the flat interpolation qualifier in GLSL/SPIR-V, interpolation is disabled. Instead, the fragment shader receives the attribute value evaluated at a single vertex: the provoking vertex.

For attributes like per-vertex color, the flat-shaded primitive appears uniformly colored according to the data bound to that specific vertex. Which vertex the hardware selects determines the primitive's final visible color.

The API Convention Mismatch

Vulkan’s core specification natively adopts the Direct3D convention:

  • First Vertex Convention: The first vertex of a primitive (index \(0\) in an independent triangle list) serves as the provoking vertex.

Historically, OpenGL defaulted to a different standard:

  • Last Vertex Convention: The final vertex of a primitive (index \(2\) in an independent triangle list) is designated as the provoking vertex.

Without explicit control over this selection, running shaders written for OpenGL conventions on a standard Vulkan pipeline results in primitives adopting incorrect flat colors unless index and vertex buffers are restructured.

How Provoking Vertex Control Modifies Color Inheritance

The VK_EXT_provoking_vertex extension introduces the structure VkPipelineRasterizationProvokingVertexStateCreateInfoEXT, which is chained into the graphics pipeline creation via the pNext pointer. This structure exposes provokingVertexMode, accepting two distinct states:

  • VK_PROVOKING_VERTEX_MODE_FIRST_VERTEX_EXT: Forces the pipeline to sample flat-shaded attributes from the first vertex of the primitive.
  • VK_PROVOKING_VERTEX_MODE_LAST_VERTEX_EXT: Forces the pipeline to sample flat-shaded attributes from the last vertex of the primitive.

When applied to different primitive topologies, the inheritance behavior adjusts as follows:

Independent Triangles

For a triangle defined by vertices \((V_0, V_1, V_2)\):

  • First Vertex Mode: The fragment color is inherited entirely from \(V_0\).
  • Last Vertex Mode: The fragment color is inherited entirely from \(V_2\).

Triangle Strips

Triangle strips introduce alternating winding orders. Provoking vertex control handles this indexing automatically:

  • First Vertex Mode: For the \(i\)-th triangle (0-indexed) defined by \((V_i, V_{i+1}, V_{i+2})\), the provoking vertex is \(V_i\).
  • Last Vertex Mode: For the \(i\)-th triangle, the provoking vertex is \(V_{i+2}\).

Lines and Line Strips

For a line segment defined by \((V_0, V_1)\):

  • First Vertex Mode: The color is sampled from \(V_0\).
  • Last Vertex Mode: The color is sampled from \(V_1\).

Implementation Details

To utilize provoking vertex control in Vulkan:

  1. Feature Enablement: Query and enable provokingVertex within VkPhysicalDeviceProvokingVertexFeaturesEXT during logical device creation.
  2. Pipeline State Configuration: Create a VkPipelineRasterizationProvokingVertexStateCreateInfoEXT struct, set provokingVertexMode to the required convention, and attach it to the pNext chain of VkPipelineRasterizationStateCreateInfo.
  3. Transform Feedback Considerations: If using transform feedback (VK_EXT_transform_feedback), the extension also provides transformFeedbackPreservesProvokingVertex to ensure vertex order integrity throughout geometric stages.

By selecting the appropriate provoking vertex mode at pipeline creation, the GPU correctly maps vertex buffer color attributes directly to flat-shaded fragments, eliminating runtime CPU conversion overhead and preserving rendering consistency across diverse graphic APIs.
