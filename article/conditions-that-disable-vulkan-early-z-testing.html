Conditions That Disable Vulkan Early-Z Testing

Early depth testing (early-Z) is a critical hardware optimization in Vulkan that discards occluded fragments before the fragment shader executes, significantly reducing GPU memory bandwidth and computation costs. Under standard pipeline conditions, the rasterizer compares a fragment's interpolated depth value against the depth buffer and immediately drops hidden fragments. However, specific shader operations and pipeline configurations prevent the hardware from determining visibility prior to shader execution, forcing the GPU to fall back to late depth testing (late-Z). Understanding these triggers is essential for writing high-performance Vulkan shaders.

1. Writing to Depth in the Fragment Shader (gl_FragDepth)

The most common reason early-Z is completely disabled is modifying the depth value within the fragment shader.

When a shader writes to gl_FragDepth, the hardware cannot know the final depth of the fragment at the rasterization stage. Consequently, both early depth testing and early depth writes are bypassed, and the depth test is deferred until the fragment shader finishes executing.

Conservative Depth Exception

If modifying depth is mandatory, you can preserve partial hardware early-Z by declaring conservative depth layout qualifiers in GLSL:

  • layout(depth_greater) out float gl_FragDepth;
  • layout(depth_less) out float gl_FragDepth;
  • layout(depth_unchanged) out float gl_FragDepth;

These qualifiers inform the driver that the calculated depth will only move in a specific direction relative to the hardware-interpolated depth, allowing hardware to perform conservative early depth culling (e.g., HiZ).

2. Dynamic Fragment Discarding (discard or demote)

Using the discard keyword (or the demote instruction via SPV_EXT_demote_to_helper_invocation) introduces conditional fragment termination based on runtime calculations, such as alpha testing or cutout textures.

  • Impact on Depth Writes: The GPU cannot write depth values early. If an early depth write occurred, an occluding fragment that is later discarded would leave an erroneous "hole" in the depth buffer, blocking valid background geometry.
  • Impact on Depth Tests: Many modern GPU architectures can still perform an early-Z read (test-only) to cull fragments hidden behind existing geometry. However, early depth writes are deferred to late-Z.

3. Modifying Sample Masks (gl_SampleMask)

In multisample anti-aliasing (MSAA) pipelines, writing to the gl_SampleMask output array inside the fragment shader dynamically alters which sample locations are covered.

Because coverage directly dictates which samples pass the depth test and receive depth updates, writing to the sample mask forces depth evaluation and writes to occur after the fragment shader stage completes.

4. Enabling Alpha-to-Coverage

Alpha-to-coverage converts the fragment's alpha output component into a temporary coverage mask used during MSAA.

Because the fragment shader must first evaluate the alpha value before the final coverage mask can be generated, early depth writes must be disabled. As with discard, the hardware cannot write depth prematurely without risking false occlusion of background objects.

5. Side Effects in Shaders (SSBO and Storage Image Writes)

If a fragment shader performs writes to storage buffers (SSBOs) or storage images, the execution of the shader constitutes a visible side effect beyond the framebuffer attachments.

By default, GPUs are free to discard fragments using early-Z even if the shader has side effects. However, if your shader algorithm relies on executing side effects for every rasterized fragment regardless of whether it is occluded, early-Z must be explicitly bypassed or managed, otherwise occluded invocations will never trigger memory writes.

Overriding with early_fragment_tests

You can explicitly force early depth and stencil testing by declaring the execution mode in your shader:

layout(early_fragment_tests) in;

When this qualifier is present:

  • Depth and stencil tests execute before the fragment shader runs.
  • Fragments failing the test are immediately discarded without invoking the shader.
  • Writing to gl_FragDepth while using early_fragment_tests is illegal according to the specification.
  • If used in a shader containing discard, depth writes occur early. Consequently, if a fragment passes the early depth test, writes its depth, and is subsequently discarded in the shader, it will leave an empty depth footprint that incorrectly occludes geometry behind it.
