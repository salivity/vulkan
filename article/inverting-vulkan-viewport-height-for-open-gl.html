Inverting Vulkan Viewport Height for OpenGL

Migrating rendering pipelines from OpenGL to Vulkan often introduces coordinate system mismatches, as OpenGL uses a normalized device coordinate (NDC) system where the Y-axis points upward, whereas Vulkan's Y-axis points downward. This article details how to dynamically invert the viewport height in Vulkan to match traditional OpenGL projection matrices directly, eliminating the need to alter vertex shaders or adjust triangle winding orders manually.

The Coordinate System Discrepancy

In OpenGL, NDC space has its origin (0, 0) at the center of the screen, with positive Y extending upward and Z spanning from -1.0 to 1.0. In contrast, Vulkan’s NDC origin is also at the center, but positive Y points downward, and Z spans from 0.0 to 1.0.

Simply negating the Y-axis component inside a projection matrix (e.g., multiplying the [1][1] matrix element by -1) aligns the Y-axis but also inverts the geometric winding order. As a result, clockwise faces become counter-clockwise, forcing developers to invert their pipeline's front-face winding or culling settings.

The Dynamic Negative Viewport Solution

Starting in Vulkan 1.1 (and available via the VK_KHR_maintenance1 extension in Vulkan 1.0), Vulkan allows the height field of VkViewport to be negative. Specifying a negative viewport height automatically flips the Y-axis transformation while simultaneously preserving the primitive winding order, allowing standard OpenGL projection matrices and cull modes to work seamlessly.

Implementation Steps

1. Enable Dynamic State in the Pipeline

When constructing your VkGraphicsPipelineCreateInfo, add VK_DYNAMIC_STATE_VIEWPORT to the dynamic states list. This allows you to modify the viewport at command recording time without recreating the entire pipeline:

VkDynamicState dynamicStates[] = {
    VK_DYNAMIC_STATE_VIEWPORT,
    VK_DYNAMIC_STATE_SCISSOR
};

VkPipelineDynamicStateCreateInfo dynamicStateCreateInfo{};
dynamicStateCreateInfo.sType = VK_STRUCTURE_TYPE_PIPELINE_DYNAMIC_STATE_CREATE_INFO;
dynamicStateCreateInfo.dynamicStateCount = 2;
dynamicStateCreateInfo.pDynamicStates = dynamicStates;

2. Set Up the Negative Viewport Dynamically

When recording your render pass commands using vkCmdSetViewport, define the viewport by setting the y offset to the bottom of the viewport area (typically the render target's height) and assigning a negative value to height:

VkViewport viewport{};
viewport.x = 0.0f;
viewport.y = static_cast<float>(surfaceHeight); // Start at the bottom
viewport.width = static_cast<float>(surfaceWidth);
viewport.height = -static_cast<float>(surfaceHeight); // Negative height flips Y
viewport.minDepth = 0.0f;
viewport.maxDepth = 1.0f;

vkCmdSetViewport(commandBuffer, 0, 1, &viewport);

3. Define the Scissor Rectangle

The scissor rectangle does not accept negative values and remains defined from the top-left corner:

VkRect2D scissor{};
scissor.offset = {0, 0};
scissor.extent = {surfaceWidth, surfaceHeight};

vkCmdSetScissor(commandBuffer, 0, 1, &scissor);

Depth Range Considerations

While flipping the viewport height resolves the X and Y axes, OpenGL's default clip-space depth range is [-1.0, 1.0], whereas Vulkan expects [0.0, 1.0]. To use existing OpenGL camera setups completely, you must still adapt the projection matrix's Z-mapping to the [0.0, 1.0] range (often provided via GLM using #define GLM_FORCE_DEPTH_ZERO_TO_ONE) or utilize depth clamping configurations where appropriate.
