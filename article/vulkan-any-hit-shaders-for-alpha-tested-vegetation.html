Vulkan Any-Hit Shaders for Alpha-Tested Vegetation

This article explores the role of any-hit shaders in the Vulkan Ray Tracing pipeline, focusing on how they solve the problem of rendering alpha-tested geometry such as foliage and grass. You will learn the mechanics of the any-hit shader stage, why standard ray tracing fails on cut-out geometry, the step-by-step process of implementing alpha testing, and the performance implications associated with this technique.

What Is an Any-Hit Shader?

In the Vulkan ray tracing pipeline (VK_KHR_ray_tracing_pipeline), ray traversal is largely managed by fixed-function hardware. When a ray intersects an axis-aligned bounding box or a triangle, the hardware needs to determine if that intersection is valid.

While a closest-hit shader is invoked only once for the single confirmed intersection closest to the ray origin, an any-hit shader is an optional stage that executes during ray traversal for each potential intersection encountered along the ray.

Inside an any-hit shader, the developer has programmatic control to accept or reject a hit before traversal continues. Vulkan GLSL provides two key intrinsic functions for this stage:

  • ignoreIntersectionEXT(): Rejects the current hit candidate. Traversal resumes as if the ray passed right through the primitive.
  • terminateRayEXT(): Commits the current hit and immediately terminates ray traversal (often used for boolean shadow tests).

The Challenge of Alpha-Tested Vegetation

In real-time rendering, dense vegetation (like leaves, vines, and grass) is rarely modeled with high-density micro-geometry. Instead, artists use flat polygon "cards" or simple quads mapped with textures containing cutouts defined by an alpha mask.

When building an acceleration structure in Vulkan, geometries flagged as VK_GEOMETRY_OPAQUE_BIT_KHR assume that every point on a triangle's surface is solid. If ray tracing handles vegetation as fully opaque, rays will collide with the transparent parts of the leaf cards. This produces inaccurate, blocky silhouettes for primary visibility, reflections, and ray-traced shadows.

Implementing Alpha Testing with Any-Hit Shaders

To render alpha-tested vegetation correctly, the any-hit shader is used to inspect the texture’s transparency at the exact hit location.

1. Acceleration Structure Setup

When building the Bottom-Level Acceleration Structure (BLAS) for vegetation geometry, do not set the VK_GEOMETRY_OPAQUE_BIT_KHR flag on VkAccelerationStructureGeometryKHR. Omitting this flag signals the ray traversal hardware that the geometry is non-opaque and that the any-hit shader must be called whenever an intersection candidate is found.

2. Hit Attribute Interpolation

When the any-hit shader is invoked, it receives the built-in barycentric coordinates (hitAttributeEXT vec2 attribs). The shader uses these coordinates alongside vertex data retrieved from storage buffers (or ray payloads) to interpolate the texture coordinates (UVs) of the intersection point:

vec3 barycentrics = vec3(1.0 - attribs.x - attribs.y, attribs.x, attribs.y);
vec2 uv = v0.uv * barycentrics.x + v1.uv * barycentrics.y + v2.uv * barycentrics.z;

3. Sampling and Discarding

The shader samples the alpha channel of the vegetation albedo/diffuse texture using the interpolated UV coordinates. If the alpha value falls below a defined cutoff threshold, the intersection is ignored:

float alpha = texture(sampler2D(textures[nonuniformEXT(texID)], samp), uv).a;

if (alpha < 0.5) {
    ignoreIntersectionEXT();
}

If ignoreIntersectionEXT() is executed, the ray traversal engine discards the hit, leaves any hit attributes uncommitted, and continues traversing the scene toward other geometry. If the alpha exceeds the threshold, the shader finishes without ignoring the intersection, and the traversal engine treats the point as an opaque hit.

Performance Considerations

While any-hit shaders provide correct visuals, they introduce performance costs because they interrupt hardware-accelerated BVH traversal to execute shader code on compute units. To maintain efficiency:

  • Ray Flags: Use gl_RayFlagsCullOpaqueEXT or gl_RayFlagsCullNoOpaqueEXT when launching rays to skip unnecessary any-hit invocations.
  • Duplicate Invocations: Hardware can report multiple intersections for the same triangle if geometry overlaps. Use the VK_GEOMETRY_NO_DUPLICATE_ANY_HIT_INVOCATION_BIT_KHR flag during BLAS creation to avoid redundant any-hit execution on identical primitives.
  • Opacity Micromaps: For modern hardware, Vulkan supports the VK_EXT_opacity_micromap extension. This technique pre-bakes micro-triangle opacity states directly into the acceleration structure, allowing the hardware traversal engine to resolve transparent cutouts without invoking an any-hit shader for every ray.
