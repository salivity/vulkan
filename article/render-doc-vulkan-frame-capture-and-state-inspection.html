RenderDoc Vulkan Frame Capture and State Inspection

RenderDoc is a standalone, open-source frame debugger that provides deep diagnostic capabilities for applications using the Vulkan graphics and compute API. This article examines RenderDoc's core functionalities for capturing Vulkan frames, inspecting complex pipeline and descriptor states, analyzing resources, and stepping through shader execution to resolve rendering anomalies and synchronization bugs.

Frame Capture Capabilities

RenderDoc hooks directly into the Vulkan loader layer chain, allowing it to record all API calls, memory transfers, and resource state transitions executed within a given frame.

  • API Layer Integration: RenderDoc operates as a standard Vulkan validation/utility layer (VK_LAYER_RENDERDOC_Capture). This ensures transparent interception of core functions, extension calls, and driver interactions without requiring engine-level modifications.
  • Trigger Methods: Frame captures can be initiated via an in-application overlay hotkey, remotely through the RenderDoc UI connected to an active target process, or programmatically using the RenderDoc In-Application API (renderdoc_app.h).
  • Multi-Queue and Asynchronous Compute Capture: RenderDoc records submissions across multiple VkQueue instances, including graphics, compute, and transfer queues. It accurately preserves queue synchronizations implemented via VkSemaphore and VkFence objects.
  • Context and Command Buffer Tracking: Both primary and secondary command buffers (VkCommandBuffer) are tracked, detailing how and when draw calls, dispatches, and memory barriers are recorded and executed.

Vulkan Pipeline State Inspection

The Pipeline State Viewer in RenderDoc translates raw Vulkan structures into a structured, visual representation of the active graphics or compute pipeline.

  • Fixed-Function and Dynamic States: The viewer displays static configuration derived from VkGraphicsPipelineCreateInfo alongside dynamic states set via vkCmdSetViewport, vkCmdSetScissor, vkCmdSetBlendConstants, and other dynamic state commands.
  • Stage-by-Stage Breakdown: Users can inspect each discrete stage:
    • Vertex Input & Input Assembly: Displays bound VkBuffer bindings, vertex attribute offsets, formats, and primitive topologies.
    • Shader Stages: Confirms the active SPIR-V module for vertex, tessellation, geometry, fragment, and compute stages, including specialization constants.
    • Rasterization & Multisampling: Shows polygon modes, culling configurations, depth bias, and sample masks.
    • Output Merger & Color Blending: Details render pass attachments, blending equations, write masks, and depth-stencil operation parameters.
  • Descriptor Set and Resource Binding: RenderDoc lists all bound VkDescriptorSet objects and their layout bindings. It maps uniform buffers, storage buffers, sampled images, storage images, samplers, and push constants directly to the active shader reflection data, allowing immediate verification of descriptor correctness.

Resource and Buffer Diagnostics

  • Texture Viewer: Allows inspection of all VkImage resources bound to attachments or descriptors. Features include viewing specific mip levels, array layers, and cubemap faces; inspecting raw channel data; applying format overlays; and checking pixel history to see which draw calls modified a specific texel.
  • Mesh Output Viewer: Visualizes 3D vertex data at various stages of the pipeline: VS Input, VS Output, and GS/Tessellation Output. This isolates errors caused by matrix transformations, clipping, or incorrect vertex attribute indexing.
  • Buffer Inspection: Provides raw and structured views of VkBuffer contents, such as uniform buffer objects (UBOs) and shader storage buffer objects (SSBOs), supporting user-defined format decoding.

Shader Debugging and Execution Analysis

RenderDoc contains a built-in virtual machine that interprets SPIR-V bytecode, enabling line-by-line debugging of Vulkan shaders.

  • Source and Assembly Mapping: The debugger displays disassembled SPIR-V alongside high-level source code (GLSL or HLSL) if debug symbols (NonSemantic.Shader.DebugInfo or embedded source) are present.
  • Interactive Debugging: Developers can set breakpoints, step through shader execution for a specific pixel, vertex, or compute thread invocation, and inspect live register values, temporary variables, and memory loads.
  • Pixel History: For any selected pixel in a render target, RenderDoc generates a chronological log of all draw calls that touched the coordinate, indicating whether each fragment passed or failed depth, stencil, scissor, or blending tests.
