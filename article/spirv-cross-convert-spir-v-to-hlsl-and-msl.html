SPIRV-Cross: Convert SPIR-V to HLSL and MSL

SPIRV-Cross is an open-source library and tool developed by the Khronos Group designed to parse, reflect, and decompile SPIR-V binary shader modules into high-level shading languages. This article explains what SPIRV-Cross is, how it operates as an intermediate cross-compilation layer, and why it is essential for multi-API rendering engines that must translate SPIR-V shaders into High-Level Shader Language (HLSL) for DirectX and Metal Shading Language (MSL) for Apple platforms while maintaining Vulkan as a primary target.

What Is SPIRV-Cross?

SPIR-V is the standard intermediate representation (IR) used by modern graphics APIs, most notably Vulkan. While Vulkan natively accepts and executes SPIR-V binaries, other major graphics APIs—such as Microsoft DirectX and Apple Metal—do not.

SPIRV-Cross bridges this divide. It ingests SPIR-V bytecode, reconstructs the control flow and shader logic into an Abstract Syntax Tree (AST), and then emits equivalent code in other high-level languages, including HLSL, MSL, GLSL, and raw C++ code. Beyond decompilation, it provides reflection capabilities that extract resource bindings, struct layouts, and vertex attributes without requiring separate metadata files.

The Role of SPIRV-Cross in a Multi-API Pipeline

In modern game engines and cross-platform renderers, maintaining distinct shader source files for Vulkan, DirectX 11/12, and Metal introduces massive maintenance overhead. SPIRV-Cross enables a "write once, compile everywhere" shader pipeline.

In this workflow:

  1. Developers write shaders in a single source language, typically modern HLSL or GLSL.
  2. An upstream front-end compiler (such as glslang or Microsoft's DirectX Shader Compiler, dxc) compiles this code directly into SPIR-V.
  3. The resulting SPIR-V binary is fed directly into Vulkan pipelines.
  4. For non-Vulkan targets, SPIRV-Cross takes the SPIR-V binary and translates it downstream into HLSL or MSL.
  5. The generated HLSL or MSL source code is compiled by the target platform’s native compiler (e.g., fxc/dxc for DirectX or metallib for macOS/iOS).

Translating SPIR-V to HLSL

Translating SPIR-V back into HLSL enables support for DirectX 11 and DirectX 12. Vulkan and DirectX handle shader resources differently, requiring SPIRV-Cross to perform several structural conversions during the translation process:

  • Resource Remapping: Vulkan organizes resources into descriptor sets and bindings (set = X, binding = Y). HLSL relies on discrete register spaces and register indices (such as register(t0, space0) for SRVs, register(u0) for UAVs, and register(b0) for CBVs). SPIRV-Cross can automatically flatten Vulkan descriptor sets into distinct HLSL register spaces or linear register assignments.
  • Combined Image Samplers: Vulkan supports both combined image-samplers and separate textures and samplers. SPIRV-Cross splits or joins these constructs into syntax compatible with HLSL's Texture2D and SamplerState conventions.
  • Vertex In/Out Layouts: SPIRV-Cross translates SPIR-V input and output interfaces into HLSL structs decorated with required HLSL semantics (such as SV_Position or custom semantic names).

Translating SPIR-V to MSL

Apple's Metal API operates strictly with Metal Shading Language. SPIRV-Cross handles the unique architectural paradigms of MSL when converting SPIR-V:

  • Argument Buffers and Discrete Bindings: MSL binds resources to indices using platform-specific attributes such as [[buffer(n)]], [[texture(n)]], or [[sampler(n)]]. SPIRV-Cross maps SPIR-V descriptor sets directly to these indices or wraps them inside Metal argument buffer structures.
  • Coordinate Systems: Vulkan utilizes a clip-space depth range of [0, 1] with an inverted Y-axis compared to legacy APIs. MSL shares the [0, 1] depth range but handles certain viewport conventions differently. SPIRV-Cross injects the necessary transformation code to ensure render targets align identically across both APIs.
  • Simulated Push Constants: Vulkan provides high-speed "push constants" for passing small amounts of uniform data directly to the GPU. Metal lacks a 1:1 equivalent feature, so SPIRV-Cross translates push constants into a dedicated dynamic buffer bound to a reserve index.

Shader Reflection

In addition to translation, SPIRV-Cross acts as a shader reflection engine. It analyzes the SPIR-V module and reports the exact layout of:

  • Uniform buffers and push constant blocks (including variable offsets and padding).
  • Input attributes and output semantics.
  • Texture, sampler, and storage buffer bindings.

This reflection data allows developers to configure pipeline layout objects, descriptor tables, and root signatures across Vulkan, DirectX, and Metal dynamically at runtime using a single set of layout data derived directly from the compiled SPIR-V shader.
