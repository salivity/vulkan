Vulkan Host vs Device Out-of-Memory Errors

In Vulkan, game engines detect and differentiate between system out-of-memory (host) errors and GPU out-of-memory (device) errors by evaluating specific VkResult return codes and tracking memory heap properties. The API makes a fundamental architectural distinction between CPU-accessible system RAM and GPU-accessible memory pools, surfacing exhaustion events via VK_ERROR_OUT_OF_HOST_MEMORY and VK_ERROR_OUT_OF_DEVICE_MEMORY. By monitoring these distinct return codes during resource creation and tracking memory usage via Vulkan extensions, an engine can accurately pinpoint the source of memory pressure and execute targeted recovery strategies.

API Return Codes: Host vs. Device

Vulkan relies on explicit error reporting through the VkResult enumeration. Functions that allocate resources, compile pipelines, or initialize objects return one of two primary out-of-memory states:

  • VK_ERROR_OUT_OF_HOST_MEMORY: Indicates that a host-side (CPU/system RAM) allocation failed. This occurs when the Vulkan loader, graphics driver, or runtime runs out of system memory to allocate internal data structures, state trackers, or scratch buffers. It can also be returned if an application-provided host allocator (VkAllocationCallbacks) fails to allocate memory.
  • VK_ERROR_OUT_OF_DEVICE_MEMORY: Indicates that a device-side allocation has failed. This happens when there is insufficient space on the target memory heap of the physical device (GPU VRAM or unified memory reserved for the GPU) to satisfy an allocation request.

Engines trap these errors by checking the VkResult of calls to vkAllocateMemory, resource creation functions like vkCreateBuffer and vkCreateImage, and pipeline generation commands like vkCreateGraphicsPipelines.

The Scope of Memory Types and Heaps

To understand why a specific out-of-memory error occurs, an engine inspects the memory subsystem initialized through vkGetPhysicalDeviceMemoryProperties. Vulkan exposes:

  1. Memory Heaps (VkMemoryHeap): Represent physical memory banks. A heap flagged with VK_MEMORY_HEAP_DEVICE_LOCAL_BIT represents dedicated device memory (such as VRAM on discrete graphics cards), while heaps lacking this bit typically represent system RAM.
  2. Memory Types (VkMemoryType): Provide specific views into heaps, detailing cache properties and access flags (e.g., VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT, VK_MEMORY_PROPERTY_HOST_COHERENT_BIT, and VK_MEMORY_PROPERTY_DEVICE_LOCAL_BIT).

When an engine explicitly calls vkAllocateMemory targeting a specific heap, receiving VK_ERROR_OUT_OF_DEVICE_MEMORY indicates that the specific device memory heap exhausted its allocation quota or physical capacity.

Proactive Detection via Memory Budgeting

Rather than waiting for an unrecoverable failure during vkAllocateMemory, modern engines proactively query device memory availability using the VK_EXT_memory_budget extension.

By passing VkPhysicalDeviceMemoryBudgetPropertiesEXT to vkGetPhysicalDeviceMemoryProperties2, the engine receives real-time metrics:

  • heapBudget: The total amount of memory available for the process to allocate on each heap without causing OS-level thrashing.
  • heapUsage: The current amount of memory allocated on each heap by the application.

If heapUsage approaches heapBudget on a device-local heap, the engine detects impending device memory exhaustion before an explicit VK_ERROR_OUT_OF_DEVICE_MEMORY is returned.

Engine Recovery and Handling Strategies

Distinguishing between these two errors determines the engine's mitigation path:

  • Handling VK_ERROR_OUT_OF_DEVICE_MEMORY: Because the GPU subsystem is isolated from core OS operations, this error is typically recoverable. When encountered, an engine can evict non-essential assets, reduce texture mipmap resolutions, flush staging buffers, or defragment its sub-allocation blocks.
  • Handling VK_ERROR_OUT_OF_HOST_MEMORY: System RAM exhaustion is critical and often fatal to application stability. When detected, the engine typically attempts an emergency shutdown sequence, serializes crash telemetry, or flushes diagnostic logs, as the underlying operating system may terminate the process due to global system memory pressure.
