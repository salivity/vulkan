Tiled vs Immediate Mode Rendering in Vulkan

This article examines the architectural differences between Immediate Mode Rendering (IMR) and Tile-Based (Deferred) Rendering (TBR/TBDR) when executing commands via the Vulkan graphics API. It details how the physical hardware differences between desktop and mobile GPUs dictate memory bandwidth usage, explains the importance of Vulkan render passes and subpasses, and highlights best practices for optimizing pipeline efficiency across both paradigms.

Understanding the Hardware Architectures

Immediate Mode Rendering (IMR) is the traditional architecture used by modern desktop GPUs (such as AMD and NVIDIA). In an IMR pipeline, draw calls are processed sequentially in real-time. Geometry is transformed, immediately rasterized, shaded, and written directly to the target framebuffers residing in high-bandwidth dedicated video memory (VRAM). Depth, stencil, and color tests occur per-primitive or per-fragment as the geometry flows through the pipeline.

Tile-Based Rendering (TBR and TBDR) is the dominant architecture in mobile and low-power hardware (such as ARM Mali, Qualcomm Adreno, Apple Silicon, and Imagination PowerVR). TBR divides the screen into small grids called tiles (typically 16x16 or 32x32 pixels). The workload is executed in two primary phases:

  1. Binning/Tiling Pass: The GPU processes vertex data for the entire scene and determines which primitives intersect with which screen-space tiles, building a per-tile command list.
  2. Rasterization/Render Pass: The GPU processes each tile individually. Pixel data, depth buffers, and color buffers are held in ultra-fast, on-chip tile memory (SRAM). Once processing for a tile is finished, the resolved pixels are written out to system memory (DRAM).

Tile-Based Deferred Rendering (TBDR) extends this by performing hidden surface removal (HSR) across all overlapping fragments within the tile memory before running fragment shaders, eliminating overdraw.

Impact on Vulkan Render Passes

The Vulkan API was deliberately designed with explicit VkRenderPass and VkSubpass abstractions specifically to accommodate tiled architectures without penalizing immediate mode hardware.

  • Load and Store Operations: In IMR, loadOp and storeOp simply determine whether to clear or preserve VRAM contents. On TBR/TBDR hardware, setting VK_ATTACHMENT_LOAD_OP_LOAD forces the GPU to read the tile's contents from high-latency system memory into on-chip cache. Using VK_ATTACHMENT_LOAD_OP_CLEAR or VK_ATTACHMENT_LOAD_OP_DONT_CARE prevents this round-trip, keeping work localized to on-chip memory. Similarly, VK_ATTACHMENT_STORE_OP_DONT_CARE instructs tiled hardware to discard transient data (such as depth or stencil buffers) directly from on-chip memory without flushing it to DRAM.
  • Subpasses and Input Attachments: Vulkan subpasses allow sequential rendering operations within the same render pass. For TBR/TBDR, reading an attachment from a previous subpass via a subpass input allows the data to remain entirely in on-chip tile memory. On IMR GPUs, reading an attachment typically requires a traditional texture sample operation backed by the GPU's L1/L2 cache and VRAM.

Memory Allocation and Bandwidth

The architectural divergence drastically influences memory consumption and memory bandwidth:

  • Transient Attachments: In deferred shading or multi-pass setups, intermediate attachments (such as G-buffers) are required. On tiled architectures, these images can be flagged with VK_IMAGE_USAGE_TRANSIENT_ATTACHMENT_BIT and backed by VK_MEMORY_PROPERTY_LAZILY_ALLOCATED_BIT. This indicates that physical DRAM does not need to be allocated, as the data exists exclusively within the on-chip tile memory for the duration of the pass. On IMR GPUs, lazy allocations usually fall back to full VRAM allocations.
  • Memory Bandwidth: IMR hardware relies on wide memory buses and high-power VRAM (e.g., GDDR6, HBM) to sustain large volumes of reads and writes per fragment. TBR/TBDR hardware reduces external bandwidth requirements by up to 90%, making it far more power-efficient, though it introduces latency due to the prerequisite geometry binning phase.

Synchronization and Compute Pipeline Interactions

Because IMR operates as an immediate stream, transitioning between compute and graphics workloads typically incurs low pipeline latency, provided memory barriers are satisfied.

On tiled hardware, interleaving compute dispatches that write to resources needed by a graphics pass requires the binning phase or the tile-rasterization phase to wait. Mid-frame compute operations can force a premature flush of on-chip tile memory to DRAM, effectively negating the power and performance advantages of the tiled architecture. Consequently, tiled renderers benefit significantly from grouping all compute workloads before or after complete render passes.
